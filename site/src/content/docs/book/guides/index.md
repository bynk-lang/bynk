title: Guides
---
Each guide gets one task done: it assumes you know the basics and walks you to
a working result. They are grouped by what you are building:

- **Data and types** — validate and decode input, model values, pattern-match,
  and write generic code.
- **Structuring code** — split a program across contexts, share code and
  capabilities, and design a public surface.
- **Handling requests** — HTTP routes, forms and uploads, schedules, queues,
  WebSockets and inbound email.
- **Callers and access** — authenticate callers, verify webhooks and
  signatures, and authorise requests.
- **Storing data** — KV, R2, and existing Postgres and MySQL databases.
- **Calling out** — providers and adapters, other Workers, mTLS origins and
  email.
- **AI and search** — Workers AI, Vectorize, AI Search and containers.
- **Reliability** — run calls in parallel, bound their time, deduplicate
  deliveries, rate-limit and cache.
- **Agents and state** — stateful agents and state machines.
- **Localisation** — message bundles and ICU formatting.
- **Testing** — write, run and tier your tests.
- **Projects and deployment** — lay out, build, share, deploy and roll back.

New to Bynk? Work through [Learn Bynk](/book/tutorials/01-first-program/)
first. To understand why a part of the language works the way it does, read its
**Concepts** page, starting with
[how a Bynk program is shaped](/book/concepts/program-structure/how-a-program-is-shaped/).
For exact rules, see the [Reference](/reference/) and the
[Specification](/reference/spec/).

Running the toolchain — `bynk doctor`, the formatter, editor support, and
debugging — is covered under [Tooling](/reference/tooling/editor-and-tooling/) in the Reference.
