---
title: v0.504.3
description: The increments released in Bynk v0.504.3.
---
Released on 4 November 2026 as **v0.504.3**, with the increments from v0.492.2 to v0.504.3.
See [Upgrading](/book/reference/upgrading/) for what to change when you move to it.

| Version | Highlights |
|---|---|
| **v0.504.3** | A test module's capability call-record types qualify a `uses` commons type, so a context capability taking a commons type passes `tsc` under `bynk test` (#2886) |
| **v0.504.2** | Diagnostics on a context function's `given` no longer point at advice it cannot follow, and a refused `given` function's callers and body add no follow-on errors (#2881, #2882) |
| **v0.504.1** | Fixture pins a `given` fn called from a provider op, a WebSocket handler and a service-header-inherited handler (#2883) |
| **v0.504.0** | `D1` gains a typed `select[T]` and `firstAs[T]`: the compiler writes the `SELECT` column list from the row type, and failures are a `SqlReadError` |
| **v0.503.0** | `String where IsoDate` refines a string to a calendar date, exactly `YYYY-MM-DD`; an impossible date such as `2026-02-30` is refused in a literal, `.of`, `Json.decode` and at the HTTP boundary |
| **v0.502.1** | An integration test proves `bynk token` credentials against a Worker under `bynk dev` |
| **v0.502.0** | `ValidationError` exposes `field` and `message` (both `String`) to Bynk code; `value` stays unreachable (#2866) |
| **v0.501.1** | The Rust token signer is byte-compared with the test runtime's signer for non-ASCII subjects |
| **v0.501.0** | A context function may declare `given`; its callers must declare the same capabilities (#2868, builds on #2719 and #2010) |
| **v0.500.0** | `by Forged` and the new `by Expired` drive a `Bearer` route's seam at `system` with a wrong-secret or an expired token, each read as `Rejected(Unauthorized)` ([#2864](https://github.com/bynk-lang/bynk/issues/2864)) |
| **v0.499.1** | `bynk token <Actor>` mints a credential for the project's own `Bearer` actor, to call a guarded route by hand |
| **v0.499.0** | An HTTP service or route can write response `Option`s as plain JSON (`v` / `null`) with `json { options: plain }` and `@json` |
| **v0.498.2** | `JsonError`'s `kind`, `path` and `message` are documented, offered by completion and hover, and named in the `interpolation_non_scalar` note (#2863) |
| **v0.498.1** | `?` on a `Result` inside a test `case` fails the case, naming the `Err` and the `?`'s location, instead of emitting a `return` that failed `tsc` (#2857) |
| **v0.498.0** | An `on http` handler reads the query string through a typed `query` parameter, decoded and validated at the boundary, or a raw `RequestQuery` view (#2854) |
| **v0.497.4** | A suite's `fixture` can be named in its `stub` clauses (#2850) |
| **v0.497.3** | A test case no longer passes `identity` to a binder-less Bearer/Oidc handler, so one that takes `given` capabilities passes tsc (#2856) |
| **v0.497.2** | A fixture refusal code without its own message now fails loudly (#2851) |
| **v0.497.1** | A test case that checks `expect r is Ok(_)` and then matches `r` exhaustively no longer fails `tsc` with TS2678 |
| **v0.497.0** | A `suite` can declare `fixture` files whose text is a `String` constant for its cases, read from `fixtures/` and never deployed |
| **v0.496.0** | `expect v matches snapshot "name"` compares a value's canonical JSON with a stored snapshot, and `bynk test --update-snapshots` records, refreshes and prunes the `snapshots/` files |
| **v0.495.0** | A `suite` can declare pure helper `fn`s that its `case` and `property` bodies call, private to the suite and emitted into test output only |
| **v0.494.0** | A nested `match` staircase gets a `let … else` hint with a fix, `Option`/`Result` gain `isNone`, `orElse`, `filter`, `isErr` and `ok`, and a second `match` in a block names the rule |
| **v0.493.0** | A reserved word names a field or a member where the name is a label (`a.type`, `{ type: String }`, `Sorted.from`), and keyword field shorthand is a targeted error (#2837, #2778) |
| **v0.492.2** | A `system` suite call with a `Wire(…)` body to a route whose handler declares `headers: RequestHeaders` (a `@raw` route too) passes the headers to the request, as a typed call does; it converted them to a string, and the generated test failed to type-check |
