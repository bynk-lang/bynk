Released on 7 November 2026 as **v0.512.5**, with the increments from v0.510.35 to v0.512.5.
See [Upgrading](/book/reference/upgrading/) for what to change when you move to it.

| Version | Highlights |
|---|---|
| **v0.512.5** | Crate hygiene E4b - the `bynkc-lsp` copy of the language server is no longer shipped (archives, the loose `bynkc-lsp-<target>` assets), and `bynk doctor` no longer accepts it in place of `bynk-lsp`; editor configs that name `bynkc-lsp` must use `bynk-lsp` |
| **v0.512.4** | Crate hygiene E3-4 - `bynkc` is removed - the executable, the `bynkc` crate, the `bynkc-<target>` release asset, the installer and dev-container entries, the `argv[0]` alias and its stderr notice - and so are `BYNK_BYNKC`, `BYNK_ALLOW_SKEW` and the hidden `--allow-skew` flag; use `bynk` (same commands, flags and output). The `/docs/cli/` reference page is folded into the `bynk` CLI page. The one deviation from byte-identical diagnostics: three parse messages and the asset/embed check messages now say `bynk compile` where they said `bynkc compile`, because that command no longer exists |
| **v0.512.3** | A failing property or history test now says `reproduce: bynk test <file> --seed <seed>` (was `bynkc test`), and the generated test runner's fallback program name is `bynk` (crate-hygiene E5 follow-up) |
| **v0.512.2** | Generated files now start `// Generated by bynk — do not edit by hand.` (TOML `# Generated by bynk — do not edit by hand.`; was `bynkc`), so every emitted file's first line changes once. This is the crate-hygiene track's one exception to byte-identical output (track §14; crate-hygiene E5) |
| **v0.512.1** | `Json.encode` / `Json.decode` / `Json.encodePlain` work in `system` and `integration` suites (#3032) |
| **v0.512.0** | `Json.encodePlain(v)` writes `Option` as `v` / `null`, the shape a `json { options: plain }` route writes (#2991) |
| **v0.511.1** | `bynk test`: a suite helper's `Json.encode`/`Json.decode` of a commons type, and a stub method's signature naming a capability's `uses`d-commons type, no longer fail `tsc` with TS2304 |
| **v0.511.0** | `headers.get("X")?` in an `HttpResult` handler warns (`bynk.http.header_question_not_found`) with a `let … else` fix answering `400`; hover on `?` says `None → 404 NotFound`; `==`/`!=` against a bare `HttpResult`/`QueueResult` variant type-checks |
| **v0.510.39** | A test `case` or `property` accepts D1 `select[T]` / `firstAs[T]` on a derived capability, as a handler does |
| **v0.510.38** | fmt keeps digit separators in InRange, MinLength, MaxLength and Length arguments |
| **v0.510.37** | `bynk test --smoke` against a named target now lists every case a write route would have run as skipped, not only its `answers` case, so the skip count agrees with the cases `--smoke-unsafe` adds ([#3008](https://github.com/bynk-lang/bynk/issues/3008)) |
| **v0.510.36** | The raw `Forged`/`Expired` Bearer test drivers append a typed `query` as its raw string, so a suite for a Bearer `GET` route with a typed query no longer fails `tsc` |
| **v0.510.35** | Crate hygiene D2-1 - the diagnostic renderers become `bynk-driver`'s `render` module and the `bynk-render` crate leaves the workspace and the release lists (its final release, which names `bynk-driver`, shipped earlier); no behaviour change |
