---
title: v0.434.0
description: The increments released in Bynk v0.434.0.
---
Released on 27 October 2026 as **v0.434.0**, with the increments from v0.405.5 to v0.434.0.
See [Upgrading](/book/reference/upgrading/) for what to change when you move to it.

| Version | Highlights |
|---|---|
| **v0.434.0** | Hovering a `given` entry shows why the declaration needs the capability, the shortest chain of agent-handler calls to its use, and a **Show capability path** action lists every chain (#2469) |
| **v0.433.0** | The VS Code Testing view tags a doc-comment example's case `doc-example`, so its tag filter groups the doc examples |
| **v0.432.0** | Doc-link hover resolves like the link itself, so own fields, parameters and unit-qualified names preview |
| **v0.431.0** | Doc-link completion after `[` offers the attached declaration's own parts (fields, ops, handlers, methods, parameters) first, agrees with `resolve_doc_link_in`, and offers `unit.Name` for a bare name another declaration shadows |
| **v0.430.0** | Find references and document highlight include the doc-comment mentions (`[Name]`) that resolve to a symbol |
| **v0.429.0** | The editor lists every boundary change since `bynk.schema.lock` (events and agent state, compatible or breaking, under the checker's own rules) and every service contract that differs from `bynk.deploy.lock`'s live record, in **Bynk: Show Contract Diff** (`bynk/contractDiff`); the existing non-additive diagnostics are unchanged (#2467) |
| **v0.428.0** | Rename rewrites the `[Name]` doc links that resolved to the renamed symbol, and refuses a rename that would re-bind one |
| **v0.427.0** | Refined-type explorer — hovering a refined type shows its predicates, and a "Try values…" panel lists seeded examples and checks a typed candidate, naming the failing clause |
| **v0.426.0** | `bynk mcp` serves the toolchain's read-only answers (diagnostics, symbols, documentation, architecture, wire contracts, explanations, check) to any agent over the Model Context Protocol on stdio (#2466) |
| **v0.425.0** | `vscode-bynk` manages dependencies and the registry: a Dependencies node in the Project sidebar, Add Dependency…, upgrade lenses in `bynk.toml`, Fetch Dependencies and a plan-first Publish…; `bynk` gains `search` and `deps`, and `--format json` on `add`, `fetch` and `publish` |
| **v0.424.1** | The unresolved doc-link hint resolves links as document links do, so a record's own field or a fn's parameter named in its doc is no longer flagged, and did-you-mean suggestions include those own parts |
| **v0.424.0** | `vscode-bynk` adds **Copy Playground Link** and **Open in Playground** for a selection or a single-file program, on desktop and on the web (#2480) |
| **v0.423.0** | `vscode-bynk` decorates the Explorer: a context badge on each file, and a red tint on files whose tests failed |
| **v0.422.0** | `bynk book` prints and searches the Book embedded in the toolchain; the editor's `bynk_search_book` language-model tool uses it (#2463) |
| **v0.421.1** | First-party names such as `[Clock.now]` in a doc comment link to the Book from the documentation panel |
| **v0.421.0** | A fenced `bynk test` example in a doc comment runs as a test case, reported at its own line in the source file |
| **v0.420.0** | Doc links resolve context-first — a declaration's own fields, operations, handlers, methods and parameters, then the unit scope, then unit-qualified names like `[window.decide]`; suite doc comments link too |
| **v0.419.0** | An unresolved doc link `[Name]` shows an opt-in editor hint (`bynk.doc.unresolved_link`) with a did-you-mean quick fix, set by `bynk.docLinks.reportUnresolved` |
| **v0.418.0** | Completion inside a doc comment offers the names a `[link]` would resolve, in resolution order |
| **v0.417.0** | The language server answers `textDocument/inlineValue`, so a paused Bynk debug session shows each in-scope `let` and parameter beside its line, in Bynk's rendering |
| **v0.416.0** | `vscode-bynk` reviews and approves pending npm requirements: a failing check, dev or deploy plan that reports `bynk.requires.unapproved` shows a Problems entry, a badge and a **Review…** notification, and a review panel approves per package; `bynk approve --list --format json` is the listing it reads |
| **v0.415.0** | **Bynk: Show Compiled Output** in VS Code opens a file's generated TypeScript beside it, built from the unsaved buffers by the new `bynk compile --sources-stdin`, with the cursor highlighting matching lines in each editor through the emitter's source map |
| **v0.414.0** | `bynk test` type-checks the fenced `bynk` examples in doc comments, reporting a mistake at the example's line; `bynk ignore` opts out |
| **v0.413.0** | VS Code: a State Migrations node in the Bynk sidebar shows `bynk migrate status` per agent class, and **Bynk: Sweep State Migrations…** runs `bynk migrate sweep` plan-first (#2468) |
| **v0.412.0** | `vscode-bynk` adds an `@bynk` chat participant (`/explain`, `/learn`, `/architecture`, `/fix`) that answers from the toolchain's language-model tools and cites its sources |
| **v0.411.0** | `bynk dev` rewrites stack frames in the workers' output to `.bynk` locations, and `vscode-bynk` shows the workers' logs in a filterable Bynk Logs view |
| **v0.410.0** | `bynk-lsp` serves LSP type hierarchy: a refined, opaque or alias type's supertype is its primitive base, and a primitive's subtypes are every such type across the project; an opaque type's representation is shown only inside its declaring unit |
| **v0.409.0** | Hovering a doc-comment `[Name]` link previews its target, or reports it unresolved |
| **v0.408.0** | Doc links to first-party names such as `[Clock.now]` link to the Book's first-party capabilities reference |
| **v0.407.1** | Evaluated LSP pull diagnostics (`textDocument/diagnostic`); `bynk-lsp` keeps push diagnostics |
| **v0.407.0** | The documentation panel makes intra-doc links (`[Name]`) clickable |
| **v0.406.0** | The VS Code extension registers language-model tools, so a chat agent can ask the installed toolchain about Bynk (diagnostics, explanations, symbols, documentation, architecture, wire contracts, `bynk check`) instead of relying on what it remembers (#2463) |
| **v0.405.7** | The extension icon and the site favicon are the bento blocks the playground uses, in place of the bird and the two indigo blocks |
| **v0.405.6** | Following a `[Name]` doc link now jumps to the declaration rather than only opening its file, so a same-file link no longer does nothing; hover's doc links do the same |
| **v0.405.5** | The `llms.txt` primer for AI agents teaches current Bynk (`suite`/`case`/`expect`, `type T = opaque U`, `//` comments, the current keywords and CLI), and CI now compiles its examples, checks its keyword list against the compiler and keeps its version line current |
