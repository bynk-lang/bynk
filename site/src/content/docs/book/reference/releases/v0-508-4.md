---
title: v0.508.4
description: The increments released in Bynk v0.508.4.
---
Released on 4 November 2026 as **v0.508.4**, with the increments from v0.505.0 to v0.508.4.
See [Upgrading](/book/reference/upgrading/) for what to change when you move to it.

| Version | Highlights |
|---|---|
| **v0.508.4** | A caller of a service whose context renames a consumed type (`consumes lib { Code as LibCode }`) can name and match on the returned value as the declared type |
| **v0.508.3** | A `let` bound to a literal `RequestHeaders.of([...])` and sent as extra request headers is checked for `Authorization` (`bynk.test.extra_headers_authorization`), and the below-`system` extra-headers error points at the offending call |
| **v0.508.2** | Deferred list elements in a generic call argument now merge through function, effect, stream, query, connection and http-outcome types, so inference no longer depends on element order |
| **v0.508.1** | A `Wire(...)` argument rejected on an event, queue or other test address is still type-checked, so an unknown name inside it is reported alongside `bynk.test.wire_http_only` |
| **v0.508.0** | A `system` case can send request headers to an http route that declares no `headers:` parameter, by a trailing `RequestHeaders` argument on the address |
| **v0.507.2** | `Some(...)`, `Ok(...)`, `Err(...)` and context-typed list elements (`[None, Some(1)]`) in a generic call argument now infer the type argument instead of being checked against the unsolved type variable |
| **v0.507.1** | fmt keeps digit separators in integer literal patterns and events-subscription literal patterns |
| **v0.507.0** | `bynk token` now mints for refinement actors (signing the claims the predicate needs, as the `system` harness does) and takes `--claim name[=value]` to add claims by hand |
| **v0.506.5** | `Wire(...)` in a unit-tier case is now `bynk.test.wire_needs_system`, and `Wire(...)` passed to a queue, cron, `on call` or event address is the new `bynk.test.wire_http_only` instead of failing at run time or in `tsc` |
| **v0.506.4** | A record field default naming a variant of a `uses`-sourced commons sum now reports `bynk.context.rebrand_construction` instead of "an invalid expression", and the `bad_field_default` note no longer lists such variants as admitted |
| **v0.506.3** | A suite mixing `as system` with lower-tier cases reports only `bynk.tier.mixed_system_suite`, not a false `bynk.observe.not_a_seam`; suite helpers are callable in `stub … returns` values, and an unresolved name there is reported as unresolved, not `bynk.stub.rhs_type` |
| **v0.506.2** | A reserved word naming an agent `on call` operation, a name on a service's `on call`, and a `stub`/`env` clause after a case statement now get targeted parse diagnostics |
| **v0.506.1** | A typed `query` field of a refined type or enum declared in a `uses` commons now reads as its real wire kind on Workers (so `?n=2` is no longer a 400), and a context whose only capability use is a `fn … given Fetch` now imports the `bynk` namespace its `deps` name |
| **v0.506.0** | A lambda parameter may be `_`, which binds nothing — `r.mapErr((_) => 0)`, `(a, _) => a` |
| **v0.505.4** | Matches patterns with an unambiguous separator between repetitions, such as the slug `[a-z]+(-[a-z]+)*`, are no longer refused as catastrophic; IsoDate bounds the input at 10 characters |
| **v0.505.3** | A list literal argument to a generic call now infers the type argument (`size([1, 2])`) instead of being checked against the unsolved type variable |
| **v0.505.2** | fmt keeps `else if` chains flat, keeps digit separators in range-pattern bounds, and keeps the blank line above a comment on a header line |
| **v0.505.1** | Aliased types in a service signature resolve for a callee's own callers (the contract now hashes the renamed type's shape); `consumes_item` node in tree-sitter; aliased services run under `workerd` |
| **v0.505.0** | `consumes U { T as Alias }` renames a type `U` exports for the consuming context, so `consumes bynk.crypto { Crypto, Digest as CryptoDigest }` no longer clashes with your own `Digest`; the `name_conflict` note names the way out (#2887) |
