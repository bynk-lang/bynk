Released on 6 November 2026 as **v0.510.34**, with the increments from v0.510.26 to v0.510.34.
See [Upgrading](/book/reference/upgrading/) for what to change when you move to it.

| Version | Highlights |
|---|---|
| **v0.510.34** | Crate hygiene E3-3 - `bynkc` becomes a name the `bynk` executable answers to for one release (release archives, the loose `bynkc-<target>` asset and the `bynkc` crate's shim all run `bynk`), with a one-line retirement notice on stderr; the `bynkc` crate's final release points to `bynk` |
| **v0.510.33** | Crate hygiene E3-2 - the test corpus drives `bynk` (through `bynk-under-test`) instead of a separate `bynkc` binary, ahead of `bynkc`'s retirement (no behaviour change) |
| **v0.510.32** | The test-module emitter matches handler kinds through the system model's `IrHandlerKind` (via `lower_handler_kind_ir`) rather than the syntax tree's variants, and its protocol matches cite M-1's domain clause; emitted test modules are unchanged (crate-hygiene B4) |
| **v0.510.31** | The `bynk-render` crate announces its final crates.io release; its renderers become the `bynk-driver` crate's `render` module (crate-hygiene D2) |
| **v0.510.30** | Crate hygiene E3-1 - the test corpus and the fuzz target stop using the `bynkc` library and name `bynk-driver`, `bynk-emit` and `bynk-render` directly (no behaviour change) |
| **v0.510.29** | The system model's placement is settled. It stays above `bynk-check`, the wire contract stays in `bynk-check` as the model's boundary half, and the editor's architecture map stays an editor view. Whether the model becomes a public interface is deferred past 1.0 (crate-hygiene B4) |
| **v0.510.28** | Crate hygiene E1-E2 PR 4 - the `bynkc` lookup (`BYNK_BYNKC`, `PATH`, sibling) and ADR 0434's version-skew gate are retired; `BYNK_BYNKC` is ignored with a one-line warning, `--allow-skew` and `BYNK_ALLOW_SKEW` are accepted and ignored, and the `bynk doctor` compiler row is always in-process |
| **v0.510.27** | `bynk openapi` and `bynk test --smoke` read handler kinds and HTTP methods from the system model instead of matching the syntax tree; their output is unchanged (crate-hygiene B2) |
| **v0.510.26** | Crate hygiene E1 PR 2 - `bynk compile` runs in-process through `bynk-driver` (no `bynkc` binary needed), gains `--target`, `--platform` and `--emit`, and ignores `BYNK_BYNKC` and `--allow-skew` (the other commands follow in a later release) |
