---
The increments merged since **v0.639.1**, the latest release. They ship in
the next one. Each increment's row is added here when it merges.

| Version | Highlights |
|---|---|
| **v0.640.13** | Internal hardening in the code generator; a new enum variant now fails the build at each emitter match outside lowering that has to handle it |
| **v0.640.12** | Docs: the Book is reorganised by kind, then by concern. Its sidebar reads Start, Learn Bynk, Concepts (the explanation pages, by concern) and Guides (the how-to pages, by what you are building), then Reference, Specification and Troubleshooting. No page moves. *How these docs are organised* is retired in favour of a shorter front page (web presence track, slice 2, #3865). |
| **v0.640.11** | Generated modules and Worker entry files no longer import names they do not use; each import list now follows from the module's code |
| **v0.640.10** | Generated modules no longer import runtime names they do not use; each module's runtime import now follows from its code |
| **v0.640.9** | Groundwork for deriving each generated module's imports from its code instead of predicting them; the generated code and its source maps are byte for byte unchanged |
| **v0.640.8** | The state-migration step functions the compiler writes into an agent's module are built as trees, not text, so each statement of a step prints on its own line and its `catch` is braced; their tokens are unchanged; a foreign client whose decoders return a consumed type now imports `Result` and `__BoundaryError`, which it used without importing |
| **v0.640.7** | The generated TypeScript client's conversions, route constants, contract table and `createClient` are built as trees, not text, so the client's layout is regular (one blank line between declarations, each route function on one line after its parameters); its tokens and source maps are unchanged apart from the one-line doc comment on `Client` becoming a block, and the contract table of a foreign-caller client (`bynk-client.ts`) gaining its trailing comma |
| **v0.640.6** | The serialisation codecs, the Worker group entry, the email handler and the extra imports are built as trees, not text, and the codec guards that sat one level shallow now sit at their true depth; only indentation in the generated code changes, and its source maps are unchanged |
| **v0.640.5** | The code generator's lowering returns trees only: the text bridge, its constructors, its counters and the string type renderer are deleted, and the generated code and its source maps are byte for byte unchanged |
| **v0.640.4** | With `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` set, the `bynk deploy` plan (`--dry-run` included) checks what it would create against the account, so an R2 bucket, D1 database, Vectorize index or queue already there is planned as `reuse` instead of `create`, and a KV namespace whose title is already taken is a warning; without them the plan stays offline and says so |
| **v0.640.3** | The closure a service or agent handler body runs in, the contract-guard closure and the subscriber and schema prologue guards are typed nodes instead of text lines; the generated code is unchanged apart from indentation, the body of an events-emitting service handler now sitting one step deeper inside its closure |
| **v0.640.2** | The `bynk` driver's own messages on stderr carry a label after who is speaking, so they take the colour palette: `error:` (red) when the command then fails, as in `bynk: error: not inside a Bynk project`, `warning:` (amber) when it carries on in a degraded state, and `note:` (blue) when you need to act; a coded `error[…]:` label and a workspace member's messages (`bynk: packages/ok: error: …`) are coloured too. The wording of these messages changed, so a script or CI filter that matches one may need the label added; exit codes and machine-readable output are unchanged |
| **v0.640.1** | Lowering builds the generic-function-as-value closure, the `Form.decode` and `Form.encode` call and the hoisted async-tail `if` as typed nodes, and nothing in lowering builds text any more; the generated code is unchanged apart from layout, and a lowering step that lacks a checker fact for a receiver namespace or a store operation is reported as an internal fault instead of emitting a placeholder, and no such fault is added to a project that already has errors |
| **v0.640.0** | `*`, `{` and `}` are reserved in an HTTP route, in a literal segment or inside a `:name`, and refused with `bynk.http.reserved_route_syntax`, so a rest-segment form can be added later without changing what an existing route means |
| **v0.639.62** | `bynk dev` serves each Worker from a copy of its config that is replaced only once the development bindings are in it, so a rebuild never briefly binds the deploy's Vectorize index, and a Worker with stand-ins gets its development index too; `bynk migrate status` and `bynk migrate sweep` find the agent classes of a context in a `[deploy.workers]` group in the group's Worker |
| **v0.639.61** | `bynk explain` explains 20 more error codes, among them the `[deploy.workers]` group rules, `[package] exports`, `[unstable] allow` and D1 migration file names |
| **v0.639.60** | A test suite of 500 or more cases now type-checks, instead of failing `bynk test` with `bynk.codegen.tsc_failed` (TS2563) because the generated runner was too large for `tsc` to analyse; and a `trace(Cap.op)` list or call record can be encoded, by `Json.encode` or as a `bynk eval` value, instead of failing with `bynk.codegen.tsc_failed` |
| **v0.639.59** | The `rust` examples in the crate READMEs are self-contained, and CI compiles and runs them as doctests so they cannot fall out of date |
| **v0.639.58** | Completion and hover show `joinOn` and `leftJoin` with their `left` and `right` key functions, as the checker checks them, instead of an `on` predicate |
| **v0.639.57** | A `system` case's `is` test on a handler result whose type comes from a commons is checked again, so a wrong variant such as `r is Created(_)` on an `HttpOutcome[Note]` is `bynk.types.is_unknown_variant` instead of a failure in `tsc`; and a service with two `on call` handlers, where the second silently replaced the first, is now `bynk.service.duplicate_call_handler` |
| **v0.639.56** | A record literal that leaves out a field now fills in its default correctly when the field is a refined type (the value is a value of that type) or a `Decimal` (the value is a decimal number, not its text), so such programs type-check and `Decimal` arithmetic on the field no longer crashes (#3759, #3801) |
| **v0.639.55** | Five fixes. `Log.since`, `before` and `between` no longer throw once a window holds more than 512 entries (#3747). `bynk test` now removes build output it did not write from its output directory (`out/` by default), as `bynk build` does, so it no longer fails with `bynk.codegen.tsc_failed` on files a Workers build or `bynk test --against` left in `out/workers/` (#3748). `bynk deploy --dry-run` no longer rewrites `bynk.schema.lock` or writes `.bynk/deploy` (#3796). A build that records stored positions in an older `bynk.schema.lock` now says so and asks for the lock to be committed (#3749). Bundle builds emit the events-dispatch cases in the same order every time, so the output is reproducible (#3815) |
| **v0.639.54** | Lowering builds labelled loops and blocks, while loops, multi-declarator lets, sequence expressions, generators with yield, for-await, array-pattern parameters, the claim-scope declaration, the witness claims and the regex and stream helpers as typed nodes instead of text; the generated code is unchanged apart from layout (and one multi-declarator const split in two), and the source maps of the changed files gain finer statement anchors |
| **v0.639.53** | Lowering builds the typeof and indexed-access casts, tail-call temporaries, or-pattern dispatch and several constructor and snapshot helpers as typed nodes instead of text; the generated code is unchanged apart from layout, and ten source maps gain finer statement anchors |
| **v0.639.52** | The generated code now brackets the operand of `Duration.millis`, `toMillis`, `Instant.fromEpochMillis`, `toEpochMillis` and `Int.toFloat`, so `Duration.millis(s.length() + 1).toMillis() * 2`, unary minus and subtraction over them compute the right value instead of binding the operand's `+` or `-` to the surrounding operator |
| **v0.639.51** | A checker fact the code generator needs and does not find is reported as an internal-error diagnostic, `bynk.internal.missing_checker_fact`, at the source span instead of being written as `any`, `undefined` or a panic; no program the checker accepts is affected and the generated TypeScript and source maps are unchanged |
| **v0.639.50** | The checker records each call's resolution as closed typed values (a static operation, a store operation, a test address, a first-party capability, a call-site principal) and the emitter reads them instead of comparing names; generated TypeScript and source maps are unchanged. One behaviour tightens: a same-named capability that is not bynk's own `Events` no longer counts as an `Events.emit`. Two first-party decisions now key on the capability's identity rather than a name: locale negotiation goes to any external provider of bynk's own `Locale` (today only `LocaleProvider`), and an `Idempotency` call inside the `bynk` unit itself counts as first-party (no such call exists today); neither changes any output |
| **v0.639.49** | `bynk` colours by one palette (blue information, green success, red error or failure, amber warning, bold headings), now also for `bynk test --mutate` (each mutant by its outcome, and the report's counts, labels and score), the `bynk revert` plan (`ok`, `refused` and the verdict), and the `error:`, `warning:` and `note:` labels of messages on stderr |
| **v0.639.48** | The agent state-persistence functions (`__hydrate<A>State`, `__rehydrate<A>State`, `__encode<A>State`) are built as statement nodes rather than text, so their checks are laid out one statement per line (a ruled layout change in 149 generated files) and an `if` over a `for` gains braces (ruled, 69 files, 150 sites, semantically identical TypeScript); source maps are unchanged apart from the extra lines; what the emitted code does is otherwise unchanged |
| **v0.639.47** | Eight more pieces of generated TypeScript are built as declaration and statement nodes rather than text, so a lazily read agent's `loadState` branch, a WebSocket agent's frame-decode `try`/`catch` and its close handler's `void` statements are laid out one statement per line (a ruled layout change in 46 generated files), and the lazy-read branch's last call now ends in a `;` (ruled, 38 files, semantically identical TypeScript); source maps are unchanged apart from the extra lines; what the emitted code does is otherwise unchanged |
| **v0.639.46** | A global `--color auto|always|never` (alias `--colour`) says when `bynk` colours its output. `bynk test` shows a passing case's ✓ green, a failing case red and the tally in colour; the `--coverage` table is red, amber or green by percentage; `bynk doctor`'s marks, the build progress lines and `--help` are coloured too. `auto`, the default, keeps the existing `NO_COLOR`/`FORCE_COLOR`/`CLICOLOR_FORCE` rules, and machine-readable formats are never coloured |
| **v0.639.45** | The agent class and its history-property driver are built as TypeScript declaration nodes rather than text, so a generated agent class no longer ends with a blank line before its closing brace (a ruled layout change in 149 generated files); the four generated files that carry a history driver also lay it out one statement per line and separate the members of its object types with `;` instead of `,` (ruled, semantically identical TypeScript); source maps are unchanged apart from the driver's extra lines; what the emitted code does is otherwise unchanged |
| **v0.639.44** | Provider classes and service objects are built as TypeScript declaration nodes rather than text, so a generated provider class prints a blank line between its operations and its constructor over three lines (a ruled layout change in 35 generated files, token-identical); each statement in a type's method body now maps to its own source line in the source map instead of the commons or context header (586 lines in 48 generated files, TypeScript unchanged); what the emitted code does is otherwise unchanged; a consumed multi-file context's bundle namespace import now targets its smallest file path deterministically instead of the first in hash order (#3807) |
| **v0.639.43** | A record literal that leaves a defaulted field out is built as a TypeScript node rather than text, so two generated files print an enclosing closure on several lines instead of one (a ruled, whitespace-only change); no change to what the emitted code does |
| **v0.639.42** | The built-in `Option`, `Result`, `Set` and `Map` kernel methods in generated code are built as TypeScript nodes rather than text, so redundant brackets round receivers are gone and several generated files, among them the standard-library `string.ts` and `locale.ts`, print an enclosing closure with different layout; no change to what the emitted code does |
| **v0.639.41** | The built-in `Int`, `Float`, `Decimal`, `Duration`, `Instant`, `Bytes` and `String` kernel methods in generated code are built as TypeScript nodes rather than text, so redundant brackets round receivers are gone and several generated files, among them the standard-library `string.ts`, print an enclosing closure with different layout; no change to what the emitted code does |
| **v0.639.40** | The built-in kernel methods on connections, request views, cookies, `within`, `race`, `detach` and `Effect[Result]` combinators in generated code are built as TypeScript nodes rather than text, so redundant brackets round receivers are gone and twelve generated files print an enclosing closure with different layout; no change to what the emitted code does |
| **v0.639.39** | Agent construction and agent calls in generated code are built as TypeScript nodes rather than text, so four generated test and demo files print an enclosing closure with different layout; no change to what the emitted code does |
| **v0.639.38** | Test-case and system-tier service calls in generated test harnesses are built as TypeScript nodes rather than text, so a few expressions print with different layout and six redundant brackets (`(x).url`) are dropped; no change to what the emitted code does |
| **v0.639.37** | Cross-context service calls, on the bundle and the Workers target, are built as TypeScript nodes rather than text, so a call with no arguments sends `{}` rather than `{  }`; no change to what the emitted code does |
| **v0.639.36** | Capability calls, `Events.emit`, the session and typed cookies and the derived-`D1` `select` are built as TypeScript nodes rather than text, so an event emission and a `D1` read are laid out as indented blocks; no change to what the emitted code does |
| **v0.639.35** | An `expect` predicate and an observation's `with` predicate may not hold an effectful call (`bynk.expect.impure_predicate`, `bynk.observe.impure_with`), and an `expect` comparison evaluates each operand once, so a capability call can no longer be recorded twice by a claim about it |
| **v0.639.34** | The persisted-store operations (held `Map`, `Map`, `Set`, `Cache`, `Log`, `Cell`) are built as TypeScript nodes rather than text, so each operation's statement IIFE is laid out as an indented block; no change to what the emitted code does |
| **v0.639.33** | The `Query` operations over a store (`filter`, `sortBy`, `distinctBy`, `groupBy`, the joins, the terminals) are built as TypeScript nodes rather than text, so a statement-bodied step is laid out as an indented block; no change to what the emitted code does |
