title: v0.510.2
description: The increments released in Bynk v0.510.2.
---
Released on 5 November 2026 as **v0.510.2**, with the increments from v0.508.5 to v0.510.2.
See [Upgrading](/book/reference/upgrading/) for what to change when you move to it.

| Version | Highlights |
|---|---|
| **v0.510.2** | A Workers WebSocket `on open` keyed by a `const` of a used commons split across files now builds: `compose.ts` imports it from the file that declares it, where it imported from a commons module such a commons does not emit (#2969) |
| **v0.510.1** | A Workers WebSocket `on open` can key its connection transfer by a public `const` of a commons the context `uses`, as it can by the context's own `const`; it was rejected with `bynk.ws.open_transfer_key` (#2967) |
| **v0.510.0** | A multi-line string may carry a language tag, `"""sql` or `r"""regex`, so editors highlight its text as that language; the tag is not part of the value |
| **v0.509.0** | A suite's or case's `env` entry may name a `fixture` of the same suite instead of a `String` literal (`APP_PRIVATE_KEY = appKey`), so a long test-only value such as a private key lives in one file under `fixtures/`; the text is verbatim, trailing newline included, and a use in `env` counts for `bynk.fixture.unused` (#2956) |
| **v0.508.14** | A match on a typed D1 read's `Err(Sql(e))` / `Err(Decode(e))` now narrows `e`, instead of failing `tsc` with TS2345 |
| **v0.508.13** | A Workers WebSocket `on open` keyed by a context `const` now builds, a literal key with a route parameter now reaches the instance the body addresses instead of one keyed by the parameter, and any other key is a compile error on Workers (`bynk.ws.open_transfer_key`) |
| **v0.508.12** | The language server binary is now `bynk-lsp` (was `bynkc-lsp`); this release also ships a `bynkc-lsp` copy, so change `cmd = "bynkc-lsp"` to `cmd = "bynk-lsp"` in editor configs |
| **v0.508.11** | Internal - the predicate-to-TypeScript helpers and the TypeScript string escaper move into `bynk-ts`; `bynk-lsp` no longer depends on `bynk-emit` |
| **v0.508.10** | A suite helper whose signature names a type from a `uses` commons no longer fails `tsc` (TS2304) when the suite has a `stub` |
| **v0.508.9** | `bynk-grammar` keeps rule order itself, so `serde_json`'s `preserve_order` is off workspace-wide and the editor-contract key sort is gone |
| **v0.508.8** | The system model's scope and placement are recorded (crate-hygiene B1), and every handler kind's and service protocol's editor rendering is pinned by a snapshot |
| **v0.508.7** | Internal - `bynk` no longer declares its unused `bynk-render` dependency |
| **v0.508.6** | CI's test job records per-test durations (nextest JUnit) as a build artifact |
| **v0.508.5** | Record the published-set rule (publish only what an installed binary reaches; retired crates get a final onward-pointing release); `bynk-grammar` announces its final crates.io release |
