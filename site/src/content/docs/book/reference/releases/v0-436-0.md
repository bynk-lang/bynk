---
Released on 29 October 2026 as **v0.436.0**, with the increments from v0.434.1 to v0.436.0.
See [Upgrading](/book/reference/upgrading/) for what to change when you move to it.

| Version | Highlights |
|---|---|
| **v0.436.0** | A service contract's canonical form names a sum variant's payload fields (`A(x: Int)`), so renaming one changes the contract hash |
| **v0.435.3** | `bynk deploy --context --accept-compatible-skew` deploys a callee ahead of live callers whose contract it stays compatible with, recorded in `bynk.contracts.lock` |
| **v0.435.2** | `bynk deploy` and the editor's contract diff classify a service-contract change as compatible or breaking, with reasons |
| **v0.435.1** | `bynk openapi` writes an OpenAPI 3.1 document for a project's `from http` services, derived from the routes, handler params, boundary types and refinements |
| **v0.435.0** | `bynk tail` streams a deployed Worker's logs with stack frames rewritten to `.bynk` locations |
| **v0.434.4** | The LSP server generates its `bynk/…` custom-request registrations and `experimental` capability flags from one table, so the two cannot drift |
| **v0.434.3** | The editor contract also carries the `bynk doctor --json` and `bynk status --json` golden outputs, so the VS Code extension can check its fixtures against them |
| **v0.434.2** | The VS Code extension moved to its own repository, `bynk-lang/vscode-bynk`, with its own version line; the compiler's releases now publish an editor contract and notify it |
| **v0.434.1** | The VS Code extension reports an error, with the binary to update, when the language server is older than the oldest version it supports (`bynkServerMinVersion`) |
