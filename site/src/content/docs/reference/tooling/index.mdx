This section of the Reference is for the person operating the toolchain:
running the compiler in CI, wiring up a project, reading the emitted TypeScript,
and setting up an editor. It assumes you already know roughly what Bynk is and
answers the operational questions instead — which command, which flag, which key
in `bynk.toml`, what the build actually produces.

To learn the language itself — what its constructs mean and how its types
behave — read the [Book](/book/) and the [language reference](/reference/); the
normative emission and runtime semantics live in the
[specification](/reference/spec/). This section is about operating the tools
that act on that language.

## Tool reference

The reference for each tool around the compiler. If you just want editor
support, the how-to [Set up editor support](/reference/tooling/editor-and-tooling/editor-support/)
is the quickest path.

| Tool | Binary / package | Purpose |
|---|---|---|
| [`bynk-fmt`](/reference/tooling/bynk-fmt/) | `bynk fmt` | The canonical source formatter. |
| [`bynk-lsp`](/reference/tooling/bynk-lsp/) | `bynk-lsp` | The language server (diagnostics, hover, go-to-definition, formatting). |
| [`bynk mcp`](/reference/tooling/bynk-mcp/) | `bynk mcp` | A Model Context Protocol server, so AI agents outside VS Code can ask the toolchain about Bynk. |
| [`bynk client`](/reference/tooling/bynk-client/) | `bynk client` | A typed TypeScript client for a project's `from http` services, for a front end. Experimental. |
| [`bynk openapi`](/reference/tooling/bynk-openapi/) | `bynk openapi` | An OpenAPI 3.1 document for a project's `from http` services, for client codegen, docs and CI. |
| [`tree-sitter-bynk`](/reference/tooling/tree-sitter-bynk/) | — | The grammar used for highlighting and structural tooling. |
| [`vscode-bynk`](/reference/tooling/vscode-bynk/) | VS Code extension | Editor integration built on `bynk-lsp`. |

All are built from the same repository as the compiler, so they track the
language version for version (currently v0.678).
