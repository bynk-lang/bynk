Released on 22 June 2026 as **v0.78.0**, with one increment, v0.78.
See [Upgrading](/reference/upgrading/) for what to change when you move to it.

> _Docs & examples (under v0.78, no version change):_ the
> [`examples/` gallery](https://github.com/bynk-lang/bynk/tree/main/examples) was
> refreshed — six of the seven projects now ship unit tests, with each one's pure
> logic (a refined type's boundary, a key helper, a windowing or health policy)
> factored into a tested `commons`. The gallery's testing note was corrected to
> reflect what is testable today (see
> [#291](https://github.com/accuser/bynk/issues/291) for the platform-capability
> test-surface limitation the split works around).

| Version | Highlights |
|---|---|
| **v0.78** | **Run/Debug a test from the editor** (tooling; `vscode-bynk` only — no language or compiler change). Each test now shows a **`▷ Run Test | Debug Test`** CodeLens at its declaration, and VS Code's native run/debug gutter glyphs appear next to it — no need to open the Testing view first. The enabler is **eager test discovery**: the extension now discovers a project's tests when you open/edit a `.bynk` file (debounced, coalescing the project compile), not only when the Testing view opens — which both populates the tree and lights up the glyphs; the CodeLens is the explicit, discoverable layer on top. Both delegate to the project run/debug (`bynkc test` has no single-test filter, so they run the whole suite; for **Debug**, your breakpoint pauses). Lenses land on **case** declarations; a `bynk.testCodeLens` setting (default on) disables them. Single-test execution is a noted follow-on. |
