The increments merged since **v0.661.1**, the latest release. They ship in
the next one. Each increment's row is added here when it merges.

| Version | Highlights |
|---|---|
| **v0.816.0** | A `Container` instance name built from a request's own input on a route whose caller is not authenticated warns (`bynk.container.unbounded_instances`), because every distinct name starts a container that costs money; the reference example names its instance from the authenticated identity |
| **v0.815.1** | An agent call's request body to a Durable Object no longer carries the caller's compose-private `deps` entries, so a `SignedCookie` actor's signing keys (`secret` and `previous`) are not sent to the Durable Object, where a tail worker or request log could read them; every `__`-prefixed `deps` key is now dropped from the wire unless it is explicitly marked wire-safe, so the next secret-bearing entry is private by default |
| **v0.815.0** | A commons function may take a capability parameter, `given Store: Kv`, beside shared capabilities such as `Logger`, and every call binds each parameter explicitly inside its arguments, `remember(key, value, given Store = Sessions)`, never inferred; a commons selects the kinds with `consumes bynk.cloudflare { Kv }` (experimental, behind the `[unstable] allow` entry `bynk.given.parameters`) |
| **v0.814.0** | A pattern that binds the same name twice, at any depth (`Both(a, a)`, `Order { id: x, total: x, .. }`, `[x, ..x]`, `Some(a as a)`), is the error `bynk.types.duplicate_pattern_binding`, in every pattern position including `is`, `let … else`, a lambda's pattern parameter and a suite case; a name shared across an or-pattern's alternatives is still required, not a duplicate |
| **v0.813.1** | `bynk deploy --format json` also reports the adoption refusals and notes of `[deploy.vectorize]` and `[deploy.containers]`, the account's notes on the plan, and the email-forward destination warnings as `refusals` and `warnings` entries with stable codes |
| **v0.813.0** | A change inside a record an event carries (a nested field removed or retyped, or a nested wire name changed without `replaces`) is `bynk.event.non_additive_schema_change`, and a nested `replaces` is honoured |
| **v0.812.2** | The workerd and browser system tests no longer fail intermittently under full-suite load (a port taken during wrangler's start-up, a request answered before the Worker was ready, a timeout shorter than a loaded machine's latency, a log read before wrangler flushed it, a rate-limit window ended between two requests) |
| **v0.812.1** | `bynk check <dir>` inside a project now checks the project, reading its `bynk.toml`, instead of checking the directory as a bare tree, so `bynk check src` no longer reports `bynk.stability.experimental` for an item the manifest already allows (and no longer tells you to add an entry that is there); a note names the project it checked. The README and the example READMEs say `bynk check` |
| **v0.812.0** | `bynk deploy` creates R2 buckets and D1 databases through Cloudflare's API instead of wrangler, and adopts one already there by reading the account (a bucket this account answers for, a database of exactly that name) rather than by matching wrangler's error text; D1 migrations stay on wrangler |
| **v0.811.0** | Fetch responses carry `setCookies: List[String]`, every `set-cookie` value separately and intact, on `Response`, `BytesResponse` and `StreamResponse` (so a login flow's cookies can be read), with `headers` unchanged |
| **v0.810.2** | The workspace's minimum Rust version rises to 1.98, with the pinned toolchain and every CI toolchain ref, and `oxc` moves from 0.146 to 0.160, so `bynk-strip` passes the source map through directly instead of writing it out as v3 JSON and parsing it back, and the crate graph holds one copy of `oxc_sourcemap` |
| **v0.810.1** | Record the decisions behind the `ApiKey` actor scheme: the key format and the opaque handle, keys stored only as peppered HMACs, and the verification contract (API keys track, slice 0; no behaviour changes yet) |
| **v0.810.0** | `RequestHeaders.entries()` lists every request header as a `Map[String, String]` of lower-case names, a repeated field combined with `", "` (`Cookie` with `"; "`) and the route's consumed credential absent; experimental, behind `bynk.RequestHeaders.entries` in `[unstable] allow` |
| **v0.809.1** | Capability parameters for commons functions: decisions D1 (declaration and explicit binding) and D2 (kinds and shared capabilities) are recorded; no behaviour changes yet |
