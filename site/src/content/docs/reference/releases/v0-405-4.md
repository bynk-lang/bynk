Released on 26 October 2026 as **v0.405.4**, with the increments from v0.404.1 to v0.405.4.
See [Upgrading](/reference/upgrading/) for what to change when you move to it.

| Version | Highlights |
|---|---|
| **v0.405.4** | `HttpResult` moves to its own runtime module, so a bundle-target HTTP service no longer emits the HTTP response helpers or the boundary module (#2443, ADR 0615) |
| **v0.405.3** | A project emits only the runtime modules it reaches, as `__bynk_runtime/<module>` files, instead of one `runtime.ts` (#2441, ADR 0615) |
| **v0.405.2** | The playground graph (`bynk_compile`) carries the per-module runtime files a program reaches instead of `runtime.js`; the spec and docs describe `__bynk_runtime/` (#2442, ADR 0615) |
| **v0.405.1** | A project emits only the runtime modules it reaches, as `__bynk_runtime/<module>` files, instead of one `runtime.ts` (#2441, ADR 0615) |
| **v0.405.0** | The browser wasm exports `bynk_format`, so the playground can format a snippet to the house style |
| **v0.404.5** | The VS Code extension ships `Bynk Dark` and `Bynk Light` colour themes |
| **v0.404.4** | Fix `bynk deploy` KV namespace creation against real wrangler, which has no `--json` on `kv namespace create` (#2428) |
| **v0.404.3** | Decision (#2426) — the runtime ships as per-module files, and a project emits only the modules its graph reaches; no helper moves into `bynk-std` |
| **v0.404.2** | `bynk_compile` tags each emitted file with a `kind` (`user`, `wiring` or `support`) |
| **v0.404.1** | The playground moves to its own repository, [bynk-lang/playground](https://github.com/bynk-lang/playground), served at [playground.bynk-lang.dev](https://playground.bynk-lang.dev) from a pinned release's browser artefacts |
