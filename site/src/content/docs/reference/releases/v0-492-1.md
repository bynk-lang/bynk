A default is a static value with a wire form, now including `Map.empty()` and `Set.empty()`; in a generic record it must hold for every instantiation. `FetchOptions`, `QueueSend`, `KvGet`, `KvPut` and `R2Put` give every field the default that reproduces the plain operation, so `Fetch.sendWith(req, FetchOptions {})` is `send(req)`. `bynk.event.bad_field_default` is now `bynk.types.bad_field_default`, `bynk.event.default_outside_event` is retired, and a default on a variant payload field is `bynk.types.field_default_on_variant`. See [Field defaults](/reference/types/#field-defaults) and [Add an option without breaking callers](/book/guides/program-structure/add-an-option/). |
| **v0.460.0** | Record destructuring in `let`: `let Item { sku, qty, .. } = item` binds a record's fields for the rest of the block, with `=` or `<-`, and needs no `else` when every field is matched by a name, `_` or a nested pattern of the same kind; a refutable record pattern still takes its `else` (patterns track slice 2, [#2654](https://github.com/bynk-lang/bynk/issues/2654)). A record `let … else` that cannot fail now offers a one-click fix that removes its `else` |

| **v0.455.0** | Record patterns: `TypeName { f1, f2: pattern, .. }` matches a record by its fields in a `match` arm, nested in a variant payload, or after `is` (parenthesised, `x is (T { .. })`). They are always open, so the trailing `..` is required and adding a field to a record never breaks a pattern.
