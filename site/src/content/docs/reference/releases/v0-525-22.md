title: v0.525.22
description: The increments released in Bynk v0.525.22.
---
Released on 9 November 2026 as **v0.525.22**, with the increments from v0.512.11 to v0.525.22.
See [Upgrading](/reference/upgrading/) for what to change when you move to it.

| Version | Highlights |
|---|---|
| **v0.525.22** | The test D1's parameter scanner treats non-ASCII characters as part of a named parameter, as SQLite does, so `:café` and `:cafè` count as two parameters (#3157) |
| **v0.525.21** | `bynk check` checks `Json.decodeSql[T]` of a literal D1 `all` / `first` read against the statement's result columns: a required field of `T` with no column is `bynk.d1.select_field_missing` |
| **v0.525.20** | `bynk check` counts a D1 call's parameters even when its binding has no migrations directory (`bynk.d1.sql_param_count`); the other D1 SQL checks still need a schema, and `[check] d1_sql = false` turns both off |
| **v0.525.19** | The D1 SQL check is pinned for context-level `fn … given` functions (literal, `const`, parameter count and `batch` are checked as in a handler) |
| **v0.525.18** | `bynk test --mutate` makes SQL mutants only from the SQL the checker ties to a D1 call (including a `const` bound to one, in any case), and now reads `\n` escapes and `CASE … END` correctly |
| **v0.525.17** | The D1 SQL check is pinned for `suite … as integration` cases (they are checked like unit-suite cases); `system` suites and suite helper `fn`s can't hold a D1 call |
| **v0.525.16** | The D1 SQL schema check reuses a database's built schema until its migrations change, so the language server doesn't re-run every migration on each edit; test-body statements also point inside the literal |
| **v0.525.15** | `bynk.d1.sql_invalid` points at the token SQLite refused inside the SQL literal, not the whole argument |
| **v0.525.14** | An agent call no longer forwards the caller's Workers `env` (secrets and vars) in the inter-Durable-Object request body |
| **v0.525.13** | `bynk test --mutate --changed <git-ref>` mutates only declarations in changed files, and `--mutate-jobs <n>` runs mutants in parallel scratch directories with the same report (slice 4 of #3069) |
| **v0.525.12** | `bynk check` prepares the literal D1 statements in the `case` and `property` bodies of unit suites against the suite target's migrations |
| **v0.525.11** | `bynk check` prepares a D1 call's `const` SQL against the migrations' schema (the constant's entry had replaced the statement's site, so it was accepted unchecked) |
| **v0.525.10** | A suite's stub values can name its own `type` and `const`, and a suite type works under `Result` and other generics at a JSON boundary |
| **v0.525.9** | Workers WebSocket `on open`/`on message`/`on close` bodies that call a consumed context's service or construct an agent now get the Durable Object's own `env`, so the call reaches the real Service Binding or DO namespace instead of an in-memory fallback |
| **v0.525.8** | `bynk check` prepares the `SqlStatement`s written inline in a D1 `batch` against the migrations' schema |
| **v0.525.7** | `bynk test --mutate` also mutates SQL literals: comparisons, `max`/`min`, and one `AND` conjunct of a `WHERE` |
| **v0.525.6** | `bynk check` counts a D1 call's parameters when the list is a `let` bound to a list literal; the `[check] d1_sql = false` opt-out and the editor path are tested |
| **v0.525.5** | `bynk test --mutate` also mutates `if` conditions, `match` arm guards and binary `+`/`-` |
| **v0.525.4** | `bynk fmt` keeps a comment between call arguments and between record-literal fields (#3110) |
| **v0.525.3** | `bynk test` reads `[profile.dev] contracts`, and `bynk deploy` refuses `[profile.release] contracts = true`; one shared rule resolves a verb's profile (#3107) |
| **v0.525.2** | CI runs in stages matched to a PR's state — fast checks on drafts, the full three-OS gate once a PR is ready for review, and a thin integration check in the merge queue |
| **v0.525.1** | `bynk build`, `bynk dev` and `bynk deploy` print a `Compiling`/`Finished` line per context on a terminal; `--quiet` turns them off and a pipe is unchanged (#3100) |
| **v0.525.0** | `bynk check` prepares each literal `D1` statement against the schema its migrations build, reporting a syntax error, an unknown table or column, a wrong `?N` count and a `select[T]` field with no column (`bynk.d1.sql_invalid`, `bynk.d1.sql_param_count`, `bynk.d1.select_field_missing`, and the warning `bynk.d1.migration_invalid`); `[check] d1_sql = false` turns it off |
| **v0.524.0** | A `String` constant bound to a literal is accepted as a database call's SQL |
| **v0.523.1** | `bynk build --profile dev|release` and `[profile.dev]`/`[profile.release]` tables in `bynk.toml` choose whether a build carries the function-contract call-site guard; the default stays `release`, the bytes `bynk compile` writes (#3054) |
| **v0.523.0** | `@example("…")` after a `Matches`/`IsoDate` refinement gives `Val[T]` a value, so `bynk test --smoke` runs patterned routes |
| **v0.522.0** | A suite declares its own `type` and `const` items, private to the suite and never deployed |
| **v0.521.0** | A `tsc` failure on generated code is reported as `bynk.codegen.tsc_failed` at the Bynk source line it came from, by `bynk test` and the new opt-in `bynk check --emit` |
| **v0.520.0** | `bynk test --require-tests` fails a project that declares no tests (`error.kind == "no_tests"` under `--format json`); without it the message is now `warning: no tests found in <dir>`, still exit 0 |
| **v0.519.0** | A record field (not an event or old-state field) whose type applies a user generic record or sum may declare a default, `page: Paginated[String] = Paginated {}` or `outcome: Outcome[Int] = Pending("queued")`; inside a generic record it may write no value of the record's own type parameter |
| **v0.518.1** | `bynk build` builds a project with no flags, taking `out`, `target`, `platform` and `emit` from a new `[build]` table in `bynk.toml`; `bynk compile` is unchanged and ignores it (#3054) |
| **v0.518.0** | `bynk revert` makes a Worker's previous deployment live again without a rebuild, after checking D1 migrations, agent schema versions, contracts, ids and secrets; each deploy records `BYNK_DEPLOY_FACTS` on the version it pushes |
| **v0.517.0** | A case drives a `from websocket` service by address (`svc.open(tc, …)`, `svc.message(tc, frame)`, `svc.close(tc)`) against a recording `TestConnection[F]()` |
| **v0.516.0** | `bynk test --mutate` applies one typed mutation at a time (comparison operators, `&&`/`||`) and reports the mutants the suites don't catch, with source spans; `[test.mutate] exclude` in `bynk.toml` |
| **v0.515.0** | A field added to a service's request or response type with a default is a compatible contract change, so a callee deploys ahead of its callers; the contract hash still covers the field, and the stored shape records which fields have a default (shape text with a default is unreadable by earlier versions, so upgrade every deployer together) |
| **v0.514.3** | `bynk fmt` keeps a comment between the elements of a list literal (#3067) |
| **v0.514.2** | `bynk.deploy.lock` no longer lists each Worker's static assets by hashed name, so a release that changes only pages leaves the lock unchanged (an existing lock loses its `assets` lines on its next write) |
| **v0.514.1** | A `system` suite resolves an actor's `identity` type declared in a `commons` the context uses, so `by User("alice")` is accepted |
| **v0.514.0** | An `Oidc` route is tested at the `system` tier. The driver is the issuer, and `by Forged`, `by Expired`, `by WrongIssuer` and `by WrongAudience` drive its seam |
| **v0.513.1** | A `system` suite reads a `Raw` response back as `Raw(body, contentType)`, as the unit tier does (#3050); a `system` suite asserting `expect r is Ok(_)` on a raw or streamed route now sees `Raw`, so change it to `Raw(_, _)` |
| **v0.513.0** | A sum variant added inside an agent's stored state is an additive change in bynk.schema.lock |
| **v0.512.11** | A nightly CodeQL scan now covers the TypeScript the compiler emits for Cloudflare Workers, with models of the Worker request and the redirect `Location` header, and deliberately vulnerable canary projects that fail the scan if those models stop firing |
