## ADR: container-instance-kind
title: Container is an instance kind that runs a Docker image as a Durable Object class
summary: Decisions A, D, E, F and J of #3477 for slice C1: a named instance with a build directory and a port, closed egress, no instance ceiling, a built-in container API and no npm dependency

**Context.** Cloudflare Containers run a Docker image as the container of a Durable Object class. Under the `durable_object` scheduling policy there is no per-application instance ceiling, no package is needed (`@cloudflare/containers` is deprecated in favour of `ctx.container`), and egress is open unless `start()` says otherwise. The image is built and pushed by `wrangler deploy`, which needs Docker, so nothing Bynk deploys itself changes here.

**Decision.** Records decisions A, D, E, F and J of #3477 as settled for slice C1. A: `Container` is an instance kind of `bynk.cloudflare` (`capability Renderer = Container @build("…") @port(8080)`), not a new declaration and not an agent flavour; it shares only the Durable Object binding and `exports` plumbing, through `BindingSource::ContainerInstance`. Its class is `__Container_<Name>`; a user `agent` cannot collide with it because an identifier cannot begin with `_`. D: the surface is HTTP to the instance's one port, with `Fetch`'s `Request`, `Response` and `BytesResponse`, addressed by instance name (the Durable Object name); errors are `ContainerError` values (`StartFailed`, `Unavailable`, `Timeout`, `Network`); an invalid name or request faults before the call. E: a container starts lazily on its first call, `@sleepAfter` (more than zero, at most 6 hours) is applied with `setInactivityTimeout` on every start, `@instanceType` (`lite`, `standard-1` to `standard-4`) is passed as `instance` to `start()` and never emitted into config, and there is no `@maxInstances` because the policy has none. F: the runtime is the built-in container API, with no npm dependency and no `[[npm]]` row. J: egress is always off (`enableInternet: false`); `@internet` is slice C5; `@forward` names Worker secrets passed as `env` and is never written to config, lock or log. `WRANGLER_MIN` is unchanged; the 4.136.0 floor for container Workers is slice C2's. No prices, allowances or billing dates are stated anywhere; the reference links to Cloudflare's pages.

**Consequences.** Experimental, so no 1.0 promise. A program that does not use `Container` has unchanged handler and Worker output; only the emitted `bynk.cloudflare` module grows. `bynk deploy` (Docker preflight, adopted images), `bynk dev` and the real-container smoke follow in C2 and C3. A real deploy has not been exercised: Docker was not available and the scratch account is not on Workers Paid, so rollback, inactivity and local-dev behaviour are unverified.
