## ADR: predicates-read-collection-size
title: An invariant or transition reads a store collection's size, and nothing else of it
summary: What a predicate may read of a Map, Set, Cache or Log store field, and which count it sees

**Context.** An invariant that mentioned a `Map`, `Set` or `Cache` store field failed with `bynk.resolve.unknown_name`, although the reference says a predicate reads the agent's store fields by bare name. Excluding scans is right, since a scan in a predicate would read the whole collection at every commit. But `size()` reads one count, and bounding a collection ("at most 100 lines") is among the commonest invariants.

**Decision.** A `Map`, `Set` or `Cache` field may be asked `size()` in an invariant (`lines.size()`) and in a transition (`new.lines.size()`, `old.lines.size()`); the call is typed `Int`. Any other read of a collection field is `bynk.invariant.collection_scan` (`bynk.transition.collection_scan`), which says why and what to do instead. A `Log` has no `size()`, so any read of it is that error. The value checked is the staged one, as for a `Cell`: `commitState` awaits the handle's count, which the handle maintains as the overlay's puts and deletes apply, so the check adds no storage read beyond the one count. In a transition, `old.<field>.size()` is the last committed count: the stored per-collection count, or for a record still in the whole-record layout the entries its inline collection holds. `String`/`Int` layouts and stored state are unchanged.

**Consequences.** Nothing that compiled before changes meaning: a collection field in a predicate was an error. The emitted `commitState` binds `__size_new_<field>` and `__size_old_<field>` before the checks, through a new runtime helper `committedSize`. Member completion on a collection inside an invariant offers only `size`. Hover, semantic tokens and signature help are unchanged.
