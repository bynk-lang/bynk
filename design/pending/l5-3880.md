## ADR: queue-delivery-metadata
title: A queue handler can take its delivery metadata
summary: An optional `QueueDelivery` parameter carries the platform's attempt count and send time

**Context.** Cloudflare gives every queue message `attempts` (from 1), `timestamp` (when it was sent) and `id`. A Bynk handler saw only the decoded body, so it could not back off by attempt, notice a message that keeps failing, or measure how long a message waited.

**Decision.** (A) The fields are `attempts: Int` and `sentAt: Instant`, the latter converted from `msg.timestamp`. (B) `id` is not exposed: whether it is stable across retries, including after a move to a dead-letter queue, is not documented, and showing it needs a send-retry-compare experiment on a deployed queue, which this implementation could not run (no Cloudflare account). The issue's own fallback applies: omit `id` and point authors at a key the producer writes into the message. It is recorded here as unverified, to be added as an opaque `MessageId` if a deployed queue shows it stable. (C) The delivery parameter is identified by its type, exactly `QueueDelivery`, like cron's `CronSchedule`: the message and at most one `QueueDelivery`, in either order. A message whose own type is `QueueDelivery`, or two of them, is `bynk.queue.bad_params`. (D) The test address takes an optional delivery: `q.message(m)` delivers `attempts: 1` and `sentAt` at the epoch, where each case's harness clock starts, and `q.message(m, QueueDelivery { attempts: 4, sentAt: t })` sets both. At `system` the driver puts them on the message double. The default `sentAt` is the epoch rather than the harness clock's current reading, because the queue driver's runtime is spliced independently of the clock module; a case that moved the clock passes the instant it means.

**Consequences.** `QueueDelivery` is a record of `bynk.cloudflare`, beside `QueueSend`. The generated `queue` entry passes `{ attempts: msg.attempts, sentAt: msg.timestamp.getTime() }` in the declared position, and its structural `batch` type names the two members it reads, so every queue entry's `index.ts` golden changes by that type. A handler that takes no delivery is called exactly as before. Attempts rising across `Retry`s is shown at `system` by delivering with explicit attempts, since the double delivers one message once.
