## ADR: validation-rule
title: A ValidationError names the failed predicate as a closed ValidationRule sum
summary: `e.rule` is a prelude `ValidationRule` with a `Bound` sum for numeric arguments; the 400 body carries it and never the value

**Context.** `ValidationError` had two `String` fields, so code could not tell which predicate failed, or by what limit, without parsing English, and an HTTP client reading a `400` could not either. The compiler generated the check, so it knew the rule and its argument and threw them away.

**Decision.** [DECISION A] `ValidationRule` is a closed sum with a variant per predicate and its typed arguments, in the first-party commons `bynk.validation`; a new predicate is a visible, exhaustive-`match` change, and the drift is pinned by an exhaustive `PredKind` match in `bynk-ts`. [DECISION B] A `Bound` sum (`IntBound`, `FloatBound`, `DecimalBound`, `DurationBound`) carries a range or one-sided bound, because the base decides its type. Two variants beyond the issue's list: `Cron`, a predicate (#3873) the list omitted, and `WellFormed`, for a value that is not a valid member of its base type at all (not finite, outside the safe-integer range), which fails before any predicate and has none to name; the alternative was `Option[ValidationRule]`, which adds a layer for every caller. [DECISION C] Both are prelude types (ADR 0925): rows in `PRELUDE_TYPES`, reached with no `uses` by a unit that names either or reads `.rule`, and their variants resolve only where the type context names the sum, so a user's own `Positive` or `MaxLength` variant is untouched. [DECISION D] The offending value stays runtime-only and is not on the wire. The issue took the current body not to include it; it did (the generated handlers put the whole runtime `ValidationError` in the body), which was fixed first and on its own as #4278, so the helper that builds the wire `violation` from `field` and `message` now also carries `rule`. [DECISION E] `message` stays and is still generated from the rule.

The rule is a plain tagged object in the emitted TypeScript, as every sum is (`{ tag: "MaxLength", limit: 280 }`), built by one `PredKind` → rule mapping beside the check mapping, so the owner-side `.of` and the boundary-side decoder cannot disagree. On the wire it is written as every sum is, with `kind`; a `Decimal` bound is its canonical text and a `Duration` its milliseconds.

**Consequences.** `e.rule` and the two sums are available everywhere a `ValidationError` is. The wire contract and OpenAPI gain `ValidationViolation`, `ValidationRule` and `ValidationBound` schemas for the `400` body. `rule` is additive to the `400` body. The browser client's `ValidationError` gains `rule` (the in-memory form for a value the client refused to send, the wire form for one the server reported) and a now-optional `value`.
