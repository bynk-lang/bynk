## ADR: sse-event-record
title: Streaming takes structured SseEvent records beside plain strings
summary: A bynk record for the SSE fields, framed in the runtime, with a bare String kept byte for byte

**Context.** `Streaming` emitted one `data:` event per `String` element, so a handler could not set an event name, an `id` a browser echoes back as `Last-Event-ID`, or a `retry` interval. Without `id` a dropped connection cannot resume, which is the point of using SSE over a plain stream. The reference called a structured event a planned follow-on.

**Decision.** (A) A `bynk` record `SseEvent { data: String, event: Option[String] = None, id: Option[String] = None, retry: Option[Duration] = None }`, exported transparently so a handler writes it as a record literal and leaves the optional fields off. (B) `Streaming` accepts `Stream[String]` or `Stream[SseEvent]`, decided by the stream's element type in the checker; a `String` element frames exactly as before, so no existing handler changes a byte. (C) The runtime frames an event as `event:`, `id:`, `retry:` (whole milliseconds) then one `data:` line per line of `data`, split on CRLF, LF or CR, and a blank line to end it. (D) A value the wire cannot carry is never written as a different one: an `event` or `id` with a line break, an `id` with NUL, or a `retry` that is not a non-negative whole number of milliseconds throws, which errors the body at that element in-band, exactly as a throw from the source does.

**Consequences.** A browser `EventSource` can resume from `Last-Event-ID` and honour `retry`. The framing lives in one runtime function, so the unit tier (which drains the stream) sees the records and the system tier sees the wire. Heartbeats and a client-side wrapper are separate follow-ups under the same issue. A unit-tier `match` on `Streaming(s)` binds `s` as `Stream[String]` whatever the handler streams, because `HttpResult[T]` does not carry the element type; draining it is safe, but reading an element of an `SseEvent` stream as a `String` is not checked. Carrying the element type is left to a follow-up.
