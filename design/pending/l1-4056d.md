## ADR: queues-over-rest
title: Queues run over REST, and every account resource is off wrangler
summary: queue create, lookup and delete move to `/queues`, a refused create is settled by reading the account's queue list, every queue deploy needs the API credentials, and the wrangler text matching left is two predicates and one parser, each for an operation wrangler keeps

**Context.** Back-half paydown 1D.4d (#4056) moves queues, the last account resource on wrangler, to Cloudflare's REST API, under ADR "Account resources need API credentials". Under wrangler, a lost create race was recognised by the words "already exists" on either stream, and a queue already deleted by `Queue "n" does not exist`. The ADR "The wrangler/REST boundary and the Cloudflare client layer" kept that matching in `cloudflare/error.rs` "until 1D.4 empties it". The API reference (https://developers.cloudflare.com/api/resources/queues/) documents `POST /queues {queue_name}`, `DELETE /queues/{queue_id}` and a numbered listing (`page`, `per_page` up to 500), and the error-code table (https://developers.cloudflare.com/queues/reference/error-codes/) documents `10104 QueueNotFound`. It documents no lookup by name, and no code for a name already taken: the `11009` wrangler printed is not in the table.

**Decision.**

- **Three typed methods (Decision C).** `queue_create(name)`, `queue_find(name) -> Option<id>` and `queue_delete(name) -> bool` run requests built in `cloudflare/rest/queues.rs`. A queue is found by paging the listing (100 a page, to `total_pages` or while full, at most 100 pages, and not past a page that brings no queue not already seen) and matching `queue_name` exactly, and deleted by its id. A listing cut short by that bound or by a repeated page, without the name, is an error, not an absent queue, so `--prune` never forgets a queue it could not see; an id that could not be one is refused before it reaches a path. The three queue `OpKind` variants are deleted, with `WranglerError::already_exists` and `already_gone`.
- **A refused create is settled by the account (as 1D.4b settles R2 and D1).** Every deploy looks each queue up first, so a refusal is the race-loser's path: a create Cloudflare refuses (`CloudflareError::is_refusal`) is a success, recorded as reused, only when the listing then shows the queue. Otherwise the create's own error stands, with a failed lookup appended to it. A denied token, a server error or a transport failure fails at once.
- **A queue already gone is success (#839).** A delete that finds no queue of the name, or that Cloudflare answers with `10104`, is the end state `--prune` asked for.
- **Credentials on every queue deploy (Decision E).** Each deploy checks every declared queue, recorded or not, so a project with a queue needs both variables on every deploy, and a `--prune` with a queue orphan does too. The pre-flight now covers KV, R2, D1, Vectorize and queues, in that order.
- **The interim paragraph ends.** The boundary ADR's "until then, every resource operation is still a wrangler call" no longer holds: every account resource runs over REST. What is left of wrangler's text belongs to operations wrangler keeps by that ADR's boundary: in `cloudflare/error.rs`, the predicates `worker_not_found` (code `10007` or `10090` from `wrangler deployments list`, now checked only for that operation) and `push_lost_its_upload` (code `10007` in `wrangler deploy`'s output); and one stdout parser, `parse_secret_list` in `deploy/provisioning.rs`, for `wrangler secret list --format json`.

**Consequences.** A queue project's deploys need both variables, as a Vectorize project's do. `wrangler_resource_ops` falls from 3 to 0, and a resource operation added on wrangler would raise it. The live checks of a lost race and of `10104` are left to the maintainer's sandbox script.
