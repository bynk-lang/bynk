## ADR: capability-parameters-and-binding
title: A commons function declares capability parameters, and every call binds each one explicitly
summary: `given Name: Kind` on a commons free function; `f(x, given Name = Cap)` at every call, never inferred or defaulted; `bynk.given.fn_outside_context` retires
**Context.** #3959, settled in the capability-parameters track (`design/tracks/capability-parameters.md`, D1). ADR 0726 let a context's free functions declare `given` and deferred capability parameters on commons functions. A commons is shared by contexts that hold different capabilities, and most Cloudflare kinds (`D1`, `R2`, `Queue`, `Service`, …) are used only through derived instances, which only a context declares (ADR 0469 D4). So a commons function has no name for the instance it needs, and libraries take function values instead. The hazard the design must contain is binding the wrong instance: reading through `PriceCache` where `Sessions` was meant is well-typed, so the compiler cannot catch it.

**Decision.** (A) A commons free function, a test-only commons' included (ADR 0974), may declare a **capability parameter** in its `given` clause, `given Store: Kv`: a capitalised name and an instantiable kind the commons selects (the companion ADR on kinds and shared capabilities, D2). In the body the name is called as a capability is (`Store.get(key)`) and lambdas close over it (ADR 0033). The ADR 0726 A refusals still apply: a free function returning `Effect[T]`, never a method and never `Events`. A parameter is refused (`bynk.given.parameter_name_conflict`) if it shadows any capability or kind visible in the commons, a type parameter of the function, or another parameter; it is never a value, and `let s = Store` gets the error a capability used as a value gets, with a note naming it a parameter. The form is commons-only: on a context function, a method, a handler, a provider or a suite helper it is `bynk.given.parameter_outside_commons`. (B) **Binding is written inside the call's argument list, after the ordinary arguments, introduced by `given`**: `cached[Session](id, load, given Store = Sessions)`, `warmUp(given Store = Sessions)`. The argument list is `"(" ( args | (args ",")? "given" binding ("," binding)* )? ")"` with `binding = Name "=" CapRef` and no trailing comma, so it works unchanged in an effect-let, `do`, `par`, a lambda, a method chain and a nested argument. The trailing clause `f(x) given S = A` is rejected, because it has no closing token; type-argument brackets are rejected, because bindings are never omitted where type arguments usually are. (C) **Every call binds every capability parameter of the callee explicitly, exactly once, to a capability in the caller's own `given`, and a binding is never inferred or defaulted, even when only one candidate exists: not by the compiler, and not by a machine-applicable fix when there is more than one candidate.** An unbound parameter is `bynk.given.binding_missing`, whose fix offers one action per candidate and is machine-applicable only when exactly one exists, so `bynk fix` never chooses between instances; a name the callee does not declare, or a binding on a callee with no parameters, is `bynk.given.binding_unknown`; a repeated name is `bynk.given.binding_duplicate`; binding a shared capability is `bynk.given.binding_shared`; a right-hand side of another kind is `bynk.given.binding_kind_mismatch`; and one the caller does not hold is the existing `bynk.given.missing_for_call`. The right-hand side counts as used in the caller. One instance may bind two parameters; the aliasing is visible at the call. (D) The inclusion rule of ADR 0726 B is extended, not reshaped: it is checked at each call, a commons body can bind only to its own parameters (it sees no instance), and so it holds along every chain and through recursion. (E) Emission reuses ADR 0726's hidden `deps` parameter, typed by parameter and shared names; a call to a function with parameters builds the callee's `deps` from the caller's (`{ Store: deps.Sessions, Logger: deps.Logger }`, from `this.deps` in a Bynk-bodied provider), and `__exec` stays its own parameter. No runtime or Worker-binding change. (F) `bynk.given.fn_outside_context` loses its last trigger and moves to the retired codes. (G) Every new form (the parameter, the in-argument binding, a capability in a commons' `consumes`, and a commons suite's suite-local instance) is experimental and needs `[unstable] allow` until promoted.

**Consequences.** Additive: each new form is a parse error or an existing refusal today, so no program that compiles changes meaning, and retiring a code does not change one that compiles. Explicit binding is more to write than inference; that is the decided trade, since a library is called far less often than it is read in review, and the instance written at the call is the mitigation for the integrity hazard. Hover and the architecture model attribute a call through a parameter to the instance bound. A function with capability parameters cannot be named as a value (`bynk.given.parameterised_fn_value`); a lambda that binds takes its place. `stub` and `expect … called` name capabilities, never parameters. Recorded in the slices that ship them: forwarding (slice 2) and tests (slice 3).

## ADR: commons-capability-kinds-and-shared-capabilities
title: A commons names first-party capabilities in its braced consumes; an instantiable kind is a parameter, any other is shared
summary: ADR 0990 Decision E carried out, contract only; instantiable means parameter, non-instantiable means shared and bare; `Events` refused
**Context.** #3959, settled in the capability-parameters track (D2). ADR 0990 gave a commons a braced, type-only `consumes` and reserved it (Decision E) for capability contracts. A capability parameter needs a kind to name, and a commons function that logs or reads the clock needs `Logger` or `Clock`, of which a caller has exactly one.

**Decision.** (A) A commons may list a **first-party** unit's capabilities in the braced `consumes` ADR 0990 gives it, beside types: `consumes bynk.cloudflare { Kv, KvEntry }`. From a project adapter a capability is still `bynk.commons.consumes_not_types`, whose note names the first-party rule. The selection imports the contract only: no provider is instantiated and no binding is emitted (a commons is not a deployment unit), a unit that `uses` the commons gets no capability through it (as ADR 0990 D says for types), and a selected capability the commons never uses gets the existing unused-import treatment. Naming a `bynk` capability is an explicit `consumes bynk`, so it turns ADR 0983's implicit reach off for the file, as any explicit `consumes bynk { … }` does. (B) **Instantiable means parameter, non-instantiable means shared.** The registry's `instantiable` list decides, so a kind a unit adds later needs no new list. An instantiable kind (`Kv`, `D1`, `R2`, `Queue`, `Service`, …) is only ever a bound: named bare in a commons' `given` (`given Kv`), a test-only commons' included, it is `bynk.given.kind_needs_parameter`, with a fix to `given Store: Kv`. A non-instantiable first-party capability (`Clock`, `Random`, `Logger`, `Fetch`, `Secrets`, `Locale`, `Idempotency`, the Cloudflare singletons, `Crypto`) is a **shared** capability named bare: the callee's `given Logger` requires the caller's, exactly as between context functions today, and it is never bound. Used as a bound (`given L: Logger`) it is `bynk.given.shared_as_parameter`, because there is only one and a binding would add a name and no choice. A kind in an experimental unit (`bynk.testing`'s `TypedReads`) needs that unit's `[unstable] allow` as usual. `Events` stays refused, for ADR 0726's reason. (C) A valid argument for a parameter bounded by `K` is a capability in the caller's `given` that is a derived instance whose base is `K`, the bare `K` where the kind allows a bare use (`Instantiable::bare`; only `Kv` today), the caller's own parameter bounded by `K`, or, in a commons suite, the double of `K` (written `K`) or a suite-local instance of `K`. The kind must match exactly. A caller binding its bare `Kv` (`given Store = Kv`) writes that choice; a library never falls back to "the default namespace". (D) A commons still declares no capability and no instance (ADR 0469 D4). The one exception is a commons suite's suite-local instance (`capability Archive = Kv`), a fresh in-memory double with no binding and no deploy effect, which lifts `bynk.capability.derived_outside_context` in a commons suite only. (E) No structural bounds, no generic capability kinds (#3879), no capability contract declared in a commons, and no capability from a project adapter.

**Consequences.** A shared library can use `Kv`, `D1` or `Logger` without taking function values, and the platform lock falls where it does today: a context binds a `Kv` parameter only to a `Kv` it holds, which it holds only by consuming `bynk.cloudflare` itself. Shared capabilities are broader than they look: `given Secrets, Fetch` in a commons can read any secret the caller can and send it anywhere. The grant is visible in every signature on the path, and `Secrets` stays shared in this track (ruled 26 November 2026); a narrower grant is the line to revisit if dependency commons reaching secrets becomes a real concern.
