## ADR: expect-violates-names-the-refusal
title: `expect <call> violates <name>` holds only when the named declaration refused the commit
summary: A fault claim that names an invariant, a transition or a `@unique` constraint, matched against the InvariantViolation the commit raised, in-process only

**Context.** `expect <call> faults` holds for any fault, so a case meant to prove that `paid_has_payment_ref` refuses a bad state also passes when a stub fails, an `unreachable` fires or a different invariant refuses the commit. The runtime already knows which declaration fired: `InvariantViolation` carries `invariant` and `declaration`.

**Decision.** `expect <call> [by …] violates <name>`, `violates` contextual as `faults` is, holds when awaiting the call throws an `InvariantViolation` whose `invariant` is the name (or whose `Agent.invariant` is). The name is one declaration: an invariant or a transition by its name, or a `@unique` constraint by its field and key (`customers.email`). An unknown name is `bynk.expect.unknown_invariant`, which lists the reachable names; a bare name two reachable agents declare is `bynk.expect.ambiguous_invariant`, and `Agent.name` disambiguates. When several declarations would refuse at once the runtime reports the first in declaration order, and the claim matches that one. The claim is in-process only, like `faults`: at `system` it is `bynk.test.violates_needs_in_process`. A failure says what happened: the call returned, the call faulted, but not with a refusal (its kind and message), or the commit was refused by another declaration (`the commit was refused by invariant few_lines, not paid_has_payment_ref`).

**Consequences.** Additive: `violates` stays an ordinary identifier everywhere else, and nothing that compiled changes meaning. "The agents the call reaches" is the agents of the suite's target (or its integration participants), not a per-call analysis, so a name declared by another agent of the same context resolves even when the call does not reach it; it is then refused at run time like any other mismatch. Hover on the name after `violates` shows the refusing predicate, and completion there offers the declared invariants, transitions and `@unique` constraints (bare or qualified by their agent); the keyword highlights in tree-sitter.
