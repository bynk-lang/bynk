## ADR: deploy-pre-account-refusals-as-entries
title: The refusals a deploy makes before it reads the account are entries of the JSON plan
summary: A `Stop` carries a refusal's entry out of `deploy()` to `run`, which prints the plan document; fourteen refusals of the checks before the plan gain stable `bynk.deploy.*` codes and subject fields

**Context.** #3797, part 2. Part 1 made the plan document carry `refusals` and `warnings` and converted the agent-move gate, but the other gates of `deploy()` still returned a bare exit code after printing a stderr line, so a client asked for JSON got nothing for them.

**Decision.** (A) `deploy()` and the checks before the plan return a `Stop` (an exit code and the refusals, warnings and upload order the run knew); an `ExitCode` converts to one with no entries, so a stop that is not a refusal (a build's diagnostics, a declined confirmation, a failed push) is unchanged and prints no document. `run` prints the document when a stop carries refusals and `--format json` was asked. The agent-move gate uses the same path instead of printing inline. (B) The checks before the build and the plan are converted: the `--env` clash after `--`, an undeployable project, the doctor's preflight, an unknown `--context`/`--worker`, a build that produced no Workers (its own code, not an unknown context), unreadable Worker declarations, a refused email claim, an unreadable secrets file or ledger, a `--context` Worker bound to Workers never deployed, an unreadable contracts manifest, the older-contracts write and rebuild failures of `--accept-compatible-skew`, and a binding cycle in the upload order. Each has a stable code in the registry (with a blurb and an explain exception, as `bynk.deploy.agent_move_refused` has), and the facts of its subject where it has any. (C) The stderr lines are byte-for-byte what they were: the entry's message is the text without the `bynk: error: ` prefix the line adds.

**Consequences.** Additive for a JSON consumer. The refusals after the plan is derived (the contract skews, foreign pins, account names, the secrets-file passthrough, Hyperdrive, strict environments, recreate, the account checks) and the other warnings are still stderr-only; they follow in later increments, and the reference lists the codes that are entries so far.
