## ADR: queue-retry-after
title: A queue handler retries a message after a delay with RetryAfter(reason, delay)
summary: A new built-in QueueResult variant carries a delay, checked at compile time when written as a literal and clamped at run time when computed

**Context.** `Retry(reason)` always called `msg.retry()` with no delay, so a message that failed because a dependency was down came straight back and failed again. Cloudflare supports `msg.retry({ delaySeconds })`, a positive whole number of seconds, up to 24 hours. A handler returns a verdict and never calls the platform itself (ADR 0078), so the delay has to be expressible in the verdict.

**Decision.** (A) A new variant `RetryAfter(reason: String, delay: Duration)` beside `Ack` and `Retry`, resolved like the other built-in variants. Adding a delay to `Retry` would break every `Retry("…")`, and a variant has no default arguments; a separate wrapper means nothing outside a retry. (B) A delay written as a `Duration` literal outside 1 second to 24 hours is `bynk.queue.retry_delay_out_of_range`. A computed delay is rounded up to whole seconds and clamped to the range by the entry, with the clamp logged (`queue <name> retry delay clamped`): a fault would retry with no delay, the opposite of the ask (a `NaN` delay counts as 1 second). (C) `Retry` keeps its meaning: it calls `msg.retry()` with no options, so the consumer's `retryDelay` (#3877) applies, and `RetryAfter` overrides it for the one message. (D) At `system` the test address yields `RetryAfter(reason, delay)`, the message double recording `delaySeconds` and the case reading it back as a `Duration` of whole seconds, so a delay that was rounded or clamped reads as the settled one; `RetryAfter(_, d)` binds the delay.

**Consequences.** `QUEUE_VARIANTS` has a third entry with a new payload shape, and the verdict a case sees has four variants (`Ack`, `Retry`, `RetryAfter`, `Undecodable`), so an exhaustive `match` over it in a case needs an arm or a wildcard; that is the breaking part, and a handler that only constructs verdicts is unaffected. The queue entry gains `__bynkRetryMessage`, the one place a retry is settled. Hover on `RetryAfter` shows its payload and range; signature help shows `RetryAfter(reason: String, delay: Duration) -> QueueResult`; completion offers it wherever `Ack` and `Retry` are offered, from the same variant table; semantic tokens are unchanged (a built-in variant is tokenised as `Retry` is). No Cloudflare account was used: the delay is verified against the entry text and the system-tier double, not a deployed queue.
