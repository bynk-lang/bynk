level: patch
changelog: The generated TypeScript client's cleartext check (#4610) now also covers an explicitly set `Cookie` header, so a server-side call (Node, a framework's server, a Worker) that forwards a session cookie to a remote `http:` URL throws before anything is sent, as a bearer or OIDC token already did; a browser's own cookie jar sends no header the client sets and is unaffected
breaking: A generated TypeScript client that sets a `Cookie` header (in `headers`, the call's `init`, or as typed `cookies`) on a call to a remote `http://` base URL now throws a `CleartextCredential` error before sending, where it used to send the cookie in the clear. Use an `https://` base URL. `http://` to `localhost`, a `*.localhost` name, `127.0.0.0/8` or `[::1]` still works, and so do anonymous calls, a `viaBinding` Service Binding, and a page's own cookie jar (`credentials: "include"`), which sets no header the client controls.
