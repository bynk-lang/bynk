## ADR: deploy-plan-json-refusals-and-warnings
title: The JSON deploy plan is always a document, with refusals and warnings as entries
summary: `--format json` prints a plan document even when the run is refused; `refusals` and `warnings` are always-present arrays of `{code, message, subject fields, override}`, introduced here for the agent-move gate

**Context.** #3797. At v0.639.1 a refused plan under `bynk deploy --format json` exited 1, printed no JSON and wrote the refusal as a prose line on stderr, so a client had to match text to tell a refusal from a crash and lost everything else the plan knew. The refusals are spread over about a dozen gates in `deploy()`, and only three carry a `bynk.deploy.*` code.

**Decision.** (A) With `--format json` the run prints one document on stdout whether or not it is refused; the exit status still says whether the deploy could go ahead. A run that stops before the plan is derived prints `environment`, `refusals`, `warnings` and the upload `order`; one that reaches the plan prints the plan with the arrays beside it. (B) An entry is `{code, message, …subject, override?}`: a stable code, the readable message, the facts of its subject flat beside them, and the flag that overrides a refusal only where one does. The agent-move refusal carries `reason`, `context`, `agents`, `from`, `to`, and `override` only when naming the context would let it through (a move out of a group that stays, and a group renamed in place, cannot be accepted). (C) The `--accept-fresh-agent` warning is a `warnings` entry (`bynk.deploy.agent_starts_fresh`), and a name that matches no move is the refusal `bynk.deploy.accept_fresh_agent_unused`. `refusals` and `warnings` are always present, so a client reads one shape. The stderr lines are unchanged. This increment converts the agent-move gate; the other gates and warnings follow in later increments, and the docs say that only the listed codes are entries so far.

**Consequences.** Additive for a JSON consumer, which now sees two arrays (empty on a clean plan), and one that previously got no document on a refusal now gets one. `agents` is an array, not the single `agent` of the proposal's example, because a context can host several agents. The short format and the exit statuses are unchanged.
