## ADR: deploy-plan-json-refusals-and-warnings
title: The JSON deploy plan carries refusals and warnings as entries
summary: `refusals` and `warnings` are always-present arrays of `{code, message, subject fields, override}` on the JSON plan, and a run refused at the agent-move gate prints a document; the other gates follow

**Context.** #3797. At v0.639.1 a refused plan under `bynk deploy --format json` exited 1, printed no JSON and wrote the refusal as a prose line on stderr, so a client had to match text to tell a refusal from a crash and lost everything else the plan knew. The refusals are spread over about a dozen gates in `deploy()`, and only three carry a `bynk.deploy.*` code.

**Decision.** (A) With `--format json` the run prints one document on stdout, and a run refused at a converted gate (the agent-move gate here) prints one too; the exit status still says whether the deploy could go ahead. A run that stops before the plan is derived prints `environment`, `refusals`, `warnings` and the upload `order`; one that reaches the plan prints the plan with the arrays beside it. Until the other gates are converted, a refusal elsewhere leaves stdout empty (or a plan whose `refusals` is `[]`, for one made after the plan is printed), and the docs tell a client to read stderr then. (B) An entry is `{code, message, …subject, override?}`: a stable code, the readable message, the facts of its subject flat beside them, and the flag that overrides a refusal only where one does. The agent-move refusal carries `reason`, `context`, `agents`, `from`, `to`, and `override` only when naming the context would let it through (a move out of a group that stays, and a group renamed in place, cannot be accepted). (C) The `--accept-fresh-agent` warning is a `warnings` entry (`bynk.deploy.agent_starts_fresh`), and a name that matches no move is the refusal `bynk.deploy.accept_fresh_agent_unused`. A refused run has no warnings, as on stderr. `refusals` and `warnings` are always present, so a client reads one shape. The stderr lines are unchanged. This increment converts the agent-move gate; the other gates and warnings follow in later increments.

**Consequences.** Additive for a JSON consumer, which now sees two arrays (empty on a clean plan), and a client that previously got no document on an agent-move refusal now gets one. `agents` is an array, not the single `agent` of the proposal's example, because a context can host several agents. The short format and the exit statuses are unchanged.
