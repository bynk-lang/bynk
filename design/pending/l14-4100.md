## ADR: ai-generate-stream
title: Ai.generateStream normalises a chat model's events to text deltas in the binding
summary: What counts as text, what is skipped, what faults, and why the iterator is not a generator

**Context.** `runStream` yields a model's events as raw JSON text, and the chat event shape is observed and not documented, so every chat UI decodes events by hand and `generate`'s typed `GenerateRequest` cannot be streamed at all (#4100).

**Decision.** `Ai.generateStream(model, request) -> Effect[Result[Stream[String], AiError]]` is a declared operation of `Ai`, the same request as `generate` (`chatBody`, so the messages and settings are one code path) asked to stream, with each event reduced in the binding to the text it added: `response`, or `choices[0].delta.content`, as `generate` reads both replies. A known event that adds no text is skipped: a `usage` report (alone or with the padding field `p`), a role-only or finishing `choices` delta, and an empty or `null` `response`. Any other event faults the stream with the event's top-level keys, never its values (they may echo what a user wrote), so a shape Cloudflare adds is a visible fault and not silent empty text; an event that is not a JSON object faults the same way. A refusal before the first event is the `Err`, as for `runStream`, and a model that does not stream is `AiFailed`. Token usage is not in the stream (a later `generateStreamWith` could carry it). The mapped stream is a hand-written iterator and not a generator, so `return()` reaches the model's stream at once even while a read waits for the next event, as `sseEvents` does. The operation is experimental like `Ai`. In a test it is stubbed with the deltas (`stub Ai.generateStream(_, _) returns Ok(Stream.of([…]))`); the event normalisation is covered by the binding's tests over a fake stream.

**Consequences.** A chat handler is `Ok(deltas) => Streaming(deltas)`. The set of known non-text events is the binding's and grows by a change to it, never silently.
