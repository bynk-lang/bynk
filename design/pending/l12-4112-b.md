## ADR: container-instance-key
title: A Container instance can type its names with @instances(by: K)
summary: Why the key is an option of the instance that re-types the operations, and what makes a type a valid key

**Context.** `Container.send(instance: String, req)` starts one container per distinct name. The warning for a name taken from request input (`bynk.container.unbounded_instances`) says what is wrong but leaves an author with only an authenticated actor, a constant or a closed set to satisfy it. A type that bounds the names is the most direct way to say which names exist.

**Decision.** (A) `@instances(by: K)` is an option of a `Container` instance, written with the label `by:` and the name of a type: `capability Renderer = Container @build("…") @port(8080) @instances(by: TenantId)`. (B) `K` is a type declared in the context: a refined type with a refinement, or an opaque type, over `String`. A plain alias of `String` adds no check, so it is refused, as is any other type or a name that is not declared (`bynk.capability.invalid_option`), and the option written without `by:`. (C) With it, `send`, `receiveBytes` and `sendBytes` take a `K` in place of the `String` first parameter, in the instance's own operation signatures, so a bare `String` is an ordinary type error at the call and `send`'s signature help and hover show `K`. Without it the operations take a `String`, as before. (D) The key's string form is the instance's name, so the limits on a name still apply to it (1 to 256 bytes, no control character). (E) A keyed instance is not warned about: the key's construction (`.of`, an opaque constructor) is where the author bounds the names. A refined type limits a name's shape and not how many there are, so the docs pair a key with an authenticated actor, a `RateLimit` or a closed set (an enum's names).

**Consequences.** Additive: an instance without the option is unchanged. The option is a type name in an annotation, a new kind of option value beside literals; a constant of that name is not resolved. Hover and completion read the option from the capability option table, so `@instances` is offered on a `Container`, and the instance's operations carry `K` where they carried `String`.
