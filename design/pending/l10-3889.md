## ADR: email-address-constant
title: An email service's address may be the name of a constant, resolved to its literal once
summary: Which constants name an address, where they resolve, and what a constant that is not an address reports

**Context.** An address often appears in more than one place: the service header, a `Forward` in another service, a test's `to`. Each copy was a string literal, so a change had to be made everywhere and a missed copy routed mail wrongly with no error. Constants exist to write a value once (ADR 0678, 0826), and `from email(…)` was a compile-time position they could not reach. Cron's schedule already takes one (#3875); this is its email equivalent (#3889).

**Decision.** (A) `from email(…)` accepts a string literal or a `String` constant, resolved by ADR 0826's rule unchanged: the constant is declared exactly `String` at every step of a chain, and is bound to a literal, in the same file, a sibling file or a used commons. There is no refined address type, so cron's extension to refined constants is not needed; if one is introduced it follows that rule. (B) Resolution happens once, upstream, in the same pass that resolves a cron schedule constant, before the address checks, the project-wide duplicate check, the generated route table, `wrangler.toml`'s `addresses` and the deploy ledger, so every reader sees the literal and the emitter, deploy and runtime are untouched. The service protocol keeps the reference (its span, for go-to-definition, find references and rename) and, when it was refused, why. (C) `fallback { forward: … }` (#3885) takes a constant by the same rule, but that surface is not on main yet, so it is a follow-up and nothing is built ahead of it. (D) A constant that does not resolve is `bynk.email.invalid_address` with a note naming the constant and its declared type, following ADR 0826 D, an unknown name is the ordinary `bynk.resolve.unknown_name`, and a private constant of another unit is `bynk.visibility.private_item`; no new diagnostic code is added.

**Consequences.** A literal and a `String` constant produce identical routing, `wrangler.toml` and dispatch, and two services claiming one address, one through a constant, are `bynk.email.duplicate_address`. Hover on the name shows the constant and its address, completion inside `email(` offers the in-scope `String` constants, and the name is a constant reference to semantic tokens, go-to-definition, find references and rename. The grammar gains an identifier beside the string literal in the `from email(` argument, and the formatter prints the name, not the literal it resolved to.
