## ADR: typed-html-templates-first-cut
title: The first template increment: a template is an embed with a parsed head, used through `fill`, and the tokeniser models the tree-builder effects that change a context
summary: How slice 1 of typed HTML represents and types a template, the diagnostic codes it adds to the track's list, and the tree-builder effects its tokeniser refuses beyond the track's

**Context.** The typed-HTML track (`design/tracks/typed-html.md`, spine #3927) settled the surface and the context model; its decision records (the html-is-not-a-string, html-context-model and template-declaration ADRs) are the rules this increment implements. Slice 1 brings `Html`, the `template` declaration and `fill`, the tokeniser and the contexts C1–C4, C8, C10, C11, C13 and C14. Building it settled a few things the track leaves to the slice, and found tree-builder effects the track's list does not name.

**Decision A — a template is an embed with a template head.** `template` parses to the same declaration node as `embed`, with a head carrying its keyword and fields type. So a template shares, with no second copy, every rule of an embed's path, file, name and size, its reading in the build and in the editor, and its composition through `uses`; a diagnostic names it a `template`. What differs is its value and its emission: a template with fields is a function of its fields record returning `Html`, and one without is an `Html` constant. `template` is contextual, a keyword only at item position before a name.

**Decision B — a template with fields is used as `name.fill(fields)`.** Naming one as a value is `bynk.template.fill_required`. `Template[F]` is not yet a type a program can write: a function that takes a template is a later, additive increment. `h.toString()` is in this increment, not the literals', because a test must read what a template rendered.

**Decision C — five codes beyond the track's list.** `bynk.html.no_constructor` (`Html.of` outside `bynk.html`: an opaque type's `of` is open to every unit, and `Html` has no predicate, so it would turn any string into markup with no check and no audit; markup comes only from a template here, and from `html"…"` and the audited `Html.unsafe` with the literals), `bynk.template.fields_not_record` (the fields type is not a non-generic record), `bynk.template.needs_bynk_html` (the unit does not `uses bynk.html`), `bynk.template.placeholder_without_fields` (a placeholder in a template with no fields) and `bynk.template.fill_required`. `bynk.template.conflicting_contexts` is registered with `Href`, because every pair of contexts in this increment accepts every scalar, so no field can meet two contexts with nothing in common. A template that ends inside a tag or inside an element whose text is not markup is `bynk.template.unsupported_markup`; the literals' `fragment_unclosed_state` is for an `html"…"` literal. A secret field is refused both as a record field (`bynk.types.secret_at_boundary`) and at its placeholder (`bynk.template.secret_placeholder`), so that code has no example that raises it alone.

**Decision D — the tree-builder effects the tokeniser refuses.** Beyond the track's list, a differential against `html5ever` with scripting on showed these change a context, so each is refused rather than modelled: a `<select>`, whose insertion mode ignores the tags that would switch the tokeniser, holds only `<option>`, `<optgroup>` and `<hr>`, must close in the same template, and takes no `Html` value (a scalar only); MathML's text integration points (`<mi>`, `<mo>`, `<mn>`, `<ms>`, `<mtext>`) are refused with SVG's; an attribute whose literal value decides how its element is read (`<script type>`, `<script language>`, `<meta http-equiv>`, `<meta charset>`, `<link rel>`, `<iframe sandbox>`, a `<template>`'s `shadowroot*` attributes, which decide whether its content becomes a live shadow root) takes no placeholder (C11); a placeholder may not continue a character reference, or follow `<` or `</` in RCDATA where it could complete an end tag; `<frameset>` and `<frame>` are refused; a doctype must be a plain name. A URL or code-loading attribute, `srcset`, `imagesrcset` and any attribute of `<base>` take no placeholder until `Href` (`bynk.template.unsupported_markup`). Two other tree-builder effects are not escapes, and the differential accepts them: an ignored start tag (`<tr>` outside a table, a second `<form>`) drops its attributes, value and all, and reopening a formatting element (`<b class="…">` after a `<p>` closed it) clones it, so a value appears twice, each time in its own context.

A template's text is normalised as a browser's input-stream preprocessing does it (CRLF and a lone CR become LF) before it is tokenised or emitted, with each diagnostic still at its offset in the file as written; a CR is not whitespace to the tokeniser, so one that reached it unnormalised would let `<script\r>` read as text, and the tokeniser refuses one rather than read it.

**Decision E — the tests that hold the tokeniser.** The `html5lib-tests` tokeniser corpus is vendored (MIT) and run from every initial state the tokeniser implements; an input with a `&` is skipped, because the tokeniser never decodes a character reference, which never changes the state. The `proptest` differential and the `cargo-fuzz` target share one oracle, `bynk-check/tests/support/html_oracle.rs`.

**Consequences.** A template's diagnostics are reported at its file's line and column, in the terminal and the editor, which reads the template's unsaved buffer. `bynk.html` now declares `Html`, so the emitted `bynk/html.js` module of a project that uses it carries `Html`'s constructor beside `escapeText` and `escapeAttr`; their behaviour is unchanged. The language server's hover, completion and navigation inside a template file are the tooling slice's.
