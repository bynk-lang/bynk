## ADR: instance-option-constants
title: A derived capability instance's options take constants
summary: ADR 0826's constant resolution extended to instance options, resolved before each option's validator, with the option's own error when it does not resolve

**Context.** ADR 0826 lets a constant stand for its literal in a set of annotation arguments, but not in a derived capability instance's options (`Service @worker`, `Queue @name`, `Email @to`, `StoredSecret @store`, `RateLimit @limit` and `@period`, `R2 @jurisdiction`, `MySql @tls`). The same Worker name, queue name or address was therefore repeated as a literal, could not be shared with the code that uses it, and could not take a per-environment value through an `env(…)` constant (#3942).

**Decision.** A. Every instance option takes a constant by ADR 0826's rule: declared exactly the option's base type (`String`, `Int`, `Duration`), bound to a literal or to another such constant. The option's kind comes from the base kind's own option table, so a new option is covered when it is declared. A list option (`@allowedRecipients`, `@allowedSenders`) takes constants for its string elements; a whole-list constant is not part of this change. The pass resolves before the option's validator, so every existing rule (Worker and queue names, the `@period` set, address syntax) applies to the resolved text unchanged, and the emitters read literals. B. A reference that does not resolve keeps the option's own error (`bynk.capability.invalid_option`), with a note on what a constant must be to stand there. C. `reference/capabilities.md` lists `D1` among the bases with instances, which the paragraph after it already documents.

**Consequences.** The same binding comes out of a constant as out of its literal, so an instance option can take a per-environment value through an `env(…)` constant. No new diagnostic code. The editor treats the reference as a use of the constant (go to definition, find references, rename); hover on a list element and a dedicated completion of in-scope constants are not part of this change.
