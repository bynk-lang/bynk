## ADR: find-regex-named
title: `findRegexNamed` returns a regex's named groups as a Map keyed by name
summary: a new `String` kernel method reads the group names from the literal pattern at compile time; a pattern with none is an error

**Context.** `findRegex` and `findAllRegex` return groups by position, although a pattern may name them and `replaceRegex` already reads `$<name>`. Reading `v[2]` for "minor" breaks silently when the pattern gains a group. A regex in Bynk is always a literal checked at compile time, so its group names are known to the compiler.

**Decision.** [DECISION A] `s.findRegexNamed(pattern) -> Option[Map[String, Option[String]]]`: each named group is a key, its value `None` when the group did not take part; the whole match and unnamed groups are not included. The names are read from the literal pattern by one function (`bynk_check::regex_groups::group_names`, which skips lookbehinds, escaped parentheses and character classes and lists each name once), used by both the checker and the emitter. A pattern with no named group is `bynk.types.regex_no_named_groups`, pointing at `findRegex`. A name used by two groups, even across alternatives, is `bynk.types.regex_duplicate_group_name`: the target runtimes refuse it when the `RegExp` is built (duplicate names are ES2025 and not yet in Node 22), so accepting it would only move the failure to run time. The method is lowered to `exec` and one entry per name, so no runtime helper is needed. [DECISION B] No `findAllRegexNamed` yet. [DECISION C, dropped] The warning for a literal key that is not one of the pattern's group names (`bynk.types.regex_unknown_group`) is not implemented: the issue allows dropping it if the map's origin is hard to track, and it is. A `Map` is an ordinary value, so by the time `v.get("mjaor")` is checked it has been bound, passed, stored or rebuilt, and following it back to the `findRegexNamed` that made it would need a flow analysis the checker does not otherwise have; a wrong key reads `None`, as any absent key does.

**Consequences.** One new diagnostic, explained and fixtured. Hover shows the method's signature and completion offers the method on a `String`; the issue's tooling deltas of listing the pattern's group names on hover, and as string keys after `.get(` on the result, are not done, since both depend on the same origin tracking that Decision C needed. Semantic tokens and signature help are unchanged.
