## ADR: signed-cookie-revoke-all
title: `revokeAll` and `by Revoked` complete revocable cookie sessions
summary: `Actor.revokeAll(identity)` ends every session of an identity, and `by Revoked` tests that the seam refuses a revoked cookie

**Context.** Part A of #3938 made a `SignedCookie` session a record in a generated agent, checked by the seam on every request, and let `expire()` end the current one. Logging out everywhere and ending every session after a password change or compromise still had no language surface, and a test had no way to present a cookie for a revoked session. The cookie arm of an actor sum (#3936) checked the session but could not end it.

**Decision.** A: `Actor.revokeAll(identity)` exists only with `sessions = true` (otherwise `bynk.types.method_not_found`); it takes the actor's identity type, is an `Effect[()]` and, like `issue`, runs only in a service handler. It calls the generated agent's `revokeAll`, which drops every live session of that identity and no other's. B: `by Revoked` is a reserved bad-credential principal that issues a cookie for a registered session, revokes the identity's sessions in the agent, and sends the cookie; the seam must answer `Rejected(Unauthorized)`. It is `system`-tier only and legal on a single `SignedCookie` actor with `sessions = true`; anywhere else is `bynk.test.revoked_needs_sessions_route`. C: the cookie arm of an actor sum threads the verified session into the handler's deps, so `expire()` ends the session from a sum handler as it does from a single-actor one. A sum route cannot be driven `by Revoked` (the sum principals `Forged`, `Expired` and `Stale` only reach the first matching member, #4385); revoke through a handler and assert with a following request.

**Consequences.** Revocation security notes: `revokeAll` takes effect on the next request, not on the response that ends it, and a request already past the seam finishes; revoking an identity with no live sessions is a no-op; an agent that cannot answer faults the request, so a failure to revoke never admits a session. The generated agent's stored shape is unchanged from part A, so no migration is needed. A generated `revokeAll` empties the identity's session map rather than deleting the agent's state, so an identity that has ever had a session keeps one small record.
