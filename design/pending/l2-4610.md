changelog: The generated TypeScript clients (HTTP and WebSocket) refuse to send a credential over cleartext, so a bearer or OIDC token no longer crosses the network readable to a remote host; a call that carries an `Authorization` header to an `http:` URL, or a WebSocket `connect` that offers a token to a `ws:` URL, whose host is not loopback throws before anything is sent
breaking: A generated TypeScript client that sends an `Authorization` header (a bearer or OIDC token) to a remote `http://` base URL, or whose WebSocket `connect` offers a token to a remote `ws://` one, now throws a `CleartextCredential` error before sending, where it used to send the token in the clear. Use an `https://` (or `wss://`) base URL. `http://` to `localhost`, a `*.localhost` name, `127.0.0.0/8` or `[::1]` (what `bynk dev` and the test tiers use) still works, and so do anonymous calls, cookie credentials (a server-side call that forwards a `Cookie` is not checked) and a `viaBinding` Service Binding, which never reaches the network. The check is on the parsed URL's hostname, so `http://localhost.evil.com` is remote. A relative `baseUrl` is checked against `location.origin`.
