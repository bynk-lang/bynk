## ADR: ai-generate-value
title: Ai.generateValue[T] is lowered over a private JSON-mode call, and its schema is derived in bynk-check
summary: Where the schema comes from, what the call lowers to, how a test stubs it, and what a failure says

**Context.** Asking a model for structured data meant describing the shape in prose, calling `Ai.generate` and decoding `Generation.text` by hand, then handling a reply wrapped in prose or a code fence (#4099). The type is the schema, and only the compiler knows both the type and the call.

**Decision.** `Ai.generateValue[T](model, request)` returns `Effect[Result[T, AiError]]` and is not a declared operation of `Ai`, as `AnalyticsSql.select[T]` is not one of `AnalyticsSql`: the checker records `Callee::AiGenerateValue { value, schema }` and the emitter lowers it over `generateJson(model, request, schema)`, a method of the binding alone (not in the capability, not in the reference, not offered by completion), which sends the platform's `response_format` JSON-schema mode and returns the reply's JSON text. The call site decodes that text as `T` with the ordinary decoder, so refinements are checked. `T`'s schema is derived in `bynk-check` (`ai_schema`) from the declaration, in the plain-JSON shape of #3974 (an enum is a string, an `Option` is the value or `null`, a `String`-keyed `Map` is an object, an `Instant` is RFC 3339 text, a sum with payloads an object with `kind`), and is compact JSON in a fixed key order so every build writes the same text. A model's JSON mode answers with an object, so a `T` that is not a record is asked for as the one field of one (`{"value": …}`) and the call unwraps it; a bare answer outside the object is still read, as the decoder reads one. A type with no schema (one that contains itself, a generic type, a `Map` with a key that is not a `String`), or one whose schema with every named type written out in place is over 32 KiB, is `bynk.types.ai_value_shape`, naming the field. A reply that is not JSON or does not decode is `Err(BadReply(message))` where the message is the kind of failure and the path (`the reply is not a Triage (StructuralMismatch at $.severity)`), never the model's text or the offending value; a platform refusal of `response_format` is the `Err` as the binding gives it (`InvalidInput` with the platform's message), with no fallback to prose. A test stubs `Ai.generate`: the test double's `generateJson` reads the `text` of the stubbed `generate`, so a case runs the production decode over a chosen reply. The operation is experimental like `Ai`, which an `[unstable] allow` entry for `bynk.cloudflare.Ai` covers.

**Consequences.** The schema is a second derivation of the wire shape beside the OpenAPI renderer's. A test (`bynk/tests/ai_schema_drift.rs`) compiles a table of types (records, enums, sums, lists, `Option`, maps, `Instant`, refined bases) both ways and fails on any difference but the deliberate ones named in it; it already caught one (an `Option` field is required and nullable, as the publisher has it). Follow-up: one derivation shared by both. An `Option` field the model leaves out still decodes as `None`.
