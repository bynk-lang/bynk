## ADR: container-deploy
title: A container deploys through wrangler, with Docker checked first and an image adoptable per environment
summary: Decisions C and G of #3477 for slice C2: no ledger id and no REST calls, a Docker preflight, digest-pinned image adoption, a 4.136.0 floor for container Workers only, and a rollback note

**Context.** The container application is created and updated by `wrangler deploy` from the `[[containers]]` stanza, which builds a Dockerfile image with Docker and pushes it to Cloudflare's registry. `wrangler deploy --dry-run` builds too, so it needs Docker and would break `bynk deploy --dry-run`'s offline guarantee. Under the `durable_object` policy only Cloudflare's registry is supported, by digest. The `image` map is uploaded with the Worker version, and a running instance keeps the image it started with. Wrangler 4.120.1 refuses the policy value.

**Decision.** C: nothing is created over the Containers API, and the ledger records only an adopted image reference (`container_images`), so a changed or dropped adoption shows in the plan. The build writes `bynk-containers.json` beside the Worker's configuration (capability, class, `@build`, `@instance_type`) because `[[containers]]` does not carry them. G: `bynk deploy` runs a Docker check after `--dry-run` returns and before it authenticates or asks for confirmation, only when some container has an image to build in this environment, and refuses with the container, the missing tool and the two ways out; `bynk deploy --dry-run` shows the plan and builds nothing; `bynk doctor` gains a `docker` row that warns only for a project that declares a container. `[deploy.containers.<Capability>] image = { <env> = "registry.cloudflare.com/<ACCOUNT_ID>/<REPOSITORY>@sha256:<DIGEST>" }` adopts an image per environment: the generated `[containers.images.<Cap>]` entry is rewritten to `image` (its `dockerfile` and `build_context` removed) in the environment's own block before the push; an entry that names no container is refused. A container Worker needs `WRANGLER_CONTAINERS_MIN` (4.136.0), refused before authenticating with the version named; `WRANGLER_MIN` is unchanged. The `[env.<name>]` block copies `[[containers]]`, as it copies `exports`. The plan line is `container <Class> (image: build from <dir> | adopted <ref>; instance <type>; reconciled by Cloudflare)`, with no price. `bynk revert` warns, for each container class in the target, that a rollback restores the image for new starts only.

**Consequences.** Experimental, like the kind. Nothing here has been run against a real account: the rollback rule is read from Cloudflare's documentation and is marked unverified, and building from a Dockerfile, the readiness wait and inactivity need a Workers Paid account and Docker (the PR carries a checklist). A renamed capability is a new class and the deploy fails loudly, as for an agent; there are no tombstones. `bynk dev` and the real-container smoke are C3.
