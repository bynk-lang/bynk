## ADR: container-unbounded-instances
title: A Container instance name from request input on an unauthenticated route warns
summary: Why the check follows handler inputs into the instance argument, what bounds a name, and what it does not follow

**Context.** `Container.send(instance, req)` starts, or reuses, one container per distinct name, and a running container costs money with no per-application ceiling. The reference example named the instance from a path parameter on a `by Visitor` route, so any anonymous caller could start as many containers as they had values to send, and it taught the pattern.

**Decision.** (A) `bynk.container.unbounded_instances` is a warning, raised when the first argument of `send`, `receiveBytes` or `sendBytes` on a `Container` instance depends on a handler's own input (a path, query or body parameter, or a header or cookie one) and the HTTP route's `by` clause has a member that does not authenticate (`Visitor`, or a declared actor with no scheme). It names the call, the input it came from and the route. (B) Dependence follows the handler's parameters and the locals bound from them with a pure `let`, through interpolation and method calls. It takes the value of a `match` or an `if` from its branches, not from what it tests, so mapping an input onto a closed set (an enum's names) is how a set is bounded and does not warn. It does not follow a call to a function, which is where an author bounds a set, nor an effect's result, nor a binding made inside a nested block: each can miss a name and none reports one wrongly. A name from a constant or the authenticated identity is not an input. (C) A refined or opaque type limits a name's shape, not how many there are, so the docs pair a keyed instance with an authenticated actor, a `RateLimit` or a closed set. (D) The reference example and the guide name the instance from the authenticated identity.

**Consequences.** A warning, so no program stops compiling; two existing fixtures that used the old pattern now carry the warning in their `expected_warnings.txt`. A typed instance key that bounds the names, which would let a name from it satisfy the check, is a follow-up (#4112 stays open for it); the explain text says so without promising a syntax.
