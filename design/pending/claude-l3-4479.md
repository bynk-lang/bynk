## ADR: workerd-tests-wait-for-readiness-not-for-time
title: The workerd and browser system tests wait for a readiness signal and name each wait
summary: Ports outside the ephemeral range, a `Ready on` gate, windows and log lines awaited, no retries

**Context.** #4479: a handful of workerd and browser system tests failed once in a while under a full-suite run and passed alone. Sixteen threads on four cores reproduced them, in a different set each run, and each failure had its own cause, which the log showed: (1) `Address already in use`, and a request answered by *another* test's Worker, because a port returned by `free_ports` came from the OS's ephemeral range, which every outgoing connection of the suite's polling and every `bind(":0")` of wrangler's own workerds is also drawn from, and a `wrangler dev` takes seconds to bind its port on a loaded machine; (2) the boot wait took any HTTP reply for the Worker, including wrangler's own `403 Forbidden` from its start-up; (3) the streamed-download smoke gave a request's head 300 ms; (4) the queue smoke read the wrangler log the instant its last request was answered, before wrangler had flushed the Worker's console; (5) the rate-limit smoke's counts straddled the end of a wall-clock-aligned miniflare window; (6) the browser driver gave each of its streams a bare 10 s, and cut the faulted `/bad` stream straight after flushing the event before it, so the browser could report the cut as an error before it delivered that event (found by the soak, once in eight runs).

**Decision.** (A) `free_ports` takes its ports from a band below the ephemeral range that the per-test fixed bands do not use, claims each across processes by a file named for its owner's pid (nextest runs a test per process; a claim whose owner has gone is ignored), keeps the process-wide set, and warns if it ever has to fall back to the OS because the band is full. (B) `wrangler::wait_until_ready` is the one boot wait: the log has `Ready on http://localhost:<this test's port>` and the boot request answers (with the status its boot route gives, which is not always 200), within a named `BOOT_DEADLINE`, and its error says which of the two expired. The harnesses that took any reply for the Worker (the binding smokes, the streamed-body smoke, `events_boundary_workerd`, `collection_rename_workerd`, `field_rename_workerd`, `idempotency_workerd`, `container_workerd`) use it; the soak found `events_boundary_workerd` accepting wrangler's start-up `404` for its Worker. (C) The waits that are the platform's own are named and generous (`QUEUE_DELIVERY_DEADLINE`, `LOG_DEADLINE`, the driver's `WAIT_MS`), and a timeout's message names the wait. (D) A test whose assertion is about a log line waits for the line (`read_log_awaiting`), and the rate-limit smoke waits until the wall clock leaves room in the current windows (`wait_for_window_room`), rather than hoping the steps are quick. (E) The streamed download's head timeout is 3 s and its parts are spaced so the body is twice that, which is the property the smoke pins: a body that outlasts the head timeout is not cut by it. (F) The browser smoke's server cuts the faulted stream only after the page has acknowledged the event before it (`/ack`), which is the property the smoke pins: that event arrives, the faulted one never does. Not done, on purpose: a retry of any test, a skip, a quarantine, or a weaker assertion. Every assertion is the one it was.

**Consequences.** Every workerd and browser test (146) run 16 at a time on four cores: before, 3 of 8 runs failed (`workers_runtime_smoke` twice and `events_ordering_workerd` once, all on `Address already in use` or a request answered by another test's Worker), and an earlier run failed `binding_workerd`'s `d1` and `fetch_bytes` smokes; after, 8 of 8 passed (more runs in the pull request). The tests that still take a fixed band from their process id (`http_client`, `typescript_client_workerd` and others) are not touched; they are disjoint from the new band.
