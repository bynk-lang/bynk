## ADR: stored-layout-marker-and-forward-compat-guard
title: A stored record's `__layout` marker, and a build that faults on one it does not know
summary: `__layout` is reserved beside `__v`; absent is the wholesale layout; any marker a build does not know faults NewerLayout before decode or write-back

**Context.** An agent's state is one record under the Durable Object key `"state"`, read by `loadState` and rewritten whole by `commitState` (ADR 0109, ADR 0110 D3). The per-entry storage track (`design/tracks/per-entry-storage.md`, proposal #3189, originating issue #3159) will move collection entries and index postings to their own keys, leaving the `Cell` record in `"state"`. ADR 0538 freezes the stored-state encoding and the place and meaning of the `__v` marker at 1.0, so the layout needs a marker of its own, and it has to exist in a released build before any build writes the new layout. A build that predates the layout, reading a record whose collection fields are no longer inline, would zero-merge them (ADR 0124 D4) and write the whole record back, silently orphaning every per-entry key. The `NewerSchema` guard (ADR 0538) does not cover this: it fires only on a `__v` bump, and only for builds with a schema lock.

**Decision.** `__layout` is a reserved key in the `"state"` record, beside `__v`. A Bynk identifier cannot start with `_`, so ADR 0538 D3's collision argument holds. An absent `__layout` means the wholesale layout every build so far writes and reads. This increment defines no other value, so a build from this increment on treats any `__layout` it finds as written by a later build: `loadState` (and the test harness's own load) calls the runtime's `checkStoredLayout` first, before the `__v` check and before any merge or decode, and throws a `RehydrationViolation` whose detail is `NewerLayout`, carrying the marker when it is a positive integer and null otherwise. Nothing is decoded and nothing is written back. The check is unconditional: unlike `__v`, it does not depend on the project having a schema lock. A later increment that teaches a build a layout widens the set of markers the check accepts; it does not remove the check. No build in this increment writes `__layout`.

**Consequences.** Shipping this release before any writer change is what makes the later layout change safe to roll back across the flip as far as data loss goes: a rolled-back build faults loudly instead of orphaning keys. Downgrade across the flip is still unsupported and the changelog will say so when the writer lands. A record that carries a `__layout` marker from a build that is not part of this repository now faults where it would previously have loaded; no released build writes one, so no stored record is affected today. The marker joins `__v` in the frozen stored-state layout; the writer slice's ADR amends ADR 0538 to say so in full. Hover, completion, semantic tokens and signature help are unchanged, because no syntax, name or signature changes.
