## ADR: commons-names-prelude-types
title: A commons names the bynk adapter's transparent types without consumes
summary: a commons that writes a type `bynk` exports `transparent` reaches it through a type-only clause the compiler adds, so a shared constant can be a `CronSchedule`; capabilities and opaque types stay unnameable

**Context.** `consumes` is not allowed in a commons, so a commons could not name any type of the `bynk` adapter: `fn f(u: Uuid)` was `bynk.resolve.unknown_type`, and the headline example of #3875, `const Nightly: CronSchedule = "0 2 * * *"` in a commons shared by two contexts, did not compile. A schedule shared across contexts had to be a `String` constant, losing the check the type gives it.

**Decision.** [DECISION A, option 1, as accepted on #4181] A commons may name the prelude's **transparent** types without `consumes`. No syntax is added. A pass over the project's own commons (`implicit_uses::add_implicit_consumes`) finds each type the `bynk` adapter exports `transparent` that the file names as an identifier (comments, docs and strings do not count), and adds the clause `consumes bynk { <those types> }` to the parsed unit, as `add_implicit_uses` already adds `uses` for a prelude type. The clause is type-only, so the unit gains no capability and stays pure. The names come from the adapter's own `exports transparent` list, so a type added there is reached with no second edit. [DECISION B] Capabilities stay unnameable, and so does anything `bynk` exports `opaque` (it has none today): they are not `transparent` exports, so they are not reached, and naming one is still `bynk.resolve.unknown_type`. That error now also says a capability is not a type and where a capability is used. A name the commons declares (a type, or a variant of one of its sums), or that a commons it `uses` declares, is the unit's own and is not reached, as with a prelude type. The reach is limited to the `bynk` adapter, the portable surface: another first-party adapter's types (`bynk.cloudflare`, `bynk.crypto`) would tie a pure commons to a platform.

To carry the clause, `Commons` gains a `consumes` list that source cannot yet write and that the commons check and emit paths already handled for a context. The checker builds the cross-unit view for a commons as it does for a context, so the emitted module imports the adapter's namespace beside the names it uses. A context that `uses` the commons gets the constant and functions without consuming `bynk` itself.

**Consequences.** `const Nightly: CronSchedule` in a commons compiles, and `on schedule(Nightly)` in a context that `uses` it resolves. A commons that happened to mention a `bynk` type name as an identifier now reaches the adapter, which is injected into the project's output if nothing else reached it; a commons that declares the name itself is unchanged. An explicit `consumes` with a braced, type-only list in a commons is #4044, which builds on the `consumes` list added here. Hover resolves a prelude type in a commons to the adapter's declaration; completion already offers the embedded units' types; semantic tokens and signature help are unchanged.
