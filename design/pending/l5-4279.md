## ADR: queue-undecodable-unreachable
title: An `Undecodable` pattern warns where the verdict cannot be it
summary: A checker warning on `Undecodable` patterns of a `QueueResult` outside a `system` case, so a dead arm does not look meaningful

**Context.** #3878 added `Undecodable` to the verdicts of a `QueueResult` match. A body fails to decode only when a real queue delivers it, so only a `system` case's queue address can yield it. A `unit` or `integration` case calls the consumer with a typed value, and handler or helper code only builds `Ack`, `Retry` or `RetryAfter`. The arm was accepted silently everywhere, leaving a dead arm that reads as if it handled something.

**Decision.** The checker warns with `bynk.queue.undecodable_unreachable` on an `Undecodable` pattern, in `match` or after `is`, whose scrutinee has type `QueueResult`. A test body reports it unconditionally because the checker does not know the case's tier; the suite checks drop it for a case whose effective tier is `system`, where it can match. The rule is by tier, not by tracing the scrutinee's provenance: a `QueueResult` in a `system` case is either a queue address's verdict or a value the case passed around, and neither is reported. It is a warning, not an error, since the arm does no harm. A `match` still has to be exhaustive (#3878), so the fix at a lower tier is a `_` arm.

**Consequences.** An existing `unit` or `integration` case, or a helper, that names `Undecodable` gains a warning; one fixture's arm became `_`. The re-typing the emitter does for a case body ignores this one warning, as the check pass already drops it at `system`. Hover, completion, semantic tokens and signature help are unchanged, since no name or token kind is new.
