## ADR: crypto-key-derivation-and-password-hashing
title: bynk.crypto derives keys with HKDF and hashes passwords with a self-describing PBKDF2
summary: Why password hashing takes no parameters, carries its own count and salt, and is the only one offered

**Context.** `bynk.crypto` had digests, MACs and signatures but no key derivation and no password hashing. Without HKDF an author reuses one secret for HMAC, for encryption and for each tenant's key. Without a slow, salted hash a service that stores passwords has nowhere correct to turn, and the by-hand versions fail in familiar ways: no salt, a low or fixed count, a comparison that stops at the first difference. The unit runs no third-party crypto, and the only password function Web Crypto offers on every platform is PBKDF2.

**Decision.** (A) `deriveKey(secret, salt, info, length)` is HKDF-SHA-256 (RFC 5869), `length` 1 to 8160 bytes, a non-empty `secret`; a bound outside that is a fault, as an empty HMAC key is. (B) `hashPassword(password)` draws a random 16-byte salt and returns `pbkdf2-sha256$<iterations>$<salt>$<hash>` (unpadded base64, a 32-byte hash). `verifyPassword(password, stored)` reads the parameters from `stored`, recomputes and compares in constant time; a `stored` that is not in the format, or that claims a count over ten million or a salt or hash outside 8 to 64 and 16 to 64 bytes, is `false`, not a fault, and cannot be made to spin. (C) The count (600,000, OWASP's guidance for this algorithm) is Bynk's, not the caller's, and is stored with each hash, so a later release can raise it and old hashes still verify; `needsRehash(stored)` is `true` for a lower count, a smaller salt or hash, or a string not in the format. (D) The password is normalised to NFC before hashing. (E) There is no cheaper option: the docs state the CPU cost, which counts against a Worker's CPU limit, and recommend an identity provider where it does not fit.

**Consequences.** The three operations are additions to `Crypto`, so no existing program changes. A future algorithm (Argon2, if Web Crypto gains it) is a new scheme name in the same format. `Secret` is not yet accepted as the password or the input secret: a `Secret` form of each, as `importSigningKeyFromSecret` is for keys, is follow-up work.
