## ADR: bynk-token-mints-bearer-credentials
title: `bynk token` mints a Bearer actor's credential in the driver
summary: A top-level `bynk token <Actor>`, signed in Rust from the environment secret, Bearer only

**Context.** Calling a `Bearer`-guarded route by hand — `curl` under `bynk dev`, or a smoke test against a deployment — needs a token signed the way the actor declares. Every project wrote its own script (`github-hooks`' `token.sh` needed three review fixes: keep the secret out of `openssl`'s arguments, validate the lifetime, add a way to backdate). The actor already declares everything a minter needs, and the test runtime already signs these tokens for `system` cases (ADR 0207 D3).

**Decision.** (A) The command is `bynk token <Actor>`, distinct from `bynk org token mint` (a registry publish token) by position, and its help says so. With no actor it lists the project's Bearer actors and the secret each reads. (B) The secret is read from the environment under the name the actor declares, never from an argument, and is never printed; an unset or empty variable is an error naming it. (C) `--sub` is validated against the actor's identity type, refinements included, using the checker's own predicate evaluation (`bynk_check::checker::string_refinement_violation`), so the token is one the seam accepts. (D) `--lifetime` (default 1 hour, at most 365 days), `--expired` (`exp` an hour in the past) and `--not-before <duration>` (`nbf` in the future; the lifetime counts from it) exist to smoke-test a deployment's refusals, pairing with `by Expired` at `system`. (E) Bearer only: a `Signature` actor signs a request body, so it has no standalone credential, and an `Oidc` actor's tokens come from the provider's private key. Both are refused with that reason, as is a refinement actor, whose seam checks claims `bynk token` does not set. The driver signs in Rust (HMAC-SHA256 via `ring`, already a dependency of `bynk` for registry signatures; a ten-line unpadded base64url encoder) rather than shelling to Node. The token's header and claim order match `test_runtime/jwt_signer.ts`.

**Consequences.** A project no longer carries a hand-rolled, security-sensitive minting script, and a token cannot disagree with its actor. Drift between the Rust signer and the verifier is held by tests: one mints with the real binary and verifies under the emitted `auth.ts` verifier run by `node`, another compares the signer byte-for-byte with `jwt_signer.ts` over a shared vector. No compiler or language change, so the tooling delta (hover, completion, semantic tokens, signature help) is unchanged: this is a CLI command with no language surface. `jwt_signer.ts` signs a non-ASCII `sub` as Latin-1 (`btoa` of a JS string), which the UTF-8 verifier would reject; the Rust signer encodes UTF-8 and the shared vector is ASCII. A later `bynk sign <Actor> <file>` could cover `Signature` actors.
