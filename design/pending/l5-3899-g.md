## ADR: queue-bynk-producers
title: A Bynk producer signs its queue messages under the edge key to the consumer's context, and a Producer refinement admits the contexts it names
summary: A `Queue` instance whose queue has a signed consumer admitting its context signs each send with the call edge's key; the consumer verifies under the sending context's key and a `Producer` refinement's `IsContext(…)` predicate decides which contexts it admits

**Context.** Part of #3899. The consumer half (signed envelopes, replay claims, `Foreign` senders) admitted only producers that are not Bynk, because a Bynk producer did not sign. A Bynk context should be admitted by what it is, as a `call` handler admits one, and its author should write nothing to be admitted.

**Decision.** The pairing is a project fact: `signed_consumer_of(queue, sender, tables)` finds the context whose consumer of the queue names a `Producer` refinement that admits `sender`. The compiler hands the `WorkersQueue` construction the sender, the consumer's context and the queue's name only when such a consumer exists, so an unpaired producer is unchanged. The key is the call edge's (`BYNK_CALL_TO_<consumer>` on the producer, `BYNK_CALL_FROM_<producer>` on the consumer): one key per ordered pair of contexts, set by `bynk deploy` (a producer to a signed consumer is now an edge, though no Service Binding joins them, so it never orders the deploy) and passed locally by `bynk dev`. The signing input starts with a different line from a call's, so the key never lets a signed call be replayed as a queue message or the reverse. The consumer's entry takes the refinement's predicate as a function over the verified `from`, reads the edge key for that context, and reports whether the sender was a context; a sum of `Foreign` actors and refinements resolves to the first member that admits the sender, with a context's name as the refinement member's identity. A refinement beside the unsigned `Producer`, or a lone refinement with a binder, stays `bynk.actor.queue_actor_not_enforced`. A dead-letter consumer lists a refinement by its actor's name, so it must name the same refinements as its source.

**Consequences.** `by Producer` consumers, `Foreign` consumers and producers with no signed consumer are unchanged. The std `bynk.cloudflare` binding gains optional constructor arguments and imports the runtime's signing, so its goldens move. A producer in a context the refinement does not admit sends messages the consumer refuses and reports; a compile-time check that every context a refinement names produces to the queue is a later improvement.
