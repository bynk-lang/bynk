---
level: patch
changelog: A `400 RefinementViolation` body no longer echoes the rejected value; `violation` carries `field` and `message` only
breaking: A `400 RefinementViolation` body no longer carries `violation.value`; a client that read it must stop
---

Every JSON `400` a generated handler answers (a path, query, header, cookie or body parameter, a consumed codec, a call or event envelope) is built from the boundary error a codec returned, and a `RefinementViolation` carried the runtime `ValidationError`, `{ field, message, value }`, so a rejected password failing `MinLength` was written back to the caller. One runtime helper, `wireRefusal`, now builds the wire `violation` from `field` and `message`, and `json_response` applies it to every `400`; the parameter-validation path of the Workers entry applies it too. The value stays on the runtime error (it is what `.of` returns) and is not logged: a thrown boundary error holds it non-enumerably and the rehydration log line names the agent, path and kind only. The wire-format reference and the OpenAPI `violation` schema say so, and #659's reflected-input test now asserts the input is not reflected.
