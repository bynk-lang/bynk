## ADR: commons-consumes-types
title: A commons may consume the types an adapter exports, in braces
summary: `consumes U { T, … }` is allowed in a commons for an adapter's exported types; every other form is `bynk.commons.consumes_not_types`

**Context.** A commons is the unit for shared, pure code, and types are pure, but `consumes` began as a context-to-context dependency, so a commons could name no type of a first-party adapter: a helper that maps a `SqlError` to a domain error, formats a `TimedOut` or reads a `KvEntry` was repeated in every context. #4181 let a commons reach the `bynk` adapter's transparent types without writing a clause, by adding the type-only clause itself; this adds the clause to the language, for any adapter.

**Decision.** [DECISION A, decided] A commons may write `consumes U { T, … }` and nothing else. A whole-unit `consumes U`, an aliased `consumes U as A` and a capability name are refused, each with `bynk.commons.consumes_not_types` saying what a commons may list. [DECISION B] The unit is an adapter: a first-party one (`bynk`, `bynk.cloudflare`, `bynk.crypto`, …) or an adapter of the project. A context is refused with the same code, since a context's exported types belong to its boundary and a commons that named one would couple shared code to one deployable. A name `U` does not export as a type is refused with the same code. [DECISION C] `T as Alias` is allowed, as in a context's braced `consumes`. [DECISION D] A unit that `uses` the commons does not get the consumed types in scope through it (the commons' table holds only its own declarations); a public signature that mentions one is fine. The dependency graph records the commons' `consumes` edges, and the `consumes` cycle check now walks `uses` edges as well, so a commons that consumes an adapter which `uses` it is `bynk.context.consumes_cycle`, reported on the `consumes` clause; a cycle of `uses` edges alone is still the `uses` check's. [DECISION E] Capabilities stay out: this does not add them, so the same braced list can later name a capability's contract.

Departures and details: the clause parses in any form, so the refusals carry a diagnostic of their own rather than a parse error. Writing `consumes bynk { … }` in a commons turns #4181's implicit reach off for `bynk`: the file lists every `bynk` type it names, and one it leaves out is `bynk.consumes.type_not_selected`, whose existing fix adds it. The implicit reach never extends to other adapters, so naming `SqlError` needs the clause. A commons' imports are per file, as in a context. The formatter prints the lines after the commons' `uses`, the tree-sitter grammar accepts them, and the parse error that lists a commons' items now includes `consumes`. In the editor, completion inside a commons' `consumes U { }` offers the types `U` exports, not its capabilities.

**Consequences.** A shared library can hold helpers over `TimedOut`, `SqlError` and `KvEntry`. A commons with a `consumes` is emitted with a named import of the types it writes and the adapter's namespace where the emitted code qualifies one. A program that parsed before is unchanged.
