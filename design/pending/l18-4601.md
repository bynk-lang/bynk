changelog: `bynk deploy --prune` reads each orphaned queue's consumers before it asks. A queue only the project's own Workers consume is deleted after they are detached, and the confirmation names them ("detaching `shop-jobs`"), where before Cloudflare refused the delete with `11005`. A queue a foreign Worker or an HTTP pull consumer reads is not pruned: nothing is deleted for it, the error names each consumer with the command that detaches it, and the run fails once the other orphans are pruned. The deploy guide gives the teardown order
