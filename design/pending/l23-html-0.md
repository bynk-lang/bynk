## ADR: html-is-not-a-string
title: Markup is `Html`, a type in `bynk.html` distinct from `String`, and escaping by context is the compiler's job
summary: `Html` is opaque in `bynk.html`, reached by escaping by context or `Html.unsafe`, never crosses a boundary, and revises ADR 0143's "Bynk does not template HTML" for HTML responses

**Context.** A Bynk service serves a page by reading a shell with `embed`, filling its markers with `String.replace` and `bynk.html`'s `escapeText`/`escapeAttr` ([ADR 0993](0993-html-escape-commons.md)), and returning `Raw(…, "text/html; charset=utf-8")`. The escapes are right only where the author put them, and even a correct escape is wrong in a URL attribute, an unquoted attribute, `<script>` or `<style>`. Nothing in the types records which strings are markup: the serve-a-page guide inserts `content` unescaped because it "is markup you built". The HTTP security review found this, and the typed-HTML track (`design/tracks/typed-html.md`, spine #3927) answers it. [ADR 0143](0143-raw-http-body.md) and `reference/http.md` say Bynk serves bytes with a content type and "does **not** template HTML (that is the frontend tier)"; [ADR 0954](0954-html-response-security-headers.md) D leaves a policy built from the page to a typed-HTML feature. ADR 0993 kept its escapes bare, rather than `Html.escapeText`, because an `Html.` prefix needed a placeholder type before this track defined the real one.

**Decision A — `Html` is a type, not a `String`.** `Html` is an opaque type over `String`, declared in the first-party `bynk.html` commons (ADR 0993's unit) and reached with `uses bynk.html`. It is not a built-in: a name in `BUILTIN_TYPE_NAMES` may not be a user's `type`, so a built-in `Html` would break every project's own `type Html`, the reason [ADR 0659](0659-url-commons.md) B kept `Url` out. The compiler knows it by its resolved identity, as [ADR 0666](0666-d1-sql-bools-literal-sql.md) B keys the D1 check on `bynk.cloudflare`'s `D1`. Its operations are the checked `html"…"` literal, a template's `fill`, `Html.text(s)` (escaped as element text), `Html.join(xs)`, `Html.empty`, `Html.unsafe(markup, reason)` and `h.toString()`. These are the only ways to make an `Html`, and `toString()` goes only the other way. `escapeText` and `escapeAttr` keep their names, types and behaviour, and stay bare.

**Decision B — the bridges.** Data reaches markup only through the escape its context needs, chosen by the compiler from where a placeholder or hole sits (the context-model ADR in this increment). Raw markup enters only through `Html.unsafe` (the unsafe-rule ADR in this increment). There is no `Html` constructor, no implicit conversion from `String`, and an opaque `Html` cannot become a `String` through interpolation, because `interpolable` admits no opaque type (`bynk.types.interpolation_non_scalar`).

**Decision C — `Html` does not cross a boundary.** A record may hold an `Html` field (a template's fields record needs one), but a type containing `Html` is refused by the codec, as a request parameter, by `Json.decode` and as an agent `store` field (`bynk.html.at_boundary`). Markup from outside therefore enters only through `Html.unsafe`; to send markup as JSON, a program sends its `toString()`. A pass-through `Forwarded` is opaque with no body accessor, and `Html` has no constructor from it, so an upstream body can never become `Html` or a page. That is structural, not a check.

**Decision D — ADR 0143 is revised for HTML responses.** Bynk now builds HTML pages, checked at compile time, and serves them with a page response (recorded with its slice). The "does not template HTML" stance in ADR 0143 and the matching `reference/http.md` passages (*Raw responses*, and the generated-CSP item under *What is deliberately excluded*) are rewritten by the track's book slice. `Raw` itself is unchanged: bytes with a content type, for everything that is not a page Bynk built.

**Consequences.** Every new form is additive: `Html` is a new name in a unit a program opts into, and no program that compiles today changes meaning. It enters as experimental, behind the single gate `bynk.html.typed` in `BUILTIN_EXPERIMENTAL`, with `bynk.html.Html` and its companions mapped to it in `BUILTIN_GATED`, and joins the frozen surface only on promotion. A unit that already `uses bynk.html` and declares its own `Html` would see a clash; the first code slice surveys the corpus for one. `EmailMessage.html` and `EmailReply.html` stay `Option[String]` until promotion, when moving them to `Option[Html]` is a breaking follow-on with its own proposal.

## ADR: html-context-model
title: Each placeholder in markup has one context from a WHATWG tokeniser, each context one treatment, and any other state is refused
summary: The contexts C1–C14, what each accepts, the hand-written tokeniser and how it is tested, and the fragment, foreign-content and `<noscript>` rules

**Context.** An embedded file and an `html"…"` literal are compile-time constants, so the compiler can tokenise their HTML while building and know the context of every placeholder. Escaping is only correct per context: text, `<title>`, a quoted attribute, a URL attribute, `<script>` and `<style>` each need a different treatment or none is safe. A context missed, or guessed, gives false confidence, which is worse than none (track §1.2, §5.2, §6, Q2, Q3).

**Decision A — the contexts.** The compiler records the tokeniser state at each placeholder; that state, with the element and attribute names around it, is the context. Each context has exactly one treatment:

| # | Context | Accepts | Treatment |
|---|---|---|---|
| C1 | Element text (data state) | a scalar (`String`, `Int`, `Float`, `Bool`, `Decimal`, `Duration`, `Instant`, a refinement of one); `Html` | scalar: `escapeText`; `Html`: as is |
| C2 | Text of `<title>`, `<textarea>` (RCDATA) | a scalar | `escapeText`; `Html` refused (`bynk.template.html_in_rcdata`) |
| C3 | Double- or single-quoted value of an ordinary attribute | a scalar | `escapeAttr` |
| C4 | Unquoted attribute value | nothing | refused (`bynk.template.unquoted_attribute`); the fix adds quotes |
| C5 | Quoted URL attribute, whole value | `Href` | `escapeAttr` of the checked string |
| C6 | Quoted URL attribute, after a safe literal prefix | a scalar | `percentEncode()`, then `escapeAttr` |
| C7 | Code-loading attribute, whole value only | an `Asset` | its `.url`, filled at compile time in a template |
| C8 | `<script>` body, other than a JSON data block | nothing | refused (`bynk.template.placeholder_in_script`) |
| C9 | `<script type="application/json">` or `application/ld+json`, whole body | a `Codable` value | JSON with `<`, `>`, `&`, U+2028, U+2029 as `\u` escapes |
| C10 | `<style>` body, `style` attribute | nothing | refused (`bynk.template.placeholder_in_style`) |
| C11 | `on*` attribute, `srcdoc`, `<meta content>` beside `http-equiv` | nothing | refused (`bynk.template.placeholder_in_code_attribute`) |
| C12 | `srcset`, `imagesrcset` | nothing | refused (`bynk.template.srcset`) |
| C13 | Tag name, attribute name, comment, doctype, CDATA, inside `<svg>`/`<math>` | nothing | refused (`bynk.template.placeholder_position`) |
| C14 | Inside `<xmp>`, `<iframe>`, `<noembed>`, `<noframes>`, `<plaintext>` or `<noscript>` | nothing | refused (`bynk.template.placeholder_in_raw_text`) |

A tokeniser state the table does not name is refused (`bynk.template.unsupported_markup`), never guessed. Script and style take no placeholder, except a JSON data block whose whole body is one `Codable` value, which is data and is not executed. URL attributes (C5, C6) are `href`, `src`, `action`, `formaction`, `poster`, `cite`, `ping`, `background`, `longdesc`, `manifest`, `codebase`, `data` (except on `<object>`), `icon`, `usemap`, `xlink:href` and the rest of the list Go's `html/template` uses. Code-loading attributes (C7) are `<script src>`, `<link href>` unless `rel` is literally navigational (`canonical`, `alternate`, `icon`, `prev`, `next`, `author`, `license`), `<object data>`, `<embed src>`, `<iframe src>` unless its `sandbox` is a literal that does not grant both `allow-scripts` and `allow-same-origin`, and SVG's `<script href>` and `<script xlink:href>`. A placeholder in a code-loading attribute that is not the whole value is refused (`bynk.template.code_loading_not_asset`), a placeholder in `sandbox` is refused as C11, and `<base href>` takes no placeholder (`bynk.template.placeholder_position`). A name used in several places must satisfy every context it appears in (`bynk.template.conflicting_contexts`), and a field's type that its context does not accept is `bynk.template.context_type`.

**Decision B — secrets are refused everywhere.** `Secret`, `Authorization` and `ApiKeyValue` (every `SecretKind`, [ADR 1038](1038-opaque-secret.md)) are refused in every context with their own code, `bynk.template.secret_placeholder`, whose note names ADR 1038; and a record carrying a secret (`type_carries_secret`) cannot be a template's fields type. None is a scalar, `Html`, `Href`, `Asset` or `Codable`, so the table already refuses them; the dedicated code says why. A secret reaches a page only through `Html.text(s.reveal())` or `Html.unsafe(s.reveal(), …)`, which write the audited door in the source.

**Decision C — a hand-written tokeniser that refuses what it does not model.** A tokeniser in the checker implements the WHATWG states the model needs (data, RCDATA, RAWTEXT, script data, tag open, the attribute states, comment, doctype, CDATA in foreign content) and refuses everything else. It needs the state at each placeholder, not a tree, and a tree builder's error recovery is what the model must refuse, not reproduce. It also refuses inputs a browser accepts only through error recovery that changes a context: a `<` in an attribute name, an attribute repeated on one element, an unclosed comment, a `</script` inside a script that is not the end tag. It builds for `wasm32` ([ADR 0816](0816-hyperdrive-h4-postgres-test-double-and-sql-check.md) B). As the YAML subset parser is held correct by a corpus and a differential against a dev-only library ([ADR 0789](0789-yaml-subset-parser.md)), it is held by three tests: the `html5lib-tests` tokeniser corpus over every state it implements, with a test that every other state is refused; a `proptest` differential against `html5ever` (a dev-dependency only), checking the state at each placeholder and that every accepted input, filled with adversarial values, parses with each value as exactly one text or attribute-value token; and a `cargo-fuzz` target. Rejected: `html5ever` as a compiler dependency, a tree builder used for a fraction of its work whose recovery is what the model refuses. Rejected: a restricted grammar of our own, which would refuse valid pages.

**Decision D — fragments start and end in element text.** An `html"…"` literal starts in the data state and must end there, not inside a tag, an attribute, a comment, or raw or RCDATA text (`bynk.template.fragment_unclosed_state`), so an `Html` value never leaves a parent page in another state. Element balance is not required: `html"<ul>"` is a valid fragment.

**Decision E — foreign content and `<noscript>` are balanced within one piece.** Inside `<svg>` or `<math>` the tree builder changes how `<script>`, `<style>`, `<title>` and `<![CDATA[` tokenise, and a fragment checked from the data state cannot see that a parent opened one. So every `<svg>` or `<math>` a template or fragment opens must close in the same template or fragment, a closer with no opener is refused, and the subtree may hold no placeholder (`bynk.template.foreign_unbalanced`, `bynk.template.placeholder_position`). In this version a subtree may not contain an integration point (`<foreignObject>`, `<annotation-xml>`, SVG's `<desc>` or `<title>`) or an HTML element that makes the tree builder leave foreign content, so counting tags matches the tree builder. `<noscript>` is RAWTEXT with scripting on and markup with it off, so its context depends on the browser: a placeholder inside it is refused (C14) and every `<noscript>` opened must be closed in the same piece. The tokeniser and the differential run with scripting on, the state of every browser serving these pages. `<plaintext>` never ends, so a placeholder after it is refused and a fragment may not contain one. Static inline icons with no placeholder keep working.

**Consequences.** A template or fragment the compiler accepts has a known context at every placeholder and an escape complete for it, and the guarantee rests on three tested things: the tokeniser agrees with browsers, each escape is complete for its context, and nothing else produces `Html`. Pages that need something refused (a placeholder in a style, a `srcset`, foreign content, a dynamic attribute name) are refused today, and each can be admitted later without breaking anything. The diagnostic codes are named here so this record can cite them; the slice that first raises one may rename it, saying so in its own ADR.

## ADR: html-unsafe-rule
title: `Html.unsafe(markup, reason)` is the one raw door, with a literal reason, allowed in dependencies and listed per package
summary: Why the escape hatch is named `unsafe`, why its reason is a literal, why there is no warning on run-time arguments, and how a dependency's use is made visible

**Context.** Real pages need markup the compiler did not check: rendered Markdown, CMS content, a third-party widget. An escape hatch that is too easy undoes the guarantee, and one that is too hard (a warning on every use) teaches people to ignore it. The maintainer ruled on its name and its use in dependencies on 27 November 2026 (track §5.6, Q5).

**Decision A — the name and its shape.** `Html.unsafe(markup: String, reason: String) -> Html` is the only way raw markup enters an `Html`. The name tells a reviewer that the compiler stops checking here and greps with other `unsafe` audits. It is one token, `Html.unsafe`; no other API reaches it, and it lowers to the identity. Rejected: `Html.trusted`, which reads as an assertion of safety rather than a waiver of checking.

**Decision B — the reason is a non-empty string literal.** Not a `const`, so the reason is at the call site, in review and in hover (`bynk.html.unsafe_reason_not_literal`). An empty reason is refused under the same code.

**Decision C — a hint for literal markup, no warning otherwise.** When `markup` is a string literal, a hint says to write `html"…"`, which is checked (`bynk.html.unsafe_literal`, machine-applicable when the literal is a valid fragment). A run-time argument draws no warning: every real use is dynamic, so a warning would fire on every use. Rejected: a warning on run-time arguments.

**Decision D — dependencies may call it, and every call is listed.** `bynk check --unsafe-html` lists every `Html.unsafe` call site the build compiles, grouped by package with the project's own first, with file, line and reason; the language server shows the same list as a code lens on the `[dependencies]` table. A Markdown renderer is the obvious dependency, and it cannot exist if dependencies may not call the hatch. Rejected: refusing dependencies unless the project opts in per package, which forbids the renderer and adds a knob the listing makes unnecessary.

**Consequences.** `Html.unsafe` belongs to the track's experimental gate, `bynk.html.typed`, like every `Html` operation, and `StabilityPolicy` is the root project's, so a dependency that uses it compiles only in a project that allows the gate. Markup passed to it is outside the guarantee; the track sanitises nothing, and the docs say so. Once the project allows the gate, a dependency's use is trusted; the listing makes that trust visible, not safe.

## ADR: template-declaration
title: A template is its own `template name: Fields = "path"` declaration, with `\(name)` placeholders checked against a declared record
summary: `template` honours ADR 0608 F, `embed` stays verbatim, placeholders are recognised narrowly, fields are a nominal record, and asset names bind only in code-loading attributes

**Context.** [ADR 0608](0608-embedded-text-in-the-language.md) F reserves a separate `template` declaration for a parsed file: "Different contracts are different declarations, so `embed` never starts to interpret `{{ }}`." A template needs a placeholder syntax, a contract between the file and the Bynk code that fills it, and a rule for how a placeholder binds (track §4.1, §6, Q1, Q6, Q11).

**Decision A — the declaration.** `template name: F = "embeds/…"` declares a template whose fields type is the nominal record `F`; `name.fill(fields)` has type `Html`, with `name: Template[F]`. `template name = "…"` declares a template with no fields, whose value is `Html` and in which any placeholder is an error. `template` is a contextual keyword at item position only, so `template` as a binding, field or function name elsewhere keeps working; today an item starting with an identifier is a parse error, so no program changes meaning. The file lives under `embeds/`, follows the embed size caps ([ADR 0609](0609-embedded-text-content-rules.md) C), and is read by the build and by the editor's analysis, so template errors show while editing. `embed` keeps one contract: verbatim text. Rejected: `embed shell: Html`, which gives `embed` two contracts by annotation, what 0608 F was written to prevent. Templates in package dependencies are not supported, as for embeds today; a dependency may export functions that return `Html`.

**Decision B — placeholders.** A placeholder is `\(name)`, a bare name, matching a hole in an `html"…"` literal ([ADR 0075](0075-string-interpolation.md)) so one rule covers both. Only `\(` followed by a name and `)` is a placeholder, and only when its backslash does not follow another backslash. Any other `\(` is literal text and the file has no other escapes, so MathJax's `\(x^2\)`, a regex such as `/\(/` and `\\(` pass through unchanged. A literal `\(name)` in text or an attribute is written `&#92;(name)`. In raw text a placeholder-shaped `\(name)` is refused like any placeholder there, with a note to rewrite it. Rejected: `{{name}}`, which Vue, Alpine, Angular and Handlebars use, so the clash with a file shared with them would be permanent.

**Decision C — a declared nominal fields record.** Every placeholder must name a field (`bynk.template.unknown_placeholder`, with the nearest field suggested) and every field must be used (`bynk.template.unused_field`). `fill` takes the whole record: there is no partial fill. A record carrying a secret cannot be a fields type, and a record cannot carry an `Asset`, which is not data. Bynk has no anonymous record literals or named arguments, and a declared record makes the template's contract readable in Bynk. Rejected: a record inferred from the file, which lets an HTML file silently change a Bynk API. Rejected: partial fills.

**Decision D — asset names bind only in code-loading attributes.** A placeholder in a code-loading attribute (C7) names an asset in scope and is filled with its URL at compile time; it is not a field. Anywhere else a placeholder names a field, and an asset name there is an unknown placeholder with a note naming the asset. A name that is both a field and an asset in scope is refused wherever it appears (`bynk.template.ambiguous_placeholder`). So renaming an asset or adding a field can never silently change what a placeholder binds to.

**Decision E — no run-time parser.** A template compiles to a function of its fields: literal chunks and escape calls, with `Html` a branded `string` in TypeScript. The tokeniser runs once, in the compiler; the runtime gains no tokeniser, parser or sanitiser.

**Consequences.** Placeholder mistakes are compile errors at the template's line and column, with a related location at the declaration. The `template` keyword is one of the track's two grammar touches, flagged for the 1.0 grammar freeze; the declaration enters as experimental under `bynk.html.typed`, through a stability check at the item under the synthetic path `bynk.html.typed.template`, so the gate holds in the build and the editor alike. Migrating a `{{name}}` shell is a find-and-replace.

## ADR: href-type
title: A URL attribute takes `Href`, an opaque type whose only door from outside is `Href.of`'s scheme check
summary: `Href`'s constructors, the four schemes `Href.of` accepts, no decoding, refusal at every boundary, and the safe-prefix rule for partial URLs

**Context.** An attribute-escaped value is still unsafe as a whole URL: `javascript:` passes `escapeAttr`. Browsers strip tabs and newlines from a scheme and read `\` as `/` in special URLs, so a regular expression over a `String` misses `java\tscript:` and `/\evil.example`. `bynk.url` already declares `Url` as a record that allows any scheme ([ADR 0659](0659-url-commons.md)), so a second `Url` would clash in any unit that uses both (track §5.4, Q4).

**Decision A — the type and its constructors.** `Href` is an opaque type over `String` in `bynk.html`. Its constructors are `Href.of(s) -> Option[Href]`, `Href.asset(a)` (an asset's URL), `Href.fromUrl(u) -> Option[Href]` (a `bynk.url` `Url`, formatted then checked as `Href.of`), and `Href.root` (`/`). There is no route builder, because Bynk has none. `Href` is not `Codable` and is refused at every boundary (`bynk.html.at_boundary`): a decoded `Href` would skip `Href.of`, so `Href.of` is its only door from outside. To store a URL, a program stores the `String` and calls `Href.of` on read. Rejected: a refined `String`, which widens back to `String` and invites the regex that misses `java\tscript:`. Rejected: reusing `bynk.url`'s `Url`.

**Decision B — what `Href.of` accepts.** It checks the string the browser will see, and neither decodes nor re-encodes:

1. Any ASCII control character (U+0000–U+001F, U+007F), space or backslash anywhere is refused.
2. A string with a scheme (WHATWG: an ASCII letter, then letters, digits, `+`, `-` or `.`, then `:` before any `/`, `?` or `#`) is accepted only for `http`, `https`, `mailto` and `tel`, compared without regard to case. `javascript:`, `data:` (even for images), `vbscript:`, `blob:`, `file:` and every other scheme are refused.
3. A string without a scheme is a relative reference, accepted unless it starts with `//`, a network-path reference that chooses the host.

A percent-encoded scheme is not a scheme: `javascript%3Aalert(1)` has no `:` in scheme position, so it is a relative path on the service's own origin, which is how the browser reads it. An already percent-encoded value passes through unchanged. Every `Href` is attribute-escaped on output, so a character reference such as `&#106;avascript:` reaches the browser as literal text, never decoded into a scheme.

**Decision C — partial URLs.** A placeholder after a literal prefix in a URL attribute (C6, `href="/orders/\(id)"`) takes a scalar, which is percent-encoded with `percentEncode()` (ADR 0659 A; it keeps only `A–Z a–z 0–9 - . _ ~`) and then attribute-escaped. The literal prefix must be a relative path starting with `/` but not `//` or `/\`, or with `./`, `?` or `#`; or `http://` or `https://`, a host, and then `/`, `?` or `#`. So a value can neither turn `/` into `//evil.example`, nor add a path, query or fragment the author did not write, nor choose the host. Any other prefix, including a bare `https://\(x)`, `https://example.com\(x)` or another scheme, is refused (`bynk.template.url_prefix`). A prefix that is itself a placeholder (`\(base)/x`) is C5 followed by literal text, and the whole value must then be an `Href` plus literal text that adds no scheme. `srcset` and `imagesrcset` are refused in this track (`bynk.template.srcset`), because a comma in a value changes their parse; a later increment can admit a list of `Href`s. `formaction` is an ordinary URL attribute, and `ping` takes one `Href`.

**Consequences.** `Href` allows any `http(s)` host, so a link to a hostile site is possible when a value chooses the whole URL; that is not XSS, and the docs say so. `percentEncode()` keeps `.`, and the URL standard reads `%2e` as a dot too, so a value of `.` or `..` filling a whole path segment is still a dot segment: `/orders/\(id)` with `id = ".."` resolves to `/`. That stays on the same origin and is a known limit, not something the rule rules out; `fill` cannot fail, a field typed `Int` or a refinement that excludes dots cannot produce it, and the partial-URL fixture pins the behaviour so a later reader cannot mistake it for a guarantee. The run-time checks are only the escape functions and `Href.of`'s scheme check, both property-tested, with `Href.of` checked against the WHATWG URL parser and a corpus of known `javascript:` bypasses.
