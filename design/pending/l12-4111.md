## ADR: opaque-secret
title: Secret is an opaque value with one deliberate way out
summary: Why a secret read from the platform is a type that cannot be printed, compared or stored, and how reveal and matches are the only readers

**Context.** `Secrets.get` and `StoredSecret.get` returned a `String`, so a secret was indistinguishable from any other text: it could be interpolated into a log line or an error, stored in a record or `store` field, returned from a handler, sent in an event, compared with `==` in variable time, or shown on the left of a failing `expect`. Each was one ordinary expression away.

**Decision.** (A) `bynk` exports `Secret`, an opaque type. It is refused wherever text could leave a program: it is not `Codable` (`Json.encode` refuses it), has no interpolation form, is not a `Key`, and is `bynk.types.secret_at_boundary` as a record, event or `store` field or a handler's parameter or result, in any nesting (`List[Secret]`, a record that holds a record that holds one). A capability operation may take or return one, which is how `Secrets.get` and `StoredSecret.get` produce it. (B) It has exactly two methods, both compiler built-ins, since an opaque value has no in-language unwrap: `reveal() -> String`, the one deliberate exit, and `matches(candidate: String) -> Bool`, a constant-time comparison that folds a length mismatch into its result instead of returning early. `==` and `!=` on a `Secret`, or on a type that holds one, are `bynk.types.secret_not_comparable`. (C) At run time a `Secret` is a `BynkSecret` wrapper whose `toString`, `toJSON` and inspection render `<secret>`, with the text in a `#private` field, so a path the checker cannot see (a fault message, a trace field, a test's failure diff, `console.log`) shows no text. The platform bindings wrap what they read. (D) `Secret.of` is a test stand-in: it returns the `Secret` directly, and a context cannot construct it (`bynk.context.external_construction`, as for any type `bynk` owns), so text in source never becomes a secret in a deployed program. (E) Breaking: a program that read the secret as a `String` now calls `reveal()`, which puts each exit in the source where review can see it. A hand-written binding receives a `BynkSecret`.

**Consequences.** The default for a secret is safe and the exception is spelled. `Request.authorization` still takes a `String` for now, so passing a secret there is `reveal()`; a later increment gives it a type that carries the secret without revealing it, and the crypto key import a `Secret` form. Header values in `Request.headers` stay `String` with a visible `reveal()`. A secret that is `reveal()`ed is text again and the compiler no longer follows it.
