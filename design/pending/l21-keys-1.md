## ADR: api-key-mint
title: `Actor.mint(identity, label)` makes an API key in a service handler, stores only its digest, and answers it once
summary: The first `ApiKey` member, its type and where it is legal, the generated agents' slice-1 shape and their internal constant-time comparison, and the one experimental gate

**Context.** The API keys track (`design/tracks/api-keys.md`, spine #3939) settles the key format, the peppered storage and the verification contract up front (the three ADRs of slice 0). It records the members' shapes in the slices that ship them. Slice 1 ships verification and `mint`, because a scheme that verifies keys nobody can mint ships nothing usable (§14). It ships in two parts: this one carries the scheme, the seam, `mint` and the generated agents; the next carries `bynk deploy`'s pepper (live check K1), the `system` tier's key principals and the reference pages.

**Decision A — `mint`.** `Actor.mint(identity, label)` on a local `ApiKey` actor is `Effect[Result[ApiKeySecret, TooManyKeys]]`. It takes the actor's own identity type and an `ApiKeyLabel` (1 to 64 characters, none of them a control character), needs `given Clock` for the key's creation time, and is legal only in a service handler, where the pepper is (`bynk.actor.api_key_mint_outside_handler`). The runtime draws the key number and the 32-byte secret, digests the secret under the pepper, and asks the identity's `<Actor>KeyOwner` to store the digest. That handler files it in `<Actor>Keys(handle)`, taking a fresh handle when the identity has none or its store is retired. `TooManyKeys { limit }` is the answer when the identity holds 100 keys. Expiry is not a `mint` argument (Q5): `ttl` is a later slice, so `expires` is `None`.

**Decision B — the key goes out once.** `ApiKeySecret` is `{ id: ApiKeyId, key: ApiKeyValue, label: ApiKeyLabel, created: Instant, expires: Option[Instant] }` in the `bynk` prelude, with `ApiKeyId`, `ApiKeyLabel` and `TooManyKeys`. `ApiKeyLabel` is a name the track did not list; it is the refined label type §9 describes. A type that holds an `ApiKeyValue` is `bynk.types.secret_at_boundary` everywhere but one place: an HTTP handler's `Effect[HttpResult[ApiKeySecret]]`, whose codec reveals the key on the wire. No Bynk code can build an `ApiKeyValue`, so every `ApiKeySecret` is one `mint` answered.

**Decision C — the agents' slice-1 shape.** `<Actor>Keys(handle)` keeps one `Map` per field (digest, `kid`, label, created and an empty scope set), keyed by key number, beside the identity and a `retired` flag. Parallel maps rather than a record keep the reserved names to the two agents. `verify(keyNo, presented, first, dummy)` compares exactly once: against the record's digest when there is a record whose `kid` the seam sent, else the presented digest against the dummy. It admits only a real record that matched. The pepper is threaded to `mint` in `deps.__apiKey`, and `callDurableObjectMethod` drops that key from every agent call's body, so no pepper reaches an agent (D2 B).

**Decision D — the comparison is an internal kernel, not `Crypto`.** §6 has the key store consume `Crypto` for its comparison. The generated agents instead call `ApiKey.equal`, an internal kernel that only the compiler's generated agents can name (anywhere else it is `bynk.actor.api_key_internal`). It lowers to the runtime's one constant-time comparison, the function `bynk.crypto`'s `Crypto.equal` binding also calls on every platform, so there is still one implementation, and a test pins that each binding calls it. This keeps a context that declares an `ApiKey` actor from having to consume, and allow, `bynk.crypto`, and adds no `consumes` line to the author's file, which would move every later span. The deviation from §6 is recorded here.

**Decision E — one gate.** The scheme, its five prelude types and its members are experimental under one name, `bynk.actor.ApiKey` (`[unstable] allow`), rather than one name per type (§17).

**Decision F — what slice 1 refuses.** `previous` and `ttl` are refused (`bynk.actor.api_key_unknown_key`) until slice 3 reads them. An `ApiKey` actor is not admissible on a WebSocket `on open`, or as an actor-sum member until slice 4 (`bynk.actor.scheme_not_admissible`). `key: identity` stays `bynk.http.rate_limit_key_unavailable` until slice 2. `bynk.actor.api_key_unlimited` warns on a route with no `clientIp` rate limit.

**Consequences.** A service can mint keys and authenticate requests with them, with no hand-written cryptography. The next part of this slice makes `bynk deploy` mint the pepper as a Worker secret through the `SignedCookie` key path (live check K1), adds `by <Actor>(…)`, `by Malformed`, `by Unknown` and `by Forged` at the `system` tier, and the reference pages. Listing and revoking keys (slice 2), expiry, last use and rotation (slice 3), sums (slice 4), and OpenAPI and the client (slice 5) follow.
