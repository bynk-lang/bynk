## ADR: r2-range-conditional-and-delimited-reads
title: R2 reads can take a byte range, an etag condition and a listing delimiter
summary: Three experimental R2 operations that map directly onto R2's own get options and list delimiter, with an R2Listing that reports the delimited prefixes

**Context.** `R2`'s reads are whole-object only: no range read (video, audio, resumed downloads, `Range` requests), no conditional get (`R2Condition` applies to `putWith` alone, so a revalidating read still transfers an unchanged object), and no delimiter on `list` (a folder view means listing everything under the path). These are R2's own capabilities that the binding did not expose.

**Decision.** `getRange(key, range: R2Range) -> Effect[Option[R2Partial]]` reads a byte range as a stream. `R2Range` is `Span(offset, length: Option[Int])` or `Suffix(length)`; the offset variant is `Span`, not the proposal's `Bytes`, because `Bytes` is a reserved word and cannot name a variant. `R2Partial` carries the whole object's metadata, the `offset` and `length` the body holds, and the body, so a handler builds `Content-Range` from it. A length past the end is clamped by R2; a range that starts at or past the end is R2's own refusal (`get: The requested range is not satisfiable (10039)`), confirmed against Miniflare's R2, and the read faults rather than Bynk inventing another answer. `getStreamIf(key, onlyIf: R2GetIf) -> Effect[R2Read]` reads only when an etag condition holds: `R2GetIf` is `Unconditional | IfEtagMatches | IfEtagDiffers` (a separate type from `R2Condition`, since `Absent` means nothing for a read, and extensible; the proposal's `EtagMatches` and `EtagDiffers` are prefixed `If` because a second `EtagMatches` in the unit makes an existing program's `let cond = EtagMatches(etag)` ambiguous, `bynk.resolve.ambiguous_variant`), and `R2Read` is `Present(body: R2Body) | Missing | NotModified(object: R2Object)`; the proposal's `Found` is renamed because `HttpResult` already has a `Found` (a redirect), so a program that consumes `bynk.cloudflare` and uses it would stop compiling. `listWith(options: R2List { prefix, cursor, delimiter }) -> Effect[R2Listing]` lists with a delimiter, and `R2Listing` gains `prefixes: List[String]`, empty unless a delimiter was given; `list(prefix, cursor)` stays the short form. A page counts keys and prefixes together. The in-memory bucket, the unit-tier double and the binding all honour ranges, conditions and delimiters, and a workerd smoke checks them against Miniflare's R2. Ranges stay streamed, never buffered.

**Consequences.** Additive; nothing that compiled changes meaning (`R2Listing` is built by the binding, not by programs). `HttpResult` has no `206` or `304` variant, so a handler cannot yet answer a range request with `206 Partial Content`, or map `NotModified` to `304` directly (the router answers `304` for a validated `Raw`/`RawTagged` response); the docs show the `Content-Range` a handler computes and say so. Real-Cloudflare behaviour is checked only through Miniflare. Hover, completion and signature help follow from the capability declaration; semantic tokens are unchanged.
