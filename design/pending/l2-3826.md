level: patch
changelog: `bynk check <dir>` inside a project now checks the project, reading its `bynk.toml`, instead of checking the directory as a bare tree, so `bynk check src` no longer reports `bynk.stability.experimental` for an item the manifest already allows (and no longer tells you to add an entry that is there); a note names the project it checked. The README and the example READMEs say `bynk check`
breaking: `bynk check <dir>` and `--emit` on a directory that has no `bynk.toml` or `src/` of its own but sits in a project's `[paths] include` trees now run on the enclosing project, where they used to treat the directory as a standalone source tree. `--fix` still edits only the directory named. A run that passed because the manifest was not read (its `[unstable] allow`, `[paths]` and `[env]` ignored) can now fail, or report other findings, as `bynk check` from the project root always did. A directory outside the project's sources, excluded from them, or with its own `src/` is still checked as itself. To check a tree standalone, run `bynk check` from a directory outside any project, or pass a single `.bynk` file; `--each` keeps its refusal inside a project.
