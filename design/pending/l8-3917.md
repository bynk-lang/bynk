## ADR: precondition-variants
title: HttpResult gains PreconditionFailed (412) and PreconditionRequired (428) for conditional writes
summary: Two message-carrying statuses, and how a handler guards a write with If-Match

**Context.** Optimistic concurrency, "update this only if it has not changed since I read it", is a standard HTTP pattern: the client sends `If-Match` and the server answers `412` when the resource has moved on, or `428` when a condition is required (RFC 9110 §13.1.1, RFC 6585 §3). `HttpResult` is a fixed vocabulary of statuses with neither, and `RawError` accepts only the listed names, so neither status could be answered at all. The automatic `ETag` is weak, and `If-Match` compares strongly, so the validators Bynk already emits cannot guard a write.

**Decision.** (A) Two message-carrying variants, `PreconditionFailed(message)` (412) and `PreconditionRequired(message)` (428), matching their neighbours `Conflict(message)` and `UnprocessableEntity(message)`; they render under the service's error format, problem details included. (B) Both are `ErrorStatus` names, so `RawError(PreconditionFailed, …)` works. (C) No automatic precondition check yet: evaluating `If-Match` in the router would need the router to know the resource's current validator before the handler has looked it up, which is a later design (an annotation naming a validator source). The variants and a documented pattern cover the need now: read `If-Match` through a typed `headers` record, compare, answer `428` or `412`. (D) The reference explains weak versus strong: the automatic `ETag` is for revalidating `GET`s, and a write is guarded with a strong validator served by `RawTagged` or an explicit version.

**Consequences.** A handler can answer the two statuses without leaving the typed error shape. A user sum variant named `PreconditionFailed` or `PreconditionRequired` is disambiguated by the existing `ambiguous_constructor` rule. OpenAPI and the client list the statuses, because both read the same variant table. Hover, completion, semantic tokens and signature help take the variants from that table, like every other variant.
