## ADR: book-from-the-installed-toolchain
title: The Book a chat agent searches comes from the installed toolchain
summary: `bynk book` embeds the Book in the driver; the extension searches it, falling back to the hosted copy

**Context.** `bynk_search_book` (#2463, DECISION B) must return Book text that
matches the `bynk` the user runs. The live site may describe features the
toolchain lacks and needs the network; bundling the Book in the `.vsix` ties it
to the extension's version instead. A file installed beside the binary does not
work: the extension downloads `bynk` as a single verified file
(`SHA256SUMS` covers the raw `bynk-<target>` assets), so a sibling file would
never arrive for a downloaded toolchain.

**Decision.** The driver embeds the Book. `bynk/build.rs` includes
`site/public/llms-full.txt` (the whole Book in sidebar order, generated by
`site/scripts/build-llms-full.mjs`) and the new `bynk book` subcommand prints it
under a first line naming the toolchain version. The release workflow generates
the bundle before building; a build without it (a plain `cargo build`, or a
crate tarball with no `site/`) embeds an empty bundle, and `bynk book` then
exits non-zero. The extension runs `bynk book`, parses the sections and ranks
them itself — the driver does not search, so the hosted fallback
(`https://bynk-lang.org/llms-full.txt`) ranks identically. When `bynk book` is
unavailable (no bundle, or an older `bynk`), the tool uses the hosted Book and
labels the result with the Book's version, the installed toolchain's, and a
mismatch warning. The tool is desktop-only: it needs the CLI, and a browser's
fetch of the hosted file depends on the site's CORS policy, which is not
established.

**Consequences.** Release binaries grow by the Book's size (about 2 MB), and the
Book answers are exact for the version shipped. The generated bundle stays out
of version control (it is gitignored), so Book edits cause no churn in `bynk/`.
`cargo install bynk` from a crate tarball has no Book bundle and relies on the
hosted fallback. The vscode.dev leg of DECISION D (Book search on the web) is
deferred until the site's CORS policy is settled or the wasm module carries the
Book.
