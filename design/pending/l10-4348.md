## ADR: test-only-commons-scoped-to-users
title: A test-only commons is in scope only where it is used
summary: How each suite's view is built from its own uses, and what the emitted module still unions

**Context.** #3984 added a test-only commons to the target's view for every suite of that target, so a suite saw its names although it had no `uses` of it, and compiled only while a sibling suite imported it (#4348).

**Decision.** The checks build one view per suite: the target's `uses` plus the test-only commons that suite `uses`, so a name is unknown in a suite that does not import it (`bynk.resolve.unknown_name`). The emitted test module is one module per target and still unions every suite's test-only `uses`; it only has to reach every name a checked suite may spell, so the union adds nothing to what a suite can write.

**Consequences.** A `stub … returns` value is checked against the target's view over every suite's test-only commons, so a stub value can still spell a name that a different suite of the target `uses`. Stubs belong to a suite, so scoping them is left for a follow-up.
