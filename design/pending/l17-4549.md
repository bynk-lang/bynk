## ADR: websocket-out-frames-use-the-codec
title: A WebSocket service writes its `out` frames with its type's serialisation codec
summary: an `out` frame is encoded by the codec its `in` counterpart is decoded with, found at `send` by a service name the socket's attachment records, so the wire form of a frame is the codec's for every type that can be a frame

**Context.** `Connection.send` wrote an `out` frame as `JSON.stringify` of the runtime value, while an `in` frame is decoded by the serialisation codec. The two directions used different wire forms: an `Option` went out as `{"tag":"None"}` where the codec writes `null` or `{"kind":"None"}`, a `Decimal` (which holds a bigint) made `JSON.stringify` throw, and an `Instant` or sum went out in its runtime representation. The cross-context wire format is frozen at 1.0, so the `out` form was an accident of the runtime about to become a contract (#4549, found while building the typed client of #3906).

**Decision A — encode with the frame type's codec, in the runtime's `send`.** The codec is the serialiser the checker already certifies a frame type for and the HTTP side uses. The call site of `send` knows the frame type but the Durable Object that holds the socket does not, and `send` is reached through a stored connection id from agent code, so the encoder cannot be threaded through every call site. Instead the module that hosts a service's sockets registers the encoder under the service's name when it loads (`__registerFrameEncoder`), and the upgrade records that name (`svc`) in the socket's attachment beside `max` and `bin`; `WorkersConnection.send` looks the encoder up by it. The attachment survives hibernation and the registration runs again when the module loads, so a woken socket encodes as before. Rejected: wrapping the frame at every `.send` lowering (many sites, one per held-connection access path, each needing the codec helpers in its module); and storing the codec on the connection (a socket holds no function).

**Decision B — a plain `Bytes` frame is unchanged, and so is a frame whose two forms coincide.** `Bytes` stays a binary message with no codec (#3905). A string, number, boolean, list or plain record is the same JSON as before, so most services see no change.

**Decision C — the test tier runs the codec too.** `svc.open(tc, …)` hands the `TestConnection` the service's encoder as well as its `maxFrame`. `send` runs it, so a frame the codec cannot write faults in a `unit` case as it does on the platform, and the frame-size check judges the wire form; `tc.sent` keeps the frame as the handler wrote it, so existing assertions read as before.

**Decision D — a socket accepted before this change is not re-encoded.** It records no service name, so it is sent as the runtime's own JSON until it reconnects, the same transition #3905 accepted for `maxFrame`. The `out` type of each hosted service is added to the boundary types the module generates helpers for, so its codec exists where the encoder is registered.

**Consequences.** An `out` frame round-trips through the codec for every serialisable type the checker admits there, which the generated client of #3906 relies on, and the WebSocket reference states the wire form. A client that read the runtime's `{ "tag": … }` shape of an `Option` must read `{ "kind": … }`. A workerd test sends frames holding an `Option` in each state, a `Decimal`, an `Instant`, a sum, a nested record and a list of `Option`s, and compares each with the codec's own JSON.
