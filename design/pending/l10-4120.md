## ADR: generate-collections-and-options
title: Collections and options are generable, and the pin diagnostic names the culprit
summary: What a for all draws and shrinks for the four types, what Val yields, and how the diagnostic finds the part

**Context.** `for all` and `Val` refused `List`, `Set`, `Map` and `Option`, and any record or sum holding one, with a message that blamed a `Matches` refinement that was not there (#4120).

**Decision.** The maintainer accepted the issue's decisions. A: a `List` draws up to eight elements, with 0, 1 and the maximum over-represented, each from its element's generator; a `Set` and a `Map` draw a list and keep distinct members and keys (the runtime's keyed set and map, so a record element is distinct by value); an `Option` is `None` or `Some`. A shrinks by dropping elements (all, each half, one at a time) and then shrinking those left, an `Option` to `None` and then its payload; plain scalars, refined `Int` and `String` and nested collections shrink in place, and a record or a sum keeps its value. The boundary values are the empty collection, `None`, and the one-element collection of the element's canonical value. B: `Val` yields the empty collection or `None`, for a bare `Val[List[T]]` and for a field of a record or sum. C: nested collections share a size budget of sixteen elements, split among the elements, so a `List[List[T]]` stays small; there is no per-property option yet. A type that recurses through a collection or an option (`Tree = { children: List[Tree] }`, `Node = { next: Option[Node] }`, a JSON-like sum) is generable, since the empty collection and `None` end the recursion; an element is drawn at most three levels deep, so a generator inlined at every level of such a type stays small. D: `bynk.val.needs_pin` names the path, for example `Order.lines`: `Slug`: …, for a `for all` and for a bare `Val`, and a type with no generator at all (a `Result`, say) is named too; so is a field that narrows a named type's `@example`. A `Val` of a collection or an option of a type that is not a value type (`Val[List[Result[Int, String]]]`) is `bynk.val.unsupported_kind`, and a pin on one is `bynk.val.pin_unsupported`. Counterexamples print as written: `[0,0,0]`, `Some(0)`, `Set.of([…])`, `Map.of([…])`.

**Consequences.** A length refinement on a collection (#3806) is not part of the language yet, so nothing bounds a size beyond the budget; when it lands the draw and `Val`'s fixed choice follow its bounds. Printing an `Option` as `Some(0)` instead of its representation changes the text of a failing `Option` counterexample. A route or handler that takes a list or an optional value is now reached by smoke tests and history properties. The `4054` negative fixture moved from a `List` to a `Result`, which is still not generable.
