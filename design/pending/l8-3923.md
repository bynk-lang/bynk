## ADR: html-response-security-headers
title: HTML responses get framing and referrer protection, and security { } gains frameAncestors, referrerPolicy and csp
summary: A text/html response defaults to frame-ancestors 'none' and strict-origin-when-cross-origin, and the security section can name the framing sources, the referrer policy and a whole csp

**Context.** `security { }` stamped `nosniff` and an opt-in HSTS, and its reference said that `Content-Security-Policy` and `X-Frame-Options` were left out because Bynk serves bytes and not markup, and that the `security { }` section is where they would land if it ever served HTML. It now does: pages are built from embedded shells and returned as `Raw(…, "text/html")`, and `RawError` serves an HTML error page. Those pages could be framed by any site (clickjacking) and sent no `Referrer-Policy`.

**Decision.** (A) A response whose `Content-Type` is `text/html`, parameters stripped and compared without case, gets `Content-Security-Policy: frame-ancestors 'none'` and `Referrer-Policy: strict-origin-when-cross-origin` by default. The test is the response's own media type, so a JSON API is unchanged and the earlier reasoning still holds for it. `X-Frame-Options` is not sent: `frame-ancestors` supersedes it in every current browser. (B) `frameAncestors: [origins]` names exact origins or `"self"`; a wildcard is refused, as in `cors`, and an entry that is not an exact `http(s)://host[:port]` origin is `bynk.http.security_invalid_field`. (C) `referrerPolicy` is one of the standard values written in camel case. (D) `csp: "…"` is opt-in and sent verbatim; if it names no `frame-ancestors` directive, the `frameAncestors` value (or `'none'`) is appended, so the framing default cannot be lost by declaring a policy. Bynk does not parse or validate the rest. A literal with a CR or LF is refused, as is an empty one. Generating a policy from the page (nonces, hashes) is left to the typed-HTML track. (E) `nosniff: false` does not turn these off: each field is independent. Opening framing takes `frameAncestors: ["*"]`, which is allowed only alone and beside an explicit `csp`, so it is never the result of an accident; dropping the referrer policy takes naming a different one.

The values are resolved at compile time and carried as two string fields of the per-service policy literal, `htmlCsp` and `htmlReferrerPolicy`, so the runtime stamp is a media-type test and two `set` calls, overwriting a header set at the edge as the existing security headers do. Every service gets them, whether or not it declares `security { }`.

**Consequences.** A page that was meant to be embedded stops rendering in its iframe until `frameAncestors` names the embedder; the changelog and upgrading page say so. Hover on a `security` field names its header and default, the service hover summarises the new fields, and completion offers the fields and, after `referrerPolicy:`, its values. The hint wording is unchanged for other fields.
