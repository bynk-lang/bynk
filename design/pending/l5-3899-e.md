## ADR: foreign-queue-senders
title: A queue consumer that names only Foreign actors admits signed messages, verified in its entry with the message id claimed once
summary: A `from queue` handler whose `by` names only `Foreign` actors verifies each message in its generated `queue()` entry before decoding it, under the secret of the actor named by the envelope's `from` (and the previous key during a rotation), claims the message id in the Worker's Idempotency database, and acknowledges and reports anything it refuses

**Context.** Part of #3899 (Decisions C, F, G and H). The signed-message format and the admission step existed as a library; nothing used them, and the checker refused every `Foreign` actor on a queue consumer. A `Foreign` producer signs for itself, so enforcing it needs no Bynk producer signing and no deploy edge key.

**Decision.** (C) `Foreign` actors are admissible on queue consumers when the `by` names only `Foreign` actors. A `Foreign` actor beside `Producer`, an unsigned actor or a `Producer` refinement stays refused (`bynk.actor.queue_actor_not_enforced`), because an unsigned message carries nothing to tell it from the signed ones. (F) The generated entry calls the admission step before decoding; a refusal is acknowledged and reported as a fault (`__bynkQueueRefused`), never retried or dead-lettered. A secret missing or empty in the Worker's `env` yields no key for that sender, so it is refused. (G) The id is claimed in the Worker's implicit `D1_IDEMPOTENCY` database, which the compiler now declares for a signed consumer; a Worker without the binding fails the message loudly rather than admitting it unchecked. A dead-letter consumer also verifies under each source queue that dead-letters into it. (H) `<SECRET>_PREVIOUS`, when set, is tried after the current key. `bynk deploy` mints and sets a queue sender's secret as it does a foreign caller's, and its hand-off says what the value is for. A `system` case sends as a foreign producer with `by`, and the harness gives a message the id of its content, so sending the same message twice replays it.

**Consequences.** `by Producer` consumers are byte-for-byte unchanged. A refinement of `Producer`, and Bynk producers signing, follow with the deploy edge keys. The `<SECRET>_PREVIOUS` name is a convention of the runtime, documented with the format.
