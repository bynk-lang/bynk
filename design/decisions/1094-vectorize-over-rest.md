# 1094 — Vectorize's six operations run over REST, typed, and a refused metadata-index create is settled by the listing wait

- **Status:** Accepted (v0.818)

**Context.** Back-half paydown 1D.4c (#4056) moves Vectorize, the last kind with several account operations, from wrangler to Cloudflare's REST API, under ADR "Account resources need API credentials". Under wrangler, three stdout parsers read the JSON `wrangler vectorize … --json` printed, which wrangler does not document field by field. A metadata index that already existed was recognised by the words "metadata index already exists". #4056's Decision G asked for that case to become a code. The API reference (https://developers.cloudflare.com/api/resources/vectorize/) documents the shapes: an index's `config` holds `dimensions` and `metric` (`cosine`, `euclidean` or `dot-product`), and a metadata-index listing is `{ "metadataIndexes": [{ "propertyName", "indexType" }] }`. It documents no error code for a metadata index that already exists, no paging for the index listing, and no answer for a missing index.

**Decision.**

- **Six typed methods (Decision C).** `vectorize(op) -> String` becomes `vectorize_names`, `vectorize_config` (an `IndexConfig`), `vectorize_create`, `vectorize_metadata_indexes` (`property:type`), `vectorize_create_metadata_index` and `vectorize_delete`. Each runs a request built in `cloudflare/rest/vectorize.rs` and is read by its decoder there. `parse_index_config`, `parse_index_names` and `parse_metadata_indexes` are deleted, along with the six Vectorize `OpKind` variants and wrangler's metadata-index text match. An index name that could not be one is refused before it reaches a request path. With no paging documented, the index listing is read while pages are full, at most 100 pages, and stops at a page that brings no new name.
- **A refused metadata-index create is settled by the listing (as 1D.4b settles R2 and D1 by reading the account).** A create that Cloudflare refuses (`CloudflareError::is_refusal`) may have found a metadata index that is already there, and Cloudflare's asynchronous builds make that the expected case between the listing and the create. Since no code says so, the refusal is not an error at the create. The listing wait that already follows every new metadata index decides it. An index that is listed with the declared property and type is what was wanted. One listed under the same property with another type fails the deploy at once, without waiting for the timeout: Cloudflare cannot retype a metadata index, so the failure names both types and the manual delete that clears it. One that is never listed fails the deploy at the timeout, and that failure now quotes what Cloudflare refused. A denied token, a server error or a transport failure still fails the create at once.
- **Credentials on every deploy (Decision E).** Every deploy of a declared index checks it against the account, adopted or not, so a project with a `Vectorize` needs both variables on every deploy. A `--prune` of an orphan the project made needs them too. The pre-flight now covers KV, R2, D1 and Vectorize, in that order. The permission hint for a denied Vectorize call (#3495) now reads the typed error (`is_denied`) instead of the text `code: 10000`.
- **Unchanged.** The metadata-index wait keeps its pacing (3 seconds, doubling to 15, giving up at 300). Drift detection, adoption and the "never recreate" rule are unchanged. Hyperdrive, the other kind in 1D.1c's group, was already on REST; its 1D.3c error handling (`status() == 404`) needs nothing more.

**Consequences.** A Vectorize project's deploys need both variables, as a linked kind's already do. A metadata-index create Cloudflare refuses outright (a property name it will not take, or the account's limit on metadata indexes reached) now fails at the wait's timeout, 300 s on, not at once; the failure quotes the refusal. That is the cost of not reading a code the reference does not document. The deploy reads the shapes the API reference documents instead of undocumented wrangler output. `wrangler_resource_ops` falls from 9 to 3: only queues remain, for 1D.4d.
