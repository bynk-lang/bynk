# 0842 — bynk dev runs containers under Docker, and without it starts them off so a call faults naming Docker

- **Status:** Accepted (v0.603)

**Context.** A container runs under Docker on the developer's machine, started by `wrangler dev` when the Worker first asks, so there is no remote call and the cost acknowledgement of the remote-only kinds does not apply. Wrangler has `enable_containers` (default true) and, at 4.136.0, `--enable-containers=false`. The proposal left open whether the flag applies under the `durable_object` policy. It does: `wrangler dev --enable-containers=false` starts a container Worker with no Docker, and the Durable Object's `ctx.container` is then absent (observed on workerd, wrangler 4.136.0 and the current 4.x, with an `image` entry; without the flag it stopped asking for a Cloudflare API token, to fetch the registry image). `--remote` support for containers is not documented.

**Decision.** H: `bynk dev` reads each served Worker's `bynk-containers.json`. It refuses `--remote` for a Worker with a container, and refuses a wrangler below `WRANGLER_CONTAINERS_MIN` for one (the general floor is unchanged). It then looks for Docker once (`docker info`): when it runs, a note says the first start builds each image, which can take minutes, and that Wrangler decides when a changed Dockerfile is built again; when it does not (missing, or no daemon), it warns once, naming the containers, and starts the affected Workers with `--enable-containers=false` and `--var BYNK_CONTAINERS_UNAVAILABLE:docker`. The generated class, seeing the variable, answers with a `bynk-container-fault` response instead of starting anything, which `WorkersContainer` throws: a call faults with a message that names the container, Docker and the way out, as an unavailable platform does, not as a `ContainerError` value a handler could answer. No `[dev]` key is added and no cost warning is printed, because nothing is remote. The real-container smoke (`BYNK_REQUIRE_DOCKER`) is a platform contract test beside the language tiers; the containers-off smoke runs without Docker.

**Consequences.** Experimental, like the kind. A stand-in binding was not needed, since the flag works. Rebuild-on-change, the first-build time and the real-container smoke have not been run: Docker was not available here, so the smoke skips (and fails under `BYNK_REQUIRE_DOCKER`). The `bynk test` double and `--against` are unchanged.
