# 1031 — AnalyticsSql.query takes literal SQL and names its dataset by an Analytics instance

- **Status:** Accepted (v0.768)

**Context.** `D1`, `Postgres` and `MySql` refuse SQL that is not a string literal or a `String` constant, so request data can never reach the text. `AnalyticsSql.query` took any `String`, and its own example built the query by interpolating `Signups.dataset()`. The SQL API is read-only but spans every Analytics Engine dataset on the account, so a value that reaches the text can read another dataset or drop the time bound the reference asks every query to carry. The only reason the exception existed was naming the per-environment dataset.

**Decision.** (A) The SQL is a literal, a `"""` block or a bare reference to a `String` constant bound to one, as for `D1`; anything else is `bynk.types.sql_not_literal`, whose note names the replacement. (B) `query(dataset, sql, params)` takes the `Analytics` instance first, and a `{dataset}` in the SQL, any number of times or none, is replaced with that instance's table for the environment the Worker runs in. The substitution is done in the binding, from `await Signups.dataset()`, so the SQL the call site holds stays the literal the checker saw, and a test that observes the call sees `{dataset}` and the dataset name apart. (C) The instance must be in `given`, as any capability use is: an instance that is declared but not listed is `bynk.given.undeclared_capability`. The first argument is checked as the instance itself, written as its bare name, and nothing else is accepted there (a `String` is `bynk.types.argument_mismatch`), because the table name is written into the SQL and so must come from a capability, never from a value; the declared parameter is a `String` only because a capability is not a type. (D) A query built at run time is now an error, so the change is breaking for such programs, and the reference and the guide are rewritten.

**Consequences.** Request data reaches an Analytics query only as a parameter. A query over several datasets is a later extension. A literal `{dataset}` in an Analytics SQL string literal would be replaced too; Analytics SQL has no other use for braces, and if one turns up the placeholder will be spelt `{{dataset}}`. `AnalyticsSql` is still experimental, so a program using it has already opted in to the signature changing.
