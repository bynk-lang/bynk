# 1091 — A capability parameter is emitted through the hidden deps, and checked at the declaration and at each call

- **Status:** Accepted (v0.815)

**Context.** #3959, slice 1 of the capability-parameters track (`design/tracks/capability-parameters.md`), which carries out the decisions recorded for D1 (capability parameters and their binding) and D2 (kinds and shared capabilities). The track records emission through `deps` in this slice (§14).

**Decision.** (A) *Syntax.* A `given` entry of a function or handler may be `Name: Kind` (`CapRef` gains an optional bound); a call by name ends its argument list with `given Name = CapRef, …` (`ExprKind::Call` gains its bindings, boxed so an expression stays within its size budget). A method call, a constructor or `Val[T](…)` with bindings is `bynk.given.binding_unknown` at parse time. The tree-sitter grammar gains `capability_parameter`, `capability_bindings` and `capability_binding`, and the formatter keeps bindings after the arguments, on a line of their own when the list wraps. (B) *Selecting a kind.* A commons' braced `consumes` admits a first-party unit's capabilities, which flatten into the commons as a context's do; a project adapter's capability is still `bynk.commons.consumes_not_types`, with a message naming the first-party rule. (C) *Declaration.* A commons free function with `given` is checked after the plain function pass, as a context's `given` functions are: a parameter's scope entry is its bound kind's contract under the parameter's name, recording the kind as its base, and a shared capability is the selected capability itself. The track's codes are raised as §14.1 names them. A bare commons capability that is not selected is `bynk.given.unknown_capability`, worded for a commons. `bynk.given.kind_needs_parameter`'s fix (`given Store: Kv`) is `MaybeIncorrect`, because it invents a name and every caller must then bind it. An adapter's helper that declares `given` is now `bynk.given.fn_unsupported`, since `bynk.given.fn_outside_context` is retired and an adapter's helpers stay pure; a method with a parameter is `bynk.given.parameter_outside_commons`. (D) *Binding.* `require_callee_given` no longer skips a function that came in through `uses`: it checks the call's bindings against the callee's parameters, then applies ADR 0726 B's inclusion rule to the shared capabilities only. A binding's right-hand side must be in the caller's `given` and of exactly the bound's kind (a derived instance's base, the bare flattened kind, or the caller's own parameter's bound); it counts as used. (E) *The fix never chooses (track §11).* `bynk.given.binding_missing` carries one suggestion per capability of the kind in the caller's `given`, `MachineApplicable` only when there is exactly one, so `bynk check --fix` binds a one-candidate call and leaves a two-candidate call alone. While a call leaves a parameter unbound, its candidates are not reported as unused: `bynk.given.unused_capability`'s machine-applicable removal would otherwise take away the instance the binding's fix offers. (F) *Emission.* A function with capability parameters takes ADR 0726's hidden `deps`, each parameter typed by its bound kind's interface (`deps: { Store: bynk_cloudflare.Kv; Logger: bynk.Logger }`); a call to one passes an object built from the caller's `deps`, one entry per callee `given` entry (`{ Store: deps.Sessions, Logger: deps.Logger }`, `this.deps` in a Bynk-bodied provider). A callee with shared capabilities only keeps today's pass-through, and `__exec` stays its own parameter. (G) *The gate.* Every new form is experimental under one built-in `[unstable] allow` entry, `bynk.given.parameters`, in `bynk-std`'s `BUILTIN_EXPERIMENTAL`: a capability in a commons' `consumes`, each parameter and each call's bindings report `bynk.stability.experimental` without it. (H) *A code the track did not name.* §6.1 gives a commons that selects a capability it never uses "the existing unused-import treatment", but no unused-import warning exists, so slice 1 adds the warning `bynk.commons.capability_unused`, raised on a selected capability that no function's `given` in the file names.

**Consequences.** A program that compiled before is unchanged: each form was a parse error or a refusal, and the positive fixtures' emission is byte-identical. `bynk.given.fn_outside_context` is retired with a tombstone. A function with capability parameters named as a value is not yet refused (slice 2's `bynk.given.parameterised_fn_value`), and a commons suite's doubles and suite-local instances are slice 3's.
