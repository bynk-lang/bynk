# 0906 — A JSON body route checks its media type, tolerantly, and @raw takes a list of types

- **Status:** Accepted (v0.654)

**Context.** `@raw`, `@form` and `@multipart` routes answer a synthesised `415` to the wrong `Content-Type`, before the auth seam and the body read. A plain JSON `body` route accepted any, so a browser form post or an upload sent to a JSON route got a confusing `400 MalformedJson`. `@raw` took one media type or `"*/*"`, so a route accepting PNG or JPEG gave up the router's `415` by using `"*/*"`.

**Decision.** (A) A JSON `body` route answers `415` when `Content-Type` is present and is neither `application/json` nor a `+json` type; a missing (or empty) `Content-Type` is accepted; parameters and case are ignored. (B) The check is tolerant, not strict: strict would break every `curl -d '{…}'` without `-H` and buys little, since CSRF defence for cookie-authenticated routes is the `SignedCookie` seam's fetch-metadata and `Origin` check, not the media type. The `curl -d` case sends a form type, so it gets a `415` whose `details` say to send `Content-Type: application/json`. (C) `@raw(contentType: […])` accepts a non-empty list of `type/subtype` literals, each checked as today; `"*/*"` cannot be in a list (`bynk.http.raw_bad_content_type`); a single string keeps working, and the handler reads which type arrived from `headers`. (D) The JSON route's `415` is the same `UnsupportedMediaType` rejection as `@raw`'s, rendered by `on rejected` and seen in a `system` test as `Rejected(UnsupportedMediaType(_))`. A `system` case probes it with its own trailing `RequestHeaders.of(["Content-Type: …"])`, which now overrides the driver's default for JSON and `@raw` routes as it already did for `@form`.

**Consequences.** Clients that label JSON as a form start getting `415`, with a message naming the fix. Lists in `@raw` are literals only (a constant inside a list is not resolved). The wire contract and its hash are unchanged: the new `415` is not added to a JSON route's documented response set, so no service's contract hash moves; OpenAPI lists each `@raw` type.
