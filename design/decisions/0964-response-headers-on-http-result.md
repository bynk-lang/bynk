# 0964 — An HttpResult carries response headers through withHeader and typed helpers for Retry-After, Location and Content-Disposition

- **Status:** Accepted (v0.700)

**Context.** A handler could set a cookie and nothing else: there was no way to add `Retry-After` to a `429`, `Location` to a `201`, `Content-Disposition` to a download, or a custom header such as a request id. The router also writes headers of its own (caching, framing, CORS, authentication challenges), and a handler that could overwrite those could defeat them.

**Decision.** (A) `withHeader(name, value)` appends one header line to any `HttpResult`; repeating a name keeps every value. (B) `retryAfter(delay)`, `at(url)` and `download(filename)` write `Retry-After` (whole seconds, rounded up), `Location` and an RFC 6266 `Content-Disposition` (an ASCII fallback plus an RFC 8187 `filename*`). A helper applies to the variants whose status it belongs to and must be written on the variant itself, after any other header methods, because the router cannot tell at compile time which variant a stored `HttpResult` holds. (C) `withHeader` refuses the headers the router owns: caching, `Content-Type` and `Content-Length`, `Location`, `Set-Cookie`, the `security { }` headers, `Access-Control-*`, `WWW-Authenticate`, `Allow` and the hop-by-hop headers. A literal is judged at compile time (`bynk.http.reserved_response_header`, `bynk.http.invalid_response_header`); a computed name or value is judged when the response is built, and a bad one answers `500`. (D) Headers ride on the result beside `cookies` and are appended after the router's own, so a typed helper may write the header `withHeader` may not. (E) `headers()` reads them in a test as a `Map[String, List[String]]` with lower-case names.

**Consequences.** Every status can now carry its standard header without escaping the type system, and a handler cannot weaken a header the router sets. A helper on a stored result is `bynk.types.method_not_found`, with a note giving the form to write. Hover and signature help name the new methods from the kernel method table and completion offers them after an `HttpResult`; semantic tokens are unchanged.
