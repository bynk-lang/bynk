# 0981 — A type's declared bounds hold at every application, including through a type parameter and an inferred instantiation

- **Status:** Accepted (v0.718)

**Context.** `type Sorted[T: Ord]` promises that every `Sorted` holds orderable items, but the bound was checked only against a type argument written out in source. A bare type parameter as the argument (`Sorted[U]`) was not checked, and neither was an instantiation the compiler infers (`Sorted { items: [true] }`), so a `Sorted[Bool]` could be built, held, stored and encoded. Nothing misbehaved at run time, because every use that depends on the bound is checked at its own call, but the declared bound was a promise the compiler did not keep.

**Decision.** (A) Every application is checked. A type applied to a type parameter, in a signature, a field, an annotation or a constant's type, requires that parameter to carry the type's bounds, and an inferred instantiation (a record or variant literal) is checked against the bounds as a written argument would be. A static's or a generic call's result needs no rule of its own: its signature is checked at declaration, and each call already instantiates its bounded parameters. (B) The same diagnostics and fixes. `missing_{eq,ord,key,codable}_bound` for a parameter and `not_{comparable,orderable,keyable,codable}` for a concrete type, with the machine-applicable fix of the function rules, so `bynk check --fix` migrates a project in one pass, as it did when `Key` landed. (C) A method's receiver parameters already hold the bounds their type declares, so a method repeats none of them; a `where` clause on a method keeps its meaning. (D) The bounds a type needs are declared on it, not inferred from its fields: `type Wrap[U] = { i: Index[U, Int] }` must say `U: Key`, as a type parameter that reaches a `Map` key in a generic type's field already must.

**Consequences.** Existing generic code that applies a bounded type to an unbounded parameter stops compiling, with a machine-applicable fix at each link of the chain. A concrete instantiation that fails a bound is rejected where the bad type is made, not at a later method call. Hover and signature help already show a declared bound, so a parameter shows the bounds it carries once they are added. The generics reference no longer says a type's bound is unchecked through a parameter, and drops the closed codec follow-up.
