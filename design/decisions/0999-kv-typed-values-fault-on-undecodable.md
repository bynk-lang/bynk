# 0999 — Kv.getValue[T] and putValue[T] are typed reads and writes that fault on a stored value that does not decode

- **Status:** Accepted (v0.734)

**Context.** `Kv` reads and writes `String` or `Bytes`, so every structured value is a hand-written `Json.encode` on the way in and a `Json.decode`, with its own error handling, on the way out, at every call site. ADR 0830 anticipates a typed `Kv` read: a first-party operation may return its `Codable` parameter, decoded at the call site, with the failure policy declared per operation.

**Decision.** `Kv.putValue[T: Codable](key, value: T, options: KvPut)` stores the value's encoded JSON text, so `Json.decode` of a `get` result reads it and a value `putValue` wrote reads back through `getValue` exactly. `Kv.getValue[T: Codable](key) -> Effect[Option[T]]` is `None` for a missing key and decodes at the call site. A stored value that does not decode as `T` faults with ADR 0830's message, naming the capability instance, the operation, the type and the path and never the value (`Kv.getValue returned a value that does not decode as Session: at $.created: expected number, got string`); text that is not JSON faults too. No miss-on-undecodable form is added. `putValue` takes `KvPut`, so expiry and metadata work as for `putWith`, and the 25 MiB limit applies to the encoded text. Both operations are experimental, listed as `bynk.cloudflare.Kv.getValue` and `bynk.cloudflare.Kv.putValue` under `[unstable] allow`. The in-memory double stores the encoded text, so a test runs the round trip production does. The shared decode helper reports a fault over an `Option` payload in terms of the value read (`Session` at `$.created`), not its `Option` wrapper (`Option[Session]` at `$.value.created`); the miss warning keeps the wrapper's form.

**Consequences.** Additive: nothing that compiled changes meaning. Changing `T` while values are stored under the old shape faults at the first read of an old value; the guide says to keep the type additive or to version the key prefix, as for stored agent state. The fault wording of other `Option` typed reads that declare the default fault policy changes to the same unwrapped form; none ships today. Hover shows the failure policy and signature help the type argument, both as every typed read does; completion offers the two operations on a `Kv` instance.
