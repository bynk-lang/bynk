# 0947 — A for all draws members of a Matches pattern and real IsoDate dates

- **Status:** Accepted (v0.685)

**Context.** A `String where Matches(…)` could not be generated, so `for all` over a patterned id, slug or code, and over any record holding one, was `bynk.val.needs_pin`, and `@example` served `Val` only (#4121). The compiler already parses every pattern, which is always a literal.

**Decision.** The maintainer accepted the issue's decisions. A: the checker parses the walkable subset of a pattern (`bynk_check::regex_walk`, Unicode mode, with the `(?i)` and `(?s)` flags) into a tree of character classes, sequences, alternations and repeats, which the emitter writes into the generator as JSON and the test runtime walks. The walk aims at a length and builds exactly that many code points, so the shortest member and the members at each repeat's bounds are boundary values; classes draw from printable ASCII first and from astral members where the class allows them. A shrink candidate deletes a code point or replaces one with an earlier character, and is kept only if it is still a member. B: length predicates bound the walk; any other predicate (a second `Matches`, `IsoDate`) filters the draws, and a draw budget of 200 that runs out fails the property naming the combination, as the pin would have. C: a construct the walk cannot honour (a lookaround, a backreference, a word boundary or an anchor inside the pattern, a Unicode property escape, a negated class under `(?i)`) keeps `bynk.val.needs_pin` and the message names it; a `Cron` refinement still pins. D: `IsoDate` draws real dates across 0000 to 9999, mostly the present era, with leap days, month ends and the first and last years as boundaries. E: `Val` is unchanged; `@example` still serves it alone.

**Consequences.** Every drawn value is re-checked against the emitted pattern, and a walk the engine disagrees with fails loudly naming the pattern, so a bug in the subset parser cannot draw a wrong value silently. A negated class or shorthand under `(?i)` is refused rather than folded, because a drawn character could be a case variant of an excluded one. The negative fixtures that pinned a plain `Matches` and an `IsoDate` under `for all` now use a lookahead, and the `IsoDate` one is replaced by the `property_matches` behaviour fixture, because the behaviour they pinned is the one this issue changes.
