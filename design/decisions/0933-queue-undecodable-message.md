# 0933 — A queue message that cannot be decoded is dead-lettered or dropped visibly, never retried

- **Status:** Accepted (v0.675)

**Context.** The generated `queue` entry decoded each body and, on failure, called `msg.retry()`. The same bytes never decode, so the message was redelivered up to `max_retries` times and then deleted, unless a dead-letter queue was set, and the guide claimed a malformed message is retried. Only the entry decodes the body, so the handler cannot decide anything about it.

**Decision.** (A) A decode failure is never retried: no retry changes the bytes. (B) With a dead-letter queue (`delivery { deadLetter }`, #3877), the entry sends `msg.body` unchanged (`contentType: "bytes"` for an `ArrayBuffer` body, else `"json"`) through a `[[queues.producers]]` binding, then acks; if the send fails, or the configured binding is missing from `env`, the message is retried, so nothing is lost while the dead-letter queue is down. The binding is named `__BYNK_DLQ_<QUEUE>` after the consumer's queue (upper case, `-` as `_`), not `__BYNK_DLQ` or one per context: a context may have several consumers with different dead-letter queues, and a Worker group's members share one `wrangler.toml`, so a name per consumer is the one that never means two queues. (C) Without a dead-letter queue, the entry logs, reports a fault through `__bynkReportFault` and acks; every message in the batch already gets an explicit `ack()` or `retry()`, which the platform honours over the rejected `waitUntil`. (D) The log record names the queue, the message type and the decode error's path and kind, never the body (it can hold user data, ADR 0825). (E) At `system`, an address whose body does not decode yields `Undecodable`, read as `expect r is Undecodable`. It is a pattern-only variant of the verdict a test sees: it is not in `QUEUE_VARIANTS`, so a handler cannot build or return it, but a test can receive it, so a `match` of a `QueueResult` must name it or have a wildcard. The double does not model the dead-letter send itself, only the verdict; the send is covered on `workerd`.

**Consequences.** An existing consumer's behaviour on an undecodable body changes: it is acked rather than retried, so the retry budget is not spent and the message is not deleted after it. A consumer with a dead-letter queue gets one more `[[queues.producers]]` table in its `wrangler.toml` and `bynk deploy` qualifies and creates that queue as it already does for the consumer's `dead_letter_queue`. The generated entry grows one helper. Hover, semantic tokens and signature help are unchanged (no new surface); completion offers `Ack`, `Retry` and `Undecodable` after `expect r is` on a queue address. No Cloudflare account was used: the dead-letter path is verified against local workerd (Miniflare), not a deployed queue.
