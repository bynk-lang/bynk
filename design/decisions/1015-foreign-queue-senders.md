# 1015 — A queue consumer that names one Foreign actor admits signed messages, verified in its entry with the message id claimed once

- **Status:** Accepted (v0.747)

**Context.** Part of #3899 (Decisions C, F, G and H). The signed-message format and the admission step existed as a library; nothing used them, and the checker refused every `Foreign` actor on a queue consumer. A `Foreign` producer signs for itself, so enforcing it needs no Bynk producer signing and no deploy edge key.

**Decision.** (C) `Foreign` actors are admissible on queue consumers when the `by` names one `Foreign` actor alone, with no binder. A `Foreign` actor in a sum, with a binder, or beside `Producer` or a `Producer` refinement stays refused (`bynk.actor.queue_actor_not_enforced`): an unsigned message carries nothing to tell it from the signed ones, and no seam binds the resolved actor in a queue handler yet. (F) The generated entry calls the admission step before decoding; a refusal is acknowledged and reported as a fault (`__bynkQueueRefused`), never retried or dead-lettered. A secret missing or empty in the Worker's `env` yields no key for that sender, so it is refused. (G) The id is claimed on a lease in the Worker's implicit `D1_IDEMPOTENCY` database, which the compiler now declares for a signed consumer: the entry keeps it for the replay window once the handler acks, and releases it when the handler asks for a retry or throws or the body does not decode, so a failed message is redelivered rather than lost; a redelivery that arrives while the lease is still held (another delivery is mid-handler, or its instance died or failed to settle) is retried after the lease and never acknowledged as a replay, and a message signed more than the window ago, or too far ahead, is refused as stale. A Worker without the binding fails the message loudly rather than admitting it unchecked. A dead-letter consumer also verifies under each source queue that dead-letters into it, and a new project-wide check (`bynk.queue.dead_letter_signing_mismatch`) requires a signed queue's dead-letter consumer to be signed, in the same context, admitting the source's senders (and the reverse), because a dead letter keeps the signed envelope. A `Foreign` actor with no secret still counts as a signed sender, with an empty secret that refuses every message. (H) `<SECRET>_PREVIOUS`, when set, is tried after the current key. `bynk deploy` mints and sets a queue sender's secret as it does a foreign caller's, and its hand-off says what the value is for. A `system` case sends as a foreign producer with `by`, and the harness gives a message the id of its content, so sending the same message twice replays it.

**Consequences.** `by Producer` consumers are byte-for-byte unchanged. A refinement of `Producer`, and Bynk producers signing, follow with the deploy edge keys. The `<SECRET>_PREVIOUS` name is a convention of the runtime, documented with the format.
