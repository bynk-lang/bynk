# 0914 — A defined, positional order for matching routes, and unreachable routes refused

- **Status:** Accepted (v0.659)

**Context.** The router sorted routes by their number of parameter segments, then alphabetically by method and path, so `/a/:x/c` beat `/a/b/:y` for `/a/b/c` only because `':' < 'b'`. The order was undocumented, a worker group merging several contexts' routes made overlaps likelier, a route could be shadowed completely with only an exact duplicate refused, and `matchPath` dropped empty segments for parameterised routes but literal routes compared the raw path.

**Decision.** (A) Routes of one method and length are compared segment by segment, left to right; at the first difference a literal beats a parameter. The emitted router orders its dispatch blocks by that rule (a topological order over the overlapping pairs, with the previous ordering kept wherever the rule leaves two routes unordered, so non-overlapping routers do not change), and literals are compared after percent-decoding. (B) A route no request can reach is `bynk.http.unreachable_route`: every path it matches is matched first by others, decided by splitting its space of paths at each segment. Parameter names are not part of a route's shape, so `/a/:x` beside `/a/:y` leaves the one spelt later unreachable; an exact duplicate stays `bynk.http.duplicate_route`. It is checked per context and, across worker-group members, over the group's routes. Overlap alone is not an error. (C) Empty segments stay insignificant and the reference says so; every route, literal ones included, now goes through the matcher so `/items/` reaches `GET /items`. A `308` redirect to a canonical form was rejected for now. (D) The order applies across methods only through `405`: the `Allow` set for a path is the union over the routes that match it, static for routes that cover the path and decided at request time (`allowUnion`) for routes that match only some of its requests.

**Consequences.** A service whose overlapping routes relied on the alphabetical tie-break changes behaviour where two routes with equal parameter counts differ first at a literal; the changelog lists the pattern and the new error flags the routes that become unreachable. Every HTTP route's emitted match now calls `__matchPath`, which re-blesses emitted entries. The test driver cannot send a trailing slash or a wrong-method path value, so those are pinned in the runtime's unit tests.
