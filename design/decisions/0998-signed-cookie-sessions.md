# 0998 — Revocable `SignedCookie` sessions are a generated agent the seam checks

- **Status:** Accepted (v0.732)

**Context.** A stateless signed cookie cannot be revoked before it expires: a copy a user already took keeps working, and `expire` only removes it from one browser. Rotating `secret` is the only bulk revocation and it logs out every user. Logging out everywhere and ending sessions after a password change were left to copying `examples/sessions`. The cookie is issued and verified by generated code and the handler never sees it, so revocation needs the seam to check something, and that has to be generated.

**Decision.** A: opt in with `sessions = true`; stateless cookies stay the default because the check costs an agent call per request. B: the compiler generates `<Actor>Sessions`, keyed by the actor's identity, as ordinary Bynk source added to the declaring context before it is parsed (so the checker, the schema lock, the emitter and the deploy migration treat it as any agent); it holds the identity's live sessions as a map from session id to expiry in milliseconds and takes `now` from its caller, so a context needs no `consumes Clock` for it. `issue` adds a session and prunes expired ones; `expire` removes the current one. C: the seam (the single-actor wrapper and the cookie arm of an actor sum) verifies the signature, `kid`, audience and expiry first, then asks the identity's agent whether the cookie's session id is live; a missing id or a dead session is `401`, and a forged cookie never costs an agent call. D: `expire()` is `Effect[Cookie]` with `sessions` and `Cookie` without. E: a `system` suite's `by User("ada")` records its session in the agent as `issue` does. The generated agent's `revokeAll` handler exists from the start so its stored shape never changes; the language surface for it and `by Revoked` follow in the next increment.

**Consequences.** Revocation security notes: a session ended by `expire` is refused from the next request, not the one that ended it; the agent is the single source of truth, so revocation is immediate and consistent; an agent that cannot answer faults the request, which refuses it (fail closed), never admits it. A cookie signed before the option was switched on carries no `sid` and is refused, so enabling `sessions` logs every user out once. Session ids are 16 random bytes from the platform CSPRNG, and the agent stores the id, not the cookie. Parsing a `sessions = true` file parses it twice (the second time with the agent appended), so it bypasses the parse cache's single entry for that file.
