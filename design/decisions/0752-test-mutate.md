# 0752 — `bynk test --mutate` reports the code changes the suites don't catch

- **Status:** Accepted (v0.516)

**Context.** A passing suite shows the code does what the tests ask, not that the tests would fail if it stopped. Authors checked this by editing sources with throwaway scripts, running `bynk test` and restoring the file (#3069). The toolchain already holds what a mutation run needs: spans, an in-memory source overlay, suite selection, and a runner it can drive in process.

**Decision.** `bynk test --mutate` is a flag, not a subcommand, so it reuses `TestArgs` (selection, seed, format). Mutation sites are the operator tokens `<`, `<=`, `>`, `>=`, `==`, `!=`, `&&` and `||` of the lexed non-suite sources, each placed in its declaration by the parser's item spans; a mutant is the file's text with one token replaced, built through the `sources` overlay into a scratch output directory, so the working tree is never written. A mutant that does not parse or check, or whose run fails before any case runs, is `invalid` and unscored. Slice 1 chose the token stream with parser item spans over a full AST walk: every operator site is a token, a walk would have to enumerate every expression position in every declaration kind, and the pipeline rejects an ill-typed mutant either way. The suites run per mutant are those that target the mutated unit or a unit that `uses` it, or that `use` it; a mutant none reaches is `no suite`, not run and not scored (`--mutate-all-suites` runs everything). The unmutated project runs first and must pass; one seed (the user's, else a fixed one) is used throughout. Runs are sequential, with a per-mutant timeout (three times the baseline, at least ten seconds) that counts as killed. The timeout kills the runner's whole process group (a process tree on Windows), since `tsx` and `npx` start `node` as a child; a timed-out run is reported with its own error kind, `timeout`, and is never retried with another runner. Exclusion is `[test.mutate] exclude` in `bynk.toml` (path globs and `unit` or `unit.decl` names), with no new syntax. Surviving mutants do not fail the run; `--mutate-fail-under <percent>` does, and also when nothing was scored. `--format json` is the unmutated run's document plus a `mutation` object. Guard and branch mutants, SQL fragment mutants (their own decision, since the edit is inside a string literal the checker no longer guards), `--changed` and parallel jobs are later slices.

**Consequences.** Mutation testing is available with no language change: no grammar, checker, emitter or runtime change, and no new diagnostic. Each mutant costs a compile, `tsc` and `node` run, so the feature is opt-in and bounded by `--only` and `--max-mutants`. A survivor may be an equivalent mutant, so the default exit code is report-only. The test runner gained a process timeout and its JSON document now goes through the capture used for in-process runs.
