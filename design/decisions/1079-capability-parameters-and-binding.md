# 1079 — A commons function declares capability parameters, and every call binds each one explicitly

- **Status:** Accepted (v0.809.1)

**Context.** #3959, settled in the capability-parameters track (`design/tracks/capability-parameters.md`, D1). ADR 0726 let a context's free functions declare `given` and deferred capability parameters on commons functions. A commons is shared by contexts that hold different capabilities, and most Cloudflare kinds (`D1`, `R2`, `Queue`, `Service`, …) are used only through derived instances, which only a context declares (ADR 0469 D4). So a commons function has no name for the instance it needs, and libraries take function values instead. The hazard the design must contain is binding the wrong instance: reading through `PriceCache` where `Sessions` was meant is well-typed, so the compiler cannot catch it.

**Decision.** (A) A commons free function, including one in a test-only commons (ADR 0974), may declare a **capability parameter** in its `given` clause, `given Store: Kv`: a capitalised name and an instantiable kind the commons selects (the companion ADR on kinds and shared capabilities, D2). In the body the name is called as a capability is (`Store.get(key)`) and lambdas close over it (ADR 0033). The ADR 0726 A refusals still apply: a free function returning `Effect[T]`, never a method and never `Events`. A parameter is refused (`bynk.given.parameter_name_conflict`) if it shadows any capability or kind visible in the commons, a type parameter of the function, or another parameter; it is never a value, and `let s = Store` gets the error a capability used as a value gets, with a note naming it a parameter. The form is commons-only: on a context function, a method, a handler, a provider or a suite helper it is `bynk.given.parameter_outside_commons`. (B) **Binding is written inside the call's argument list, after the ordinary arguments, introduced by `given`**: `cached[Session](id, load, given Store = Sessions)`, `warmUp(given Store = Sessions)`. The argument list is `"(" ( args | (args ",")? "given" binding ("," binding)* )? ")"` with `binding = Name "=" CapRef` and no trailing comma, so it works unchanged in an effect-let, `do`, `par`, a lambda, a method chain and a nested argument. The trailing clause `f(x) given S = A` is rejected, because it has no closing token; putting bindings in the type-argument brackets is rejected, because type arguments are usually inferred and the brackets omitted, while bindings never are, so every call would need brackets for a reason unrelated to types. (C) **Every call binds every capability parameter of the callee explicitly, exactly once, to a capability the caller holds, and the compiler never infers or defaults a binding, even when only one candidate exists.** What the caller holds is its own `given`; a suite case has no `given` of its own, so what a case holds follows ADR 0977 B: in a context's suite, its target's capabilities, and in a commons suite, the double of every kind its commons selects and every suite-local instance the suite declares (the companion ADR, D2 (C) and (D)). An unbound parameter is `bynk.given.binding_missing`. Its fix offers one action per candidate and is machine-applicable only when exactly one exists: tooling writes the binding into the source only when the choice is unique, and with two or more `bynk fix` never chooses between instances, so every binding is still written at the call where review sees it; a name the callee does not declare, or a binding on a callee with no parameters, is `bynk.given.binding_unknown`; a repeated name is `bynk.given.binding_duplicate`; binding a shared capability is `bynk.given.binding_shared`; a right-hand side of another kind is `bynk.given.binding_kind_mismatch`; and one the caller does not hold is the existing `bynk.given.missing_for_call`. The right-hand side counts as used in the caller. One instance may bind two parameters; the aliasing is visible at the call. (D) The inclusion rule of ADR 0726 B is extended, not reshaped: it is checked at each call, a commons body can bind only to its own parameters (it sees no instance), and so it holds along every chain and through recursion. (E) Emission reuses ADR 0726's hidden `deps` parameter, typed by parameter and shared names; a call to a function with parameters builds the callee's `deps` from the caller's (`{ Store: deps.Sessions, Logger: deps.Logger }`, from `this.deps` in a Bynk-bodied provider), and `__exec` stays its own parameter. No runtime or Worker-binding change. (F) `bynk.given.fn_outside_context` loses its last trigger and moves to the retired codes. (G) Every new form (the parameter, the in-argument binding, a capability in a commons' `consumes`, and a commons suite's suite-local instance) is experimental and needs `[unstable] allow` until promoted.

**Consequences.** Additive: each new form is a parse error or an existing refusal today, so no program that compiles changes meaning, and retiring a code does not change one that compiles. Explicit binding is more to write than inference; that is the decided trade, since a library is called far less often than it is read in review, and the instance written at the call is the mitigation for the integrity hazard. Hover and the architecture model attribute a call through a parameter to the instance bound. A function with capability parameters cannot be named as a value (`bynk.given.parameterised_fn_value`); a lambda that binds takes its place. `stub` and `expect … called` name capabilities, never parameters. Recorded in the slices that ship them: forwarding (slice 2) and tests (slice 3).
