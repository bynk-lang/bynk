# 1013 — A deploy plan flags what a named environment shares with `default`

- **Status:** Accepted (v0.746)

**Context.** A non-default environment can silently share production's resources: a staging `Service @worker("legacy-billing")` calls production's billing Worker, because under `--env` a foreign Worker's name is used as declared, and an `Email @to` or `@allowedRecipients` alert from staging reaches production's people. With `env(…)` constants an environment can override these, but nothing said when one had not (#3943).

**Decision.** A. When deploying a named environment, the plan lists every `env(…)` constant that resolves from `[vars]` or its default rather than the environment's own `[env.<name>.vars]`, and every `Service @worker` (to a Worker outside the build; a Service to the build's own Worker is a project edge, named apart per environment) and `Email @to` or `@allowedRecipients` whose resolved value equals `default`'s, whether written as a literal or as a constant. The comparison builds `default` in memory beside the environment and matches bindings by context and name. B. Advisory, never blocking: each is a `shared with default: NAME → value` line after the plan and a `shared_with_default` entry in `--format json` (present only when there is any), because sharing a read-only partner Worker can be deliberate. `--strict-environments` turns the lines into a refusal, for CI that requires isolation. C. Setting the variable under `[env.<name>.vars]`, even to the same value as `default`'s, records the sharing as deliberate and the line goes; a binding is matched to that setting by its value, since the binding model holds only the resolved text.

**Consequences.** A project that shares on purpose and sets the variable explicitly sees no noise, and one that has not decided sees what a staging deploy is about to touch before anything is pushed. When `default` cannot be built (a required variable it does not set), the binding comparison is skipped and the constants' lines still print. A binding whose value merely coincides with a differently named explicit setting is treated as deliberate; that errs towards silence, never towards a false refusal. The JSON plan gains one optional key; existing consumers are unaffected.
