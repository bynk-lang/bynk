# 0931 — Plain-type generators draw across a realistic domain, with the boundaries that break code

- **Status:** Accepted (v0.673)

**Context.** `Decimal`, `Instant`, `Duration` and `Bytes` drew one fixed value, `Int` drew -1000..1000, `String` 0 to 8 lowercase letters and `Float` finite values in [-1000, 1000] with no boundaries, so a property over them was weaker than it looked (#4199).

**Decision.** The maintainer accepted: each plain type draws across its realistic domain with common boundaries; a refinement narrows the draw; shrinking still reaches small values; existing seeds finding different counterexamples is acceptable before 1.0. `Int` draws mostly small magnitudes up to about 2³¹ and leads with `0`, `±1` and the safe-integer limits as boundaries (a random draw stays below 2³¹ so a handler that sums a few generated amounts does not overflow by construction). `String` draws up to 64 characters from letters, digits, whitespace, punctuation, accented, CJK and astral characters and shrinks by code point. `Decimal` draws any sign, scale 0 to 8 and coefficients up to ±10¹⁸, through magnitude tiers (up to 10¹², then 10¹⁸). `Duration` and `Instant` draw whole milliseconds through tiers of a day, a month, a present-day epoch and a JavaScript `Date`'s whole reach, and shrink through the integer shrinker so every candidate stays whole. `Bytes` draws 0 to 64 octets. `Float` draws finite values only: ordinary values, `0`, `-0` and magnitudes from about `1e-300` to `1e300`. `NaN` and `±Infinity` are never drawn, because the wire codecs and `==` semantics for a non-finite `Float` are not settled; this can be revisited once they are.

**Consequences.** A seed recorded from an earlier version reproduces a different failure, or none. A property that adds or multiplies two generated `Int`s can lose precision at a safe-integer boundary (property bodies use plain `number` arithmetic, so `n + 2 - 2 == n` fails at `2⁵³ − 1` by rounding, with no fault), which is a finding about the claim.
