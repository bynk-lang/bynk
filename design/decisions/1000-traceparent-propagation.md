# 1000 — A request's trace crosses contexts as a W3C traceparent, and an event envelope carries its id

- **Status:** Accepted (v0.735)

**Context.** One request that crosses contexts leaves a log line in each Worker it touches, and nothing says they belong together. #3895 (decisions A to E) adds a trace id every one of those lines can carry. This is its first half: the propagation core, with no entry point starting a trace yet and no log line attaching one, so a deployed project behaves as before.

**Decision.** (A) The trace is one W3C trace id, 32 lowercase hex digits, not all zero. It crosses a context boundary as a `traceparent` header, `00-<trace id>-<span id>-01`: a fresh span id on every hop, and the flags always `01`, because Bynk never decides sampling. (B) A trace is started by an entry point; that is the second half. (C) A callee reads a `traceparent` only from a request that has proved its caller, which is a signed Bynk call, a signed event delivery or a signed foreign caller, and the runtime records it only after the signature has held. A `traceparent` on a request that is not verified, including every public HTTP request, is never read. The header is not part of the signing input: it is observability metadata, a missing or malformed one is ignored and never refuses a call, and the wire version stays 1, so it is an additive optional header. (D) An event carries its trace id in `EventEnvelope.trace: Option[String] = None`, an additive defaulted field, set when the emission happens inside a trace and absent from the wire outside one; the fan-out Durable Object delivers outside the emitting request, so the delivery's header is built from the envelope's `trace` and not from the request scope. A queue message carries no trace. (E) The request scope is `AsyncLocalStorage`, found through `process.getBuiltinModule("node:async_hooks")` as the dev tracer finds it. A Worker without it has no scope, so nothing is carried and nothing fails: every read of the scope answers "no trace". This half adds no compatibility flag, because nothing sets the scope yet; the second half adds `nodejs_als` beside the existing default, or relies on `nodejs_compat` where a project already sets it.

**Consequences.** `EventEnvelope` has a fifth field. An envelope built by hand, in a test or by a publisher built before this, has `trace: None`, because the field is defaulted and the receiving codec treats an absent, `null` or malformed id as `None`. The runtime gains a `traceparent` module, which the cross-context wire client includes, so a foreign caller built from it sends the header from inside a trace as a Bynk caller does. It is not the dev-only `x-bynk-trace-*` tracer (ADR 0640), which has its own headers and scope and is left as it is.
