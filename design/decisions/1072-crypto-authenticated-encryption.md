# 1072 — bynk.crypto seals with AES-256-GCM, owns the nonce and the format, and fails one way

- **Status:** Accepted (v0.804)

**Context.** `bynk.crypto` had digests, MACs and signatures and no encryption, though encrypting personal data before it reaches agent state, `D1`, `KV` or `R2` is one of the commonest reasons to reach for crypto. The route left was an adapter, where the usual mistakes are easy: a reused or caller-chosen nonce, a dropped tag, a ciphertext not bound to where it belongs.

**Decision.** (A) `seal(key, plaintext, scope)` is AES-256-GCM and draws a fresh random 96-bit nonce on every call; no operation takes a nonce. (B) `scope`, GCM's associated data, is a required argument so a ciphertext is bound to something (the record id, the field name); an empty `Bytes` is allowed but must be written. The parameter is `scope` because `context` is a reserved word. (C) The output is `version (1 byte) ‖ nonce (12) ‖ ciphertext ‖ tag (16)`, version `1`, so a later algorithm can be added and every stored value still opens; `open` refuses an unknown version. (D) `open` returns `Err(OpenFailed)` for a wrong key, a wrong scope, a changed byte, a truncated value or an unknown version alike, revealing nothing more; `CryptoError` gains the variant, and it is already extensible, so a `match` needs a wildcard. A platform without Web Crypto is not an `OpenFailed`: it fails loudly, as every other operation does. (E) `importCipherKey(key: Bytes)` takes exactly 32 bytes (`InvalidKey` otherwise) and returns an opaque, non-extractable `CipherKey`, refused where `SigningKey` is (`bynk.types.key_at_boundary`); `importCipherKeyFromSecret` takes the base64 a `Secret` holds, as `importSigningKeyFromSecret` does. (F) A random 96-bit nonce is safe for about 2^32 messages under one key; the docs say so and recommend rotating keys, with `deriveKey` for a key per purpose.

**Consequences.** All additions, so no existing program changes. The provider's constructor takes an optional nonce source, used only so a test can pin the format against NIST's GCM known answer; the compiled program constructs it with none. Key management stays the author's: the docs pair `seal` with `Secrets` storage and rotation.
