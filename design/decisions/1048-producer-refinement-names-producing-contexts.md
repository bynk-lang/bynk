# 1048 — A Producer refinement may admit only contexts that declare a Queue for the queue

- **Status:** Accepted (v0.786)

**Context.** #4441, found while shipping #3899 3c-2b (#4435): a queue consumer admits Bynk contexts through a `Producer` refinement (`actor FromOrders = Producer where IsContext(shop.orders)`), and each admitted context signs under its edge key. Nothing checked at compile time that a named context produces to the queue, so a refinement could name a context that never sends, or one that stands in for the context that does, and the intended producer's messages would be refused only at run time. The compiler sees every context and every `Queue` instance, so the whole-program checks (`phase_caller_admission`, `phase_queue_producers`) are where such a rule belongs.

**Decision.** (A) The check is an error, `bynk.queue.producer_never_sends`, not a warning: a name that cannot produce is a promise the build can never keep, the same standing as `bynk.actor.caller_not_admitted` for a call, and an error is what a misspelt-but-valid context name needs to be caught before deploy. It has an explain entry with a compiled bad/good pair and three negative fixtures. (B) A context is a producer of a queue when it declares a `Queue @name("<queue>")` instance of it. That is the binding the issue names, and it is what signs a send (`signed_consumer_of` finds the edge from the same instances), so the rule asks for exactly what the signing needs. A send call is not required: a context may declare the instance and send through a helper in another unit, and the instance is the compile-time fact. (C) The error is written at the name inside `IsContext(…)` that is admitted but does not produce, so each dead name is one error at the place to change it. A name that is no context of the project stays `bynk.actor.unknown_context` and is skipped here, so a misspelling is reported once, under the code that suggests the nearest context. A name under `!` is not admitted by the predicate, so it is not asked to produce. A refinement with no such name that still admits no producing context (for example `IsContext(a) && IsContext(b)` where no one produces, or an unproductive `!` form) is reported once, at the predicate. (D) A dead-letter queue's consumer is checked against the producers of the queues that dead-letter into it, transitively and once each: a dead letter keeps the signed envelope its source received (`bynk.queue.dead_letter_signing_mismatch`), so those are the contexts whose signature it must admit, and the dead-letter queue itself has no `Queue` instance of its own. (E) Not checked: a `Foreign` actor names no context, so it is out of scope, and a queue consumed by a Worker outside the project has no `Producer` refinement here to check.

**Consequences.** `3899_bynk_producer` and the other #3899 fixtures compile as before. `3899_queue_sum_producers` named `shop.fulfil` and `shop.audit` in its refinement but neither declared the `Queue`, which is the dead configuration this rule refuses; the two contexts now declare `Queue @name("orders")`, so the fixture still compiles and its `system` cases run unchanged. A project that named a non-producing context now fails to build until the name or the `Queue` is fixed, which is the point; the run-time refusal it replaces was silent. Because the check is on the declared instance rather than the send, a context that declares a `Queue` for the queue and never sends passes: that is the remaining dead-configuration case, left to a lint if wanted.
