# 1007 — CORS exposes headers, and origins accept constants

- **Status:** Accepted (v0.741)

**Context.** A browser script reading a cross-origin response sees only the CORS-safelisted headers, so it could not read `WWW-Authenticate` (#3914), `Retry-After` or `Location` (#3915), or a header an author adds with `withHeader`. `origins` had to be string literals, so a staging front end on another origin needed a source edit and the same list repeated across services could drift.

**Decision.** [DECISION A] `cors { expose: [names] }`: every response to an allowed origin carries `Access-Control-Expose-Headers` listing `WWW-Authenticate`, `Retry-After`, `Location` and `ETag` plus the author's names (a name already in the set is not repeated, compared without case). Names are RFC 9110 tokens. `["*"]` stands alone, and with `credentials: true` is refused (`bynk.http.cors_wildcard_expose_credentials`), as a browser reads `*` on a credentialed response as a header literally named `*`; an invalid name or `*` beside others is `bynk.http.cors_invalid_field`. This replaces the `401`-only append of `WWW-Authenticate` from #3914. [DECISION B] An `origins` entry may name a `String` constant and the whole list a `List[String]` constant, resolved by ADR 0826's rule (declared exactly that type, bound to a literal or to another such constant, in the unit or a commons it `uses`), once, ahead of the checks, so the wildcard and credentials rules and the emitter read literal text. A name that does not resolve is `bynk.http.cors_invalid_origins`. [DECISION C, superseded] The issue body's `[deploy.cors."<context>.<service>"]` table is not built: the issue's own comment moves per-environment origins to #3941's `const X: List[String] = env(NAME, default)`, with `[env.<name>.vars]` in `bynk.toml` replacing the list for an environment. The environment-specific list is therefore an ordinary constant by the time `origins` is read, and the deploy plan is unchanged. [DECISION D] The generated client and OpenAPI are unaffected: CORS is browser policy, not part of the contract.

**Consequences.** A cross-origin script can read a challenge, a retry delay, a redirect target and an entity tag with no author action, and any header the author sets. The set sent is a fixed list of names, with no secret in it, and only to origins the service already trusts. Every program that compiled still does; its CORS responses gain one header.
