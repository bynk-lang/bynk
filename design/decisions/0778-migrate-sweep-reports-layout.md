# 0778 — The sweep wake reports each instance's storage layout, and the sweep says how far the layout upgrade has got

- **Status:** Accepted (v0.529)

**Context.** The per-entry storage track (retired; see [`design/archive/retired-tracks.md`](../archive/retired-tracks.md), #3195, proposal #3189) adds a stored-layout marker, `__layout`, with a lazy upgrade in `loadState`. `bynk migrate sweep` already wakes every stored instance through `/_bynk/migrate`, which calls `loadState` and `commitState`, so it is the eager path for the upgrade and needs no new mechanism. What it lacks is a way to say how far the upgrade has got, and an operator wants that before relying on the new layout.

**Decision.** The Worker's wake answer for one instance gains `layoutBefore` (the layout its record was in: 1 when `__layout` is absent, the number when it is a positive integer, null otherwise) and, when the wake succeeds, `layoutAfter` (the layout this build writes). The sweep's answer gains `layout`, the layout this build writes. `wakeForMigration` and `sweepAgentInstances` take it as an optional last argument that defaults to 1, so a build whose emitted code does not pass one reports layout 1 and the sweep line is unchanged. The driver reads `layout` and each instance's `layoutBefore` as optional, so a Worker built before this increment still sweeps; per-instance `layoutAfter` is reported for other readers and is not parsed, because a woken instance is in the Worker's own layout. Once a Worker reports a layout above 1, the sweep line gains `layout N: X moved up, Y already there`: instances whose record was in an older layout, and instances already in the Worker's layout or a later one. An instance with no stored record, or whose marker is not a layout, is in neither count and is reported separately (`Z with no readable layout`), so the line never reads as more done than it is. A record in a layout the build does not know faults `NewerLayout`, which the existing per-instance fault report already names. **The layout is informational only:** it does not enter the rule for when a class's floor may rise, which stays a question about schema versions. `bynk migrate status` is not changed here: it reads the lock, not stored records, so it has no layout to show until a build records one.

**Consequences.** Reporting `layoutAfter` as the layout the build writes, and skipping the commit when the schema version is current, are correct only if the slice that changes the layout makes `loadState` persist the upgraded layout itself; that slice must do so, or the sweep would report a layout that was never written. No behaviour changes today: no build writes a layout above 1, so no sweep line changes and nothing else reads the new fields. The emitter starts passing the layout it writes when the layout change itself lands. Hover, completion, semantic tokens and signature help are unchanged, because no syntax, name or signature changes.
