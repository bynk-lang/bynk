# 0971 — Instant and Duration get real string forms and interpolate

- **Status:** Accepted (v0.706)

**Context.** Interpolation refused `Instant` and `Duration` (ADR 0075, enforced by #2799) because their string form was "a choice, not a default". Their `toString()` methods had already made a choice, and a bad one: an `Instant` gave its epoch milliseconds and a `Duration` lowered to `String(d)`, so `5.minutes.toString()` was `"300000"` with no unit. An author refused at `"\(t)"` reached for `toString()`, the usual fix, and got "expires at 1767225600000".

**Decision.** `Instant.toString()` is RFC 3339 in UTC, the same text as `toIso()`, with expanded years outside 0000 to 9999. `Duration.toString()` is units, largest first: `d`, `h`, `m`, `s`, `ms`, each part an integer, zero parts left out, `0s` for zero, a leading `-` for a negative span, and a day a 24-hour span as `1.day` is. Fractional seconds (`1.5s`) were rejected, because an integer part per unit is unambiguous and matches the literal units. A new `Duration.toIso()` gives ISO 8601 with days as the largest unit, since months and years are not fixed spans, and the seconds carrying the millisecond fraction without trailing zeros (`PT1H30M`, `P1DT2H`, `PT0.25S`, `-PT5S`, `PT0S`); the leading `-` is an extension that is widely accepted. Both types, and refinements of them, interpolate as their `toString()` does. `Bytes` stays refused, because hex or base64 is a real choice. Two runtime helpers, `__bynkDurationToString` and `__bynkDurationToIso`, work on whole milliseconds with integer arithmetic only, so a large span is exact. There is no migration diagnostic: the change is to text only and the new text names its units, so nothing can silently mistake it for the old number.

**Consequences.** Breaking for code that parsed the old `toString()` text. The repository was searched: the only dependent was the default rendering of a `Moment` argument in `bynk.locale`, which now calls `toEpochMillis().toString()` and so keeps its text. The negative fixtures that pinned the refusal of an `Instant` and a `Duration` hole (`2800_interpolate_duration`, `2801_interpolate_instant`) are replaced by a run-tested positive fixture; `2799_interpolate_bytes` still pins the `Bytes` refusal. An `Instant` beyond ±8.64e15 ms faults in an interpolation hole exactly as `toIso()` does. Hover on an interpolation hole does not yet say which form it renders; the type's own hover already names the type.
