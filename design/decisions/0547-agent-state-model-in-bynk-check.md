# 0547 — The agent state model lives in `bynk-check`, shared by the state view and the checker, with its commit condition pinned to the emitter's by test

- **Status:** Accepted (v0.375.3)

**Context.** [ADR 0535](0535-agent-state-model-data-source.md) put the agent state model in `bynk-ide` as a pure function of an `AgentDecl` and the type table, shaped so it could move below `bynk-ide` later. Slice 1 of the transition-diagnostics track (#2215, proposal #2220, track §3.1) needs it there now: the checker warning of slice 2 (#2221) cannot call into `bynk-ide`, which depends on `bynk-check`. Separately, [ADR 0539](0539-transition-overlay-is-a-view-annotation.md) recorded that the model's commit condition only mirrors the emitter's `bynk_lower::body_writes_state`, with nothing to keep the two together.

**Decision.** `agent_state` moves to `bynk_check::agent_state`, with the store-write recogniser (`bynk_check::store_write`) and the three AST text helpers it shares with the sequence diagram (`bynk_check::ast_text`: `branch_outcome`, `pattern_summary`, `peel_paren`). `bynk-check` gains a `bynk-fmt` dependency for the guard labels, which are part of the model because guards merge by their text. `bynk-ide` re-exports the module as `bynk_ide::agent_state`; `agent_effects` stays in `bynk-ide`. The recogniser stays syntactic, since the state view runs on a re-parse with no resolved callees. The commit condition becomes public as `handler_commits`, and a test in `bynk-lower` (which depends on `bynk-check`, so it reaches both) compares it with `body_writes_state` on every handler of a fixture built to probe where they could differ. That test found one: a `let`, match-arm or lambda binding named like a store field made the syntactic test report a commit the emitter never makes. The commit test now scopes those bindings, as the model's walker already did. A second test, in `bynkc` beside the fixtures, pins the overlay's findings across `examples/` and the positive fixtures.

**Consequences.** The state view and a checker diagnostic read one model. A change to either commit predicate that makes them disagree fails `bynk-lower`'s test. The overlay no longer flags an unchanged path in a handler whose only "write" is through a shadowing local. The pinned corpus test makes any change in what the overlay finds visible in review. The agreement test covers a targeted fixture rather than every fixture handler: `body_writes_state` needs a fully checked program, which only a single-unit fixture can build inside `bynk-lower`'s tests.
